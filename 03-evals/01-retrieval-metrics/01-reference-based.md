# 정답 기반 검색 지표 (Reference-based)

정답 문서 목록(qrels)이 있을 때 쓰는 지표를 정리한다. 검색기가 정답을 얼마나 많이, 얼마나 위쪽에 가져오는지를 측정한다.

- 폴더 요약과 메인 지표는 [README](./README.md) 참고
- 골든셋을 만드는 방법은 [03-golden-set](../03-golden-set/README.md) 참고
- 정답 없이 쓰는 지표는 [02-reference-free](./02-reference-free.md) 참고

## 1. 지표 정의

기호
- `k`: 평가에 사용하는 상위 결과 개수
- `R`: 질의의 정답 문서 집합 (`|R|`: 정답 개수)
- `rel(i)`: i번째 결과의 관련도 등급 (0 = 무관, 1 = 부분 관련, 2 = 관련)

| 지표 | 정의 | 범위 | RAG에서의 의미 |
| --- | --- | --- | --- |
| Recall@k | top-k 안의 정답 수 / `\|R\|` | 0~1 | **LLM에 넘기는 k개 안에 근거가 들어왔는가** |
| Hit Rate@k | top-k에 정답이 하나라도 있으면 1, 없으면 0 | 0/1 | 정답이 1개인 질의에서는 Recall@k와 같다 |
| Precision@k | top-k 안의 정답 수 / k | 0~1 | 컨텍스트에 섞이는 잡음의 양 |
| MRR | 1 / (첫 정답의 순위). 정답이 없으면 0 | 0~1 | 정답이 얼마나 위쪽에 오는가 |
| nDCG@k | DCG@k / IDCG@k | 0~1 | 등급과 순위를 함께 반영 |
| MAP | 정답이 나온 위치마다 Precision을 구해 평균 (`\|R\|`로 나눔) | 0~1 | 정답이 여러 개일 때 전체 순위 품질 |

nDCG 계산

```text
DCG@k  = Σ_{i=1..k} gain(rel(i)) / log2(i + 1)
IDCG@k = 정답을 등급 내림차순으로 이상적으로 배치했을 때의 DCG@k
nDCG@k = DCG@k / IDCG@k
```

- gain은 `rel(i)` 그대로 쓰는 선형 방식(trec_eval 기본)과 `2^rel(i) - 1`을 쓰는 지수 방식이 있다. 지수 방식은 높은 등급을 더 크게 반영한다.
- 어떤 방식을 쓰는지 결과와 함께 기록한다. 방식이 다르면 수치를 비교할 수 없다.

## 2. 손계산 예시

질의 q1의 정답과 검색 결과

```text
정답(qrels): d2 = 2, d5 = 1, d9 = 1   (|R| = 3)
검색 결과 top-5: d3, d2, d7, d5, d1
                  ✗   ✓(2) ✗  ✓(1) ✗
```

| 지표 | 계산 | 값 |
| --- | --- | --- |
| Hit Rate@5 | 정답 있음 | 1 |
| Recall@5 | 2 / 3 | 0.667 |
| Precision@5 | 2 / 5 | 0.400 |
| MRR | 첫 정답 d2가 2위 → 1 / 2 | 0.500 |
| AP@5 | (1/2 + 2/4) / 3. 찾지 못한 d9는 0으로 계산 | 0.333 |
| nDCG@5 (선형 gain) | DCG = 2/log2(3) + 1/log2(5) = 1.262 + 0.431 = 1.693<br>IDCG = 2/log2(2) + 1/log2(3) + 1/log2(4) = 2 + 0.631 + 0.5 = 3.131 | 0.541 |
| nDCG@5 (지수 gain) | DCG = 3/log2(3) + 1/log2(5) = 1.893 + 0.431 = 2.323<br>IDCG = 3 + 0.631 + 0.5 = 4.131 | 0.562 |

읽는 법
- Recall@5 = 0.667: 근거 3개 중 하나(d9)는 LLM에 전달되지 않는다.
- MRR = 0.5: 첫 결과(d3)는 잡음이다. 리랭커로 개선할 여지가 있다.

## 3. 설계 판단

### 3.1 k 값과 기준 지표

k와 기준 지표는 **검색 결과를 누가 읽는가**에 따라 달라진다.

| | RAG (LLM이 읽음) | 검색 화면 (사람이 읽음) |
| --- | --- | --- |
| 결과 소비 | LLM이 top-k를 **전부** 읽음 | 사람은 **위쪽 몇 개만** 봄 |
| 중요한 것 | 근거가 k개 안에 들어왔나 | 정답이 **맨 위에** 있나 |
| k | LLM에 넣는 청크 수 (예: 5) | 첫 화면에 보이는 결과 수 (예: 3~5) |
| 기준 지표 | **Recall@k** | **nDCG@k, MRR**, Precision@k |
| 순위의 중요도 | 낮음 (k 안에만 있으면 됨) | 높음 (2위와 8위는 체감이 다름) |
| 함께 볼 것 | 생성 지표 ([03-evals/02-generation-metrics](../02-generation-metrics/README.md)) | 클릭률, 첫 클릭 순위, 이탈률, 재검색률 |

RAG일 때
- **핵심 k는 실제로 LLM에 넣는 청크 수와 맞춘다.** 컨텍스트에 5개를 넣으면 Recall@5가 기준이다.
- 리랭커를 쓰면 1차 검색 후보 수를 따로 본다 (예: Recall@50). 1차 검색에서 놓친 정답은 리랭커가 살릴 수 없다.
- 단, k가 골든셋 Pooling 깊이보다 크면 미판정 문서가 많아 Recall이 낮게 나온다. 이때는 참고용으로 보고 Judged@k를 함께 기록한다([02-pooling](../03-golden-set/02-pooling.md) 4장).

검색 화면일 때
- 중간에 LLM(쿼리 재작성, 필터 추출, 리랭킹)을 써도 최종 결과물이 문서 목록이면 이 지표들로 평가한다. 생성 지표는 쓰지 않는다.
- 단, LLM이 쓴 요약이나 답변이 화면에 보이면 그 부분은 생성 지표(Faithfulness)로 따로 평가한다.

공통
- 여러 k를 함께 기록한다: @1, @5, @10, @50
- [README](./README.md)의 메인 지표(Recall@5 기준)는 RAG를 전제로 정한 것이다. 검색 화면용 시스템이면 메인 지표를 nDCG@k, MRR 기준으로 바꾼다.

### 3.2 판정 단위: 문서 vs 청크

골든셋은 보통 문서(조문) 단위로 정답을 잡고, 검색은 청크 단위로 한다. 두 단위를 맞추는 규칙이 필요하다.

| 방식 | 내용 | 장점 | 단점 |
| --- | --- | --- | --- |
| A. 청크 → 문서 매핑 | 청크의 원문서가 정답이면 정답. 같은 문서의 청크가 여러 개 나오면 첫 순위만 남긴다 | 골든셋 그대로 사용, 청킹을 바꿔도 비교 가능 | 정답 문서의 엉뚱한 부분을 가져와도 정답 처리 |
| B. 청크 단위 정답 | 정답 청크를 직접 판정 | 가장 정확 | 청킹을 바꿀 때마다 다시 판정해야 함 |
| C. 근거 구간 포함 | 정답 근거 문장(span)이 청크에 포함되면 정답 | 청킹이 바뀌어도 자동 판정 | 골든셋에 근거 구간이 있어야 함 |

- 기준선은 **A 방식**으로 시작한다. 중복 제거를 하지 않으면 같은 문서가 top-k를 차지해 Precision이 부풀려진다.
- 골든셋에 근거 구간이 있으면 C 방식을 함께 기록한다. [04-advanced-rag/04-chunking](../../04-advanced-rag/04-chunking/README.md) 비교에서는 C 방식이 더 정확하다.

### 3.3 이진 판정 vs 등급 판정

- 골든셋이 0/1 이진이면 Recall@k, MRR이면 충분하다.
- 0/1/2 등급이면 nDCG@k를 추가한다. 등급 기준은 골든셋 판정 기준과 같아야 한다.
- 등급 골든셋으로 이진 지표(Recall, Precision, MRR)를 계산할 때는 몇 등급부터 정답으로 볼지 정해야 한다. 이 프로젝트는 1 이상을 정답으로 본다([03-golden-set](../03-golden-set/README.md) 사양).

### 3.4 판정 안 된 문서

- 골든셋에 없는 문서는 기본적으로 오답(0)으로 처리한다.
- 새 검색기(예: dense)가 기존 pool에 없던 문서를 많이 가져오면 점수가 실제보다 낮게 나온다.
- 비교할 때 **Judged@k**(top-k 중 판정된 문서 비율)를 함께 기록한다. 이 값이 크게 떨어지면 해당 결과를 추가 판정한다. 자세한 내용은 [02-pooling](../03-golden-set/02-pooling.md) 참고

### 3.5 평균과 분포

- 질의별 점수를 구한 뒤 단순 평균(macro)을 낸다.
- 평균만 보지 않는다. 함께 기록할 것:
  - Recall@k = 0인 질의 수 (완전 실패)
  - 질의 유형별 평균 (단답형, 다중 근거, 상황 시나리오 등)
- 두 검색기를 비교할 때는 같은 질의 집합에서 질의별 차이를 본다. 평균 차이가 작으면 유의성 검정(paired t-test, bootstrap)으로 확인한다.

## 4. 확인할 점

- 직접 구현한 지표는 라이브러리 결과와 같은지 한 번 검증한다. 손계산 예시(2장)를 테스트 케이스로 쓸 수 있다.
- Recall@k의 분모는 `|R|`이다. k가 `|R|`보다 작으면 Recall@k는 1이 될 수 없다. 정답이 많은 질의에서 Recall@1이 낮게 나오는 것은 정상이다.
- 같은 문서의 청크 중복 제거를 했는지 결과마다 명시한다.
