# Pooling 방식 — 검색 평가 데이터(Golden Set) 생성

- 이 프로젝트의 Pooling 설정(깊이, 참여 검색기, 판정 방식)은 [README](./README.md) 사양 참고
- 다른 생성 방법과의 비교는 [00-generation-methods](./00-generation-methods.md) 참고

## 1. Pooling이란?

**Pooling(풀링)**은 여러 검색 시스템이 반환한 상위 검색 결과를 하나로 합치고, 중복을 제거한 뒤 관련성을 판정하여 **평가용 정답 데이터(Golden Set, Qrels)**를 생성하는 방법이다.

주로 정보검색(IR), RAG, 벡터 검색, 하이브리드 검색 시스템의 성능 평가에 활용된다.

### Pooling이 필요한 이유

전체 문서가 100만 개라면 평가 질문마다 모든 문서를 확인하여 정답을 찾는 것은 현실적으로 어렵다.

또한 하나의 검색 방식만 사용하여 정답 데이터를 생성하면 특정 검색 모델에 유리한 평가 데이터가 만들어질 수 있다.

예를 들어:

- Dense 검색은 의미적으로 유사한 문서를 잘 찾는다.
- BM25 검색은 정확한 키워드가 포함된 문서를 잘 찾는다.
- Hybrid 검색은 두 검색 방식의 장점을 결합한다.

따라서 여러 검색 방식의 결과를 통합하면 **정답 문서 누락과 특정 검색 방식에 대한 편향을 줄일 수 있다.**

## 2. Pooling 처리 과정

```text
            평가 질문(Q1)
                 │
       ┌─────────┼─────────┐
       ▼         ▼         ▼
     Dense      BM25     Hybrid
     Top K      Top K     Top K
       │         │         │
       └─────────┼─────────┘
                 ▼
          검색 결과 통합
                 │
                 ▼
          중복 문서 제거
                 │
                 ▼
          Pool 후보 생성
                 │
                 ▼
       관련성 판정 (사람/LLM)
                 │
                 ▼
        Golden Set (Qrels)
                 │
                 ▼
          검색 성능 평가
      Recall / nDCG / MRR
```

### 단계별 설명

1. **평가 질문 준비**: 검색 성능을 평가할 질문 목록 생성
2. **검색 실행**: Dense, BM25, Hybrid 등 여러 검색 방식으로 Top K 검색
3. **결과 통합**: 각 검색 방식에서 반환된 문서를 하나로 합침
4. **중복 제거**: 동일한 문서 ID를 기준으로 중복 제거
5. **관련성 판정**: 각 문서가 질문에 얼마나 관련 있는지 평가
6. **Golden Set 생성**: 질문별 정답 문서와 관련성 점수 저장
7. **검색 성능 평가**: 생성한 Golden Set을 기준으로 검색 모델 비교

## 3. Pooling 예시

### 3.1 검색 결과 수집

**평가 질문**

> Q1. 연차휴가 신청 절차는 어떻게 되나요?

각 검색 방식에서 Top 5 문서를 가져온다고 가정한다.

| 검색 방식 | 검색 결과 |
|---|---|
| Dense | A, B, C, D, E |
| BM25 | B, F, G, H, I |
| Hybrid | A, B, F, J, K |

검색 결과는 총 15개지만 중복 제거 후에는 11개의 문서가 남는다.

```text
Pooling 결과

A, B, C, D, E, F, G, H, I, J, K

총 11개 문서
```

### 3.2 관련성 판정

각 문서의 관련성을 0 / 1 / 2 등급으로 판정한다(2 관련, 1 부분 관련, 0 무관). 등급 정의는 [README](./README.md)의 판정 기준을 그대로 쓴다.

예시:

| 문서 ID | 관련성 점수 |
|---|---:|
| A | 2 |
| B | 2 |
| C | 0 |
| D | 1 |
| E | 0 |
| F | 2 |
| G | 0 |
| H | 0 |
| I | 1 |
| J | 0 |
| K | 2 |

### 3.3 Golden Set 생성

관련성 판정 결과를 Qrels 형식으로 저장한다.

**qrels.csv**

```csv
query_id,doc_id,relevance
Q1,A,2
Q1,B,2
Q1,C,0
Q1,D,1
Q1,E,0
Q1,F,2
Q1,G,0
Q1,H,0
Q1,I,1
Q1,J,0
Q1,K,2
```

이후 해당 데이터를 기준으로 각 검색 시스템의 성능을 평가한다.

## 4. Pooling 깊이(Top K)

Pooling 깊이는 각 검색 시스템에서 수집할 상위 문서 개수를 의미한다.

| Pooling 깊이 | 특징 |
|---|---|
| Top 5 | 빠르지만 정답 문서 누락 가능성이 큼 |
| Top 10 | 초기 평가에 활용 가능 |
| Top 20~30 | 비교적 폭넓은 후보 수집 |
| Top 50~100 | 정밀 평가에 활용 가능하나 판정 비용 증가 |

Top K의 크기는 정해진 표준이 없으며, 데이터 규모와 평가 목적에 따라 결정한다.

### Pooling 후보 수 계산

예를 들어 다음과 같이 설정한다고 가정한다.

- 평가 질문: 100개
- 검색 방식: Dense, BM25, Hybrid (3개)
- 검색 결과: 각 Top 20

중복 제거 전 최대 후보 수:

```text
100 × 3 × 20 = 6,000
```

실제 후보 수는 검색 결과 간 중복이 존재하므로 6,000개 이하가 된다.

### Pooling 깊이와 평가 k의 관계

Pooling 깊이는 **믿을 수 있는 평가 k의 상한**이다.

```text
Pool 깊이 20  →  각 검색기의 1~20위는 판정됨, 21위 아래는 대부분 미판정
Recall@10, nDCG@10  →  판정된 범위 안이므로 그대로 믿을 수 있음
Recall@50           →  21~50위의 정답이 미판정(0 처리)이라 낮게 나옴
```

- 평가에 쓰는 가장 큰 k보다 Pooling 깊이가 같거나 커야 한다.
- 깊이보다 큰 k를 쓸 때는 참고용으로만 보고 Judged@k를 함께 기록한다([01-reference-based](../01-retrieval-metrics/01-reference-based.md) 3.4).

## 5. Pooling의 장점과 한계

### 장점

- 전체 문서를 검사하지 않고 평가 데이터를 생성할 수 있다.
- 다양한 검색 방식이 찾은 정답 후보를 확보할 수 있다.
- 특정 검색 모델에 대한 편향을 줄일 수 있다.
- 동일한 Golden Set으로 여러 검색 모델을 비교할 수 있다.
- 사람 또는 LLM을 활용한 관련성 판정 자동화가 가능하다.

### 한계

**1. 정답 문서 누락 가능성**

모든 검색 시스템이 찾지 못한 정답 문서는 Pool에 포함되지 않는다.

**2. 검색 모델 편향**

Pooling에 참여한 검색 모델과 유사한 검색 방식이 평가에서 유리할 수 있다. 새 검색 방식을 비교할 때는 그 결과도 추가 판정한다([04-update-loop](./04-update-loop.md)).

**3. 관련성 판정 비용**

Pooling 크기가 커질수록 사람 또는 LLM의 문서 판정 비용이 증가한다.

**4. 미판정 문서 문제**

Pooling에 포함되지 않은 문서는 관련성이 확인되지 않은 상태이다.

따라서 **미판정 문서(Unjudged Document)와 관련 없음(0)을 개념적으로 구분**해야 한다.

일부 평가 도구는 미판정 문서를 관련 없는 문서처럼 처리하므로, 평가 시 해당 정책을 확인해야 한다. 이 프로젝트는 미판정을 0으로 처리하고 Judged@k를 함께 기록한다.

미판정 문서를 순위에서 빼고 계산하는 condensed 지표(nDCG′, bpref)를 함께 보면, pool에 없던 문서를 많이 가져오는 새 검색기가 덜 불리하게 평가된다.

## 6. 설정과 주의사항

Pooling 설정(질문 수, 참여 검색기, 깊이, 판정 방식)은 [README](./README.md) 사양에서 관리한다. 처음 시작한다면 질문 50~100건, Dense + BM25 + Hybrid 각 Top 20, 0 / 1 / 2 등급, LLM 판정 + 사람 검수로 시작하고, 정답 누락률과 판정 비용을 보면서 조정한다.

### 참여 검색기 고르기

Pool은 참여 검색기가 찾을 수 있는 정답만 담는다. 참여 검색기가 **서로 다른 이유로** 틀려야 누락이 줄어든다.

| 축 | 예 | 잘 찾는 것 |
| --- | --- | --- |
| 어휘 기반 | BM25 (형태소 분석) | 고유명사, 코드, 정확한 용어 |
| 의미 기반 | 임베딩 모델 A의 dense 검색 | 바꿔 말한 표현 |
| 다른 계열 의미 기반 | 학습 데이터·회사가 다른 임베딩 모델 B | 모델 A가 놓치는 표현 |
| (선택) 질의 변형 | 질문을 LLM으로 3~5가지로 바꿔 쓰고 각각 검색 | 원래 질문 표현에 묶여 놓친 문서 |

- 같은 임베딩 모델에서 나온 dense와 learned sparse, 그 둘을 섞은 hybrid는 세 개처럼 보여도 **사실상 검색기 하나**다. 이 경우 어휘 기반 BM25와 다른 계열 임베딩을 반드시 추가한다.
- hybrid처럼 비교 대상인 검색기는 다양성과 별개로 참여시킨다. 참여하지 않은 검색기는 평가에서 불리하기 때문이다.

### Pool 편향 점검

| 점검 | 방법 | 나쁜 신호 |
| --- | --- | --- |
| 유일 기여 | 검색기마다 그 검색기만 찾은 정답 수를 센다 | 한 검색기에 몰려 있음 → 비슷한 검색기가 하나 더 빠지면 그만큼 누락 |
| leave-one-out | 검색기 S만 찾은 정답을 qrels에서 빼고 S를 다시 채점한다 | 점수가 크게 떨어짐(예: Recall@10 0.05 이상) → pool에 참여하지 않은 새 검색기는 그만큼 과소평가됨 |
| 사람 직접 검색 | 질문 일부(예: 10건)를 사람이 자유롭게 검색해 pool 밖 정답을 찾는다 | pool 밖 정답 비율이 높음 → 검색기 추가 또는 깊이 확대 |

- 세 점검은 골든셋 버전을 올릴 때마다 다시 한다. 결과는 [04-update-loop](./04-update-loop.md) 8장 회차별 요약에 함께 남긴다.

### 더 나은 방법 (선택)

- **적응형 pooling:** 모든 검색기를 같은 깊이로 자르지 않고, 관련 문서가 많이 나오는 검색기와 질문에서 더 깊이 판정한다(move-to-front, bandit 방식). 같은 판정 비용으로 정답을 더 많이 찾는다.
- **질의 변형 pooling:** 위 표의 질의 변형을 모든 소스에 쓴다. 검색기를 늘리기 어려울 때 다양성을 늘리는 가장 싼 방법이다.

### 주의사항

- Pooling과 평가는 서로 다른 과정이다.
- Pooling은 **정답 후보 수집**, 관련성 판정은 **정답 데이터 확정**, 평가지표 계산은 **검색 성능 측정**에 해당한다.
- 동일한 Golden Set을 사용해야 검색 방식별 성능을 공정하게 비교할 수 있다.
- 관련성 점수 1을 정답으로 인정할지 여부는 평가 전에 정의해야 한다. 이 프로젝트는 이진 지표에서 1 이상을 정답으로 본다([README](./README.md) 사양).
- 청크 단위 검색에서는 문서 단위 평가인지 청크 단위 평가인지 명확히 해야 한다([01-reference-based](../01-retrieval-metrics/01-reference-based.md) 3.2).
- 새로운 검색 모델이 기존 Pool에 없는 관련 문서를 찾는다면 추가 판정 또는 Pool 확장을 고려해야 한다([04-update-loop](./04-update-loop.md)).

## 7. 핵심 요약

| 구분 | 설명 |
|---|---|
| Pooling | 여러 검색 시스템의 상위 결과를 통합 |
| Pool | 중복 제거된 평가 후보 문서 집합 |
| Relevance Judgment | 질문과 문서의 관련성 판정 |
| Qrels | 질문별 문서 관련성 점수 데이터 |
| Golden Set | 검색 평가에 사용하는 기준 정답 데이터 |
| Evaluation | Golden Set을 활용한 검색 성능 측정 |

**전체 흐름**

```text
검색 결과 수집 → Pooling → 관련성 판정 → Golden Set → 성능 평가
```

**핵심:** Pooling은 검색 성능을 직접 측정하는 기법이 아니라, 여러 검색 시스템의 결과를 활용하여 평가용 정답 데이터를 효율적으로 구축하기 위한 방법이다.
