# 정답 없는 생성 지표 (Reference-free)

정답 답변 없이, 질문과 검색된 컨텍스트와 생성된 답변만으로 답변 품질을 판정하는 지표를 정리한다. 판정은 LLM judge가 맡는다.

- 폴더 요약과 메인 지표는 [README](./README.md) 참고
- 정답 기반 지표는 [01-reference-based](./01-reference-based.md) 참고
- judge 프롬프트 설계, 사람 판정과의 일치도 검증은 [04-llm-judge](../04-llm-judge/README.md)에서 다룬다

## 1. 개념

```text
정답 기반:  질문 + 답변 + 정답 답변           →  같은 내용인가 (맞았는가)
정답 없음:  질문 + 답변 + 검색된 컨텍스트     →  근거에 충실한가, 질문에 맞는 대답인가
```

- 정답 없는 지표는 **"맞았는가"가 아니라 "앞뒤가 맞는가"**를 본다.
- 검색이 틀린 문서를 가져와도 그 문서에 충실하게 답하면 점수가 높게 나온다. 그래서 검색 지표와 함께 봐야 의미가 있다.

## 2. 지표 정의

| 지표 | 입력 | 정의 | 잡아내는 문제 |
| --- | --- | --- | --- |
| Faithfulness (Groundedness) | 답변 + 컨텍스트 | 답변 주장 중 컨텍스트로 뒷받침되는 비율 | **환각** |
| Answer Relevance | 질문 + 답변 | 답변이 질문에 대한 대답인가 | 동문서답, 불필요하게 긴 답변 |
| Citation Support | 답변 문장 + 인용한 청크 | 인용한 청크가 해당 문장을 실제로 뒷받침하는 비율 | 잘못된 출처 표시 |
| Citation Coverage | 답변 + 인용 | 인용이 필요한 문장 중 인용이 붙은 비율 | 출처 누락 |
| Refusal Appropriateness | 질문 + 컨텍스트 + 답변 | 컨텍스트에 근거가 없을 때 거절했는가, 있을 때 답했는가 | 근거 없는 답변, 과잉 거절 |
| Rubric 점수 | 질문 + 답변 (+ 컨텍스트) | 기준표(완결성, 형식, 어조, 길이 등) 항목별 점수 | 서비스 요구 사항 위반 |
| Pairwise Preference | 질문 + 답변 A, B | 두 답변 중 더 나은 쪽 선택 | 두 시스템 비교 (절대 점수 없이) |

### Faithfulness 계산

```text
1. 답변을 독립된 주장 목록으로 쪼갠다          A = {a1, a2, ...}
2. 주장마다 컨텍스트로 뒷받침되는지 판정한다    지지 / 모순 / 근거 없음
3. Faithfulness = 지지된 주장 수 / |A|
```

- **모순**(컨텍스트와 반대)과 **근거 없음**(컨텍스트에 없음)을 따로 센다. 근거 없음 중에는 상식 수준의 연결 문장도 섞여 있어서 모순보다 가볍게 본다.
- 주장을 쪼개는 단계도 LLM이 하므로, 쪼개는 방식에 따라 분모가 달라진다. 쪼개는 프롬프트도 버전을 기록한다.

### Refusal Appropriateness와 검색 지표

- "컨텍스트에 근거가 있는가"는 검색 지표의 Context Sufficiency와 같은 판정이다. [검색 지표 02-reference-free](../01-retrieval-metrics/02-reference-free.md) 참고
- Sufficiency = 0인데 답했으면 근거 없는 답변, Sufficiency = 1인데 거절했으면 과잉 거절이다.

## 3. 손계산 예시

[01-reference-based](./01-reference-based.md)와 같은 질문

```text
질문:      비밀번호 재설정 링크는 얼마 동안 유효한가?
컨텍스트:  [c1] 재설정 링크는 발송 후 24시간 동안 유효하다. 만료된 링크는 앱에서 다시 요청해야 한다.
답변 C:    링크는 발송 후 24시간 동안 유효하며 [c1], 만료되면 고객센터에 문의해야 합니다 [c1].
```

| 주장 | 판정 |
| --- | --- |
| a1: 링크는 발송 후 24시간 동안 유효하다 | 지지 |
| a2: 만료되면 고객센터에 문의해야 한다 | 모순 (컨텍스트: 앱에서 다시 요청) |

| 지표 | 계산 | 값 |
| --- | --- | --- |
| Faithfulness | 1 / 2 | 0.5 |
| Citation Support | a1의 [c1]은 뒷받침, a2의 [c1]은 뒷받침 안 함 → 1 / 2 | 0.5 |
| Citation Coverage | 두 문장 모두 인용 있음 → 2 / 2 | 1.0 |
| Answer Relevance | 질문(유효 시간)에 답함 | 1 |

같은 질문에서 **검색이 오래된 문서를 가져온** 경우

```text
컨텍스트:  [c2] (2023년 문서) 재설정 링크는 발송 후 12시간 동안 유효하다.
답변 D:    링크는 발송 후 12시간 동안 유효합니다 [c2].
```

| 지표 | 값 |
| --- | --- |
| Faithfulness | **1.0** (컨텍스트에 충실) |
| Answer Relevance | 1 |
| Answer Correctness (정답 기반) | **0** (정답은 24시간) |

읽는 법
- C는 질문에는 맞게 답했지만 컨텍스트에 없는 절차를 지어냈다. Faithfulness가 이런 환각을 잡는다.
- D는 정답 없는 지표가 모두 만점인데 실제로는 틀렸다. **원인은 생성이 아니라 검색이다.** 정답 없는 생성 지표만 보면 이 오류를 놓친다.

## 4. 판정 설계 (요약)

자세한 설계와 검증은 [04-llm-judge](../04-llm-judge/README.md)에서 다루고, 여기서는 지표 계산에 영향을 주는 결정만 적는다.

| 항목 | 선택지 | 기본값 (초안) |
| --- | --- | --- |
| Faithfulness 판정 단위 | 답변 전체 / 문장 / 주장 | 주장 단위 (분해 후 판정) |
| 판정 등급 | 이진 / 지지·모순·근거 없음 | 지지·모순·근거 없음 |
| 점수 방식 | 절대 점수(pointwise) / 두 답변 비교(pairwise) | 기준선은 pointwise, 시스템 비교에는 pairwise 추가 |
| 출력 | 등급만 / 등급 + 근거 한 줄 | 등급 + 근거 한 줄 (오판 분석용) |
| 재현성 | judge 모델, 프롬프트 버전, temperature 고정 | temperature 0, 프롬프트 버전 기록 |

- pairwise에서는 답변 순서를 바꿔 두 번 판정한다. 먼저 나온 답변을 선호하는 위치 편향이 있다.
- 생성 모델과 같은 계열의 judge는 자기 스타일 답변을 선호할 수 있다. 가능하면 다른 계열 모델을 쓰거나 편향을 측정한다.

## 5. 한계

- **맞았는지는 알 수 없다.** 검색이 틀리면 충실한 오답이 만점을 받는다 (3장 답변 D).
- **judge 품질이 곧 지표 품질이다.** 검증하지 않은 judge 점수는 기준선으로 쓰지 않는다.
- **judge 편향**
  - 긴 답변, 형식이 정돈된 답변을 더 좋게 평가한다
  - 컨텍스트에 없는 상식 문장을 "근거 없음"으로 볼지 판정이 흔들린다
  - 도메인 지식이 부족하면 미묘한 모순(조건, 예외 조항)을 놓친다
- **비용**: 주장 분해 1회 + 주장 수만큼 판정. 답변이 길수록 비싸다.
- **모델이 바뀌면 점수가 바뀐다.** judge 모델을 바꾸면 기준선을 다시 잰다.

## 6. 정답 기반 지표와 맞춰 보기

| 확인 | 방법 | 기준 (초안) |
| --- | --- | --- |
| 판정 일치도 | 골든셋 질의에서 Faithfulness 판정을 사람 판정과 비교 | 일치율, Cohen's kappa. 기준은 [04-llm-judge 통과 기준](../04-llm-judge/02-human-agreement.md) 참고 |
| 오답 탐지력 | Answer Correctness = 0인 답변 중 Faithfulness가 낮게 나온 비율 | 낮으면 오답의 원인이 대부분 검색 쪽이라는 뜻 (3장 D 유형) |
| 시스템 순위 일치 | 여러 생성 설정을 두 계열 지표로 각각 순위 매기기 | Kendall's tau. 순위가 뒤집히면 정답 없는 지표로 비교하지 않는다 |

- Faithfulness는 정답 기반 지표를 **대신하지 않는다.** 정답 기반 지표가 못 보는 "환각"을 따로 보는 지표로 쓴다. 그래서 골든셋 평가에서도 함께 기록한다.

## 7. 언제 쓰나

| 상황 | 쓰는가 | 이유 |
| --- | --- | --- |
| 생성 설정 비교 (프롬프트, 모델) | 함께 사용 | 기준은 Answer Correctness, 환각은 Faithfulness로 따로 확인 |
| 배포 전 회귀 테스트 ([05-regression-ci](../05-regression-ci/README.md)) | 사용 | Faithfulness 하락은 정답 기반 점수보다 먼저 드러나는 경우가 많다 |
| 골든셋 밖 질의, 새 도메인 | 사용 | 정답이 없으므로 다른 방법이 없다 |
| 운영 모니터링 ([06-llmops](../../06-llmops/01-tracing/02-tools-and-monitoring.md)) | 사용 | 샘플링한 운영 질의에 Faithfulness, Answer Relevance, Refusal 추적 |
