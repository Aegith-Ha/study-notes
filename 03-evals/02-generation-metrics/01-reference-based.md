# 정답 기반 생성 지표 (Reference-based)

정답 답변(reference answer)이 있을 때 쓰는 지표를 정리한다. 생성된 답변이 정답과 같은 내용을 말하는지 측정한다.

- 폴더 요약, 메인 지표, 결과는 [README](./README.md) 참고
- 골든셋을 만드는 방법은 [03-golden-set](../03-golden-set/README.md) 참고
- 정답 없이 쓰는 지표는 [02-reference-free](./02-reference-free.md) 참고

## 1. 지표 정의

| 지표 | 정의 | 범위 | 잘 맞는 답변 유형 |
| --- | --- | --- | --- |
| Exact Match (EM) | 정규화한 답변과 정답이 완전히 같으면 1 | 0/1 | 단답형 (숫자, 날짜, 이름) |
| Token F1 | 답변과 정답의 겹치는 토큰으로 구한 Precision, Recall의 조화평균 | 0~1 | 짧은 서술형 |
| ROUGE-L | 최장 공통 부분열(LCS) 기반 겹침 | 0~1 | 요약형 |
| BLEU | n-gram 정밀도 기반 겹침 | 0~1 | 번역형 (RAG에는 잘 안 맞음) |
| BERTScore / 임베딩 유사도 | 답변과 정답의 의미 벡터 유사도 | 대략 0~1 | 표현이 다양한 서술형 |
| Answer Correctness (LLM judge) | judge가 정답과 비교해 같은 내용인지 판정 | 0/1 또는 0·1·2 | **모든 유형. RAG 기본 지표** |
| Citation Recall / Precision | 답변이 인용한 문서와 골든셋 근거 문서의 겹침 | 0~1 | 출처를 표시하는 답변 |

### Answer Correctness를 주장(claim) 단위로 계산하기

서술형 답변은 통째로 맞다/틀리다를 판정하기 어렵다. 정답과 답변을 핵심 주장 목록으로 쪼개서 비교하면 두 가지를 따로 볼 수 있다.

```text
정답 주장 R = {r1, r2, ...}     답변 주장 A = {a1, a2, ...}

Claim Recall    = 답변에 들어 있는 정답 주장 수 / |R|      → 완결성: 빠뜨린 내용이 있는가
Claim Precision = 정답과 일치하는 답변 주장 수 / |A|       → 정확성: 틀린 내용을 덧붙였는가
Claim F1        = 두 값의 조화평균
```

- 정답과 **모순되는** 답변 주장은 따로 센다. 정답에 없을 뿐인 주장(추가 설명)과 정답과 반대되는 주장(오답)은 무게가 다르다.

### Citation 지표

골든셋에 근거 문서가 있으면 답변의 인용을 정답처럼 채점할 수 있다.

```text
Citation Recall    = 인용한 근거 문서 ∩ 골든셋 근거 문서 / |골든셋 근거 문서|
Citation Precision = 인용한 근거 문서 ∩ 골든셋 근거 문서 / |인용한 근거 문서|
```

- 인용이 실제로 그 문장을 뒷받침하는지는 정답 없이도 판정할 수 있다. [02-reference-free](./02-reference-free.md)의 Citation Support 참고

## 2. 손계산 예시

```text
질문:   비밀번호 재설정 링크는 얼마 동안 유효한가?
정답:   재설정 링크는 발송 후 24시간 동안 유효하다
답변 A: 링크는 24시간 동안 유효합니다               (맞음)
답변 B: 재설정 링크는 발송 후 12시간 동안 유효하다  (틀림)
```

Token F1 (공백 기준 토큰)

```text
정답 토큰 (7): 재설정, 링크는, 발송, 후, 24시간, 동안, 유효하다
A 토큰 (4):   링크는, 24시간, 동안, 유효합니다         겹침 3: 링크는, 24시간, 동안
B 토큰 (7):   재설정, 링크는, 발송, 후, 12시간, 동안, 유효하다   겹침 6
```

| 지표 | 답변 A (맞음) | 답변 B (틀림) |
| --- | --- | --- |
| EM | 0 | 0 |
| Token F1 | P = 3/4, R = 3/7 → **0.545** | P = 6/7, R = 6/7 → **0.857** |
| Answer Correctness (judge) | **1** | **0** |
| Claim Recall (정답 주장: "24시간 유효", "발송 후 기준") | 1/2 = 0.5 ("발송 후 기준" 누락) | 1/2 = 0.5 ("24시간 유효" 불일치) |
| 정답과 모순되는 주장 수 | 0 | **1** ("12시간") |

읽는 법
- **틀린 B가 Token F1에서 더 높다.** 겹침 기반 지표는 핵심 숫자 하나가 틀려도 거의 감점하지 않는다.
- **맞은 A가 낮다.** 한국어는 어미(`유효하다`/`유효합니다`)와 조사 때문에 같은 뜻이어도 토큰이 달라진다.
- 그래서 RAG의 서술형 답변에는 겹침 기반 지표를 기준 지표로 쓰지 않는다. 단답형에서 정규화 후 EM을 보조로 쓰는 정도로 제한한다.
- **Claim Recall은 둘 다 0.5다.** A는 부가 조건을 빠뜨렸고 B는 핵심 숫자가 틀렸지만 Recall만으로는 구분되지 않는다. 모순 주장 수를 따로 세야 B를 오답으로 걸러낼 수 있다.
- 누락(A)을 얼마나 감점할지, 모순(B)은 바로 0점 처리할지는 등급 기준에서 정한다.

## 3. 설계 판단

### 3.1 답변 유형별 지표 선택

| 답변 유형 | 기준 지표 | 보조 지표 |
| --- | --- | --- |
| 단답형 (숫자, 날짜, 예/아니오) | 정규화 후 EM | Answer Correctness |
| 서술형 | Answer Correctness (claim 단위) | BERTScore |
| 다중 근거 (여러 조문 종합) | Claim Recall | Citation Recall |
| 답 없음 (근거가 문서에 없음) | 거절 정확도 | - |

- 골든셋 질의마다 답변 유형 태그를 달아 두면 유형별로 지표를 나눠 볼 수 있다.

### 3.2 정규화

EM, Token F1을 쓸 때는 비교 전에 정규화한다. 정규화 규칙은 결과와 함께 기록한다.

- 공백, 문장부호, 대소문자 통일
- 숫자 표기 통일 (`24시간` = `하루` = `24 시간`)
- 한국어는 형태소 분석으로 조사와 어미를 떼거나, 토큰 대신 글자 단위 F1을 쓴다

### 3.3 정답이 여러 개일 때

- 같은 질문에 정답 표현이 여러 개면 정답 목록을 두고 **가장 높은 점수(max)**를 쓴다.
- 정답 자체가 여러 항목인 경우(예: 조건 3가지)는 claim 단위로 쪼개 Claim Recall을 쓴다.

### 3.4 답 없음 질의

- 골든셋에 "문서에 근거가 없는 질문"을 일부(예: 10%) 넣고 정답을 `답 없음`으로 둔다.
- 이 질의에서는 거절("문서에서 찾을 수 없습니다")이 정답이다.
- 거절 정확도와 과잉 거절률(답이 있는데 거절한 비율)을 함께 본다. 하나만 보면 무조건 거절하거나 무조건 답하는 모델이 좋아 보인다.

### 3.5 Answer Correctness judge

- 정답을 함께 주므로 정답 없는 judge보다 판정이 안정적이다. 그래도 judge이므로 [04-llm-judge](../04-llm-judge/README.md)의 검증을 거친다.
- 판정 기준(등급별 정의)과 "정답에 없는 추가 내용"을 어떻게 처리할지 미리 정한다. 기본값은 정답과 모순되지 않으면 감점하지 않는다.

## 4. 확인할 점

- 정답 답변의 품질이 지표의 상한이다. 정답이 모호하거나 틀리면 지표도 틀린다. 골든셋 검수 때 정답 답변도 함께 검수한다.
- 정답 답변은 근거 문서에서 확인 가능한 내용만 담는다. 근거에 없는 내용이 정답에 들어 있으면 충실한 답변이 감점된다.
- 겹침 기반 지표(Token F1, ROUGE)를 쓴다면 손계산 예시(2장)처럼 오답이 높게 나오는 사례를 함께 기록해 둔다.
