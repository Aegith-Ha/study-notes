# 트레이싱 도구와 운영 모니터링 (Tools and Monitoring)

트레이스를 수집·조회하는 도구를 비교하고, 트레이스로 만드는 운영 대시보드 지표와 알림 기준을 정리한다.

- 폴더 요약과 메인 결정은 [README](./README.md) 참고
- 트레이스 구조와 필드는 [01-trace-design](./01-trace-design.md) 참고

## 1. 도구

| 도구 | 성격 | 장점 | 확인할 점 |
| --- | --- | --- | --- |
| Langfuse | LLM 앱 트레이싱·평가 플랫폼, 자체 호스팅 가능 | 프롬프트 버전, 데이터셋, 점수 기록을 함께 관리 | 자체 호스팅 시 운영 부담 |
| Phoenix (Arize) | 트레이싱 + 평가, OpenTelemetry 기반 | 로컬에서 바로 띄워 실험 분석하기 쉬움 | 운영 규모 저장소는 별도 검토 |
| OpenTelemetry | 트레이스 표준 형식과 SDK | 도구에 묶이지 않음, 기존 APM과 연결 | LLM 전용 화면은 없음 (위 도구로 조회) |

- 기록 형식을 OpenTelemetry에 맞추면 조회 도구를 바꿔도 앱 코드는 그대로 둔다.
- 사내 데이터가 밖으로 나가면 안 되면 자체 호스팅을 고른다.

## 2. 대시보드 지표

| 분류 | 지표 | 출처 |
| --- | --- | --- |
| 사용량 | 요청 수, 사용자 수, 질문 유형 분포 | trace |
| 지연 | 전체·단계별 p50, p95, 첫 토큰까지 시간 | span 시각 |
| 오류 | 오류율, 도구 오류율, 시간 초과율, 출력 잘림 비율 | span 상태, 종료 이유 |
| 비용 | 질의당 토큰, 질의당 비용, 캐시 읽기 비율 | LLM span |
| 검색 | 결과 0건 비율, top-1 점수 분포 | 검색 span |
| 품질 (샘플) | Context Relevance, Faithfulness, 거절 비율 | 샘플링한 trace에 judge 실행 |
| 피드백 | 👍/👎 비율, 👎 사유 분포 | [04-feedback-loop](../04-feedback-loop/README.md) |

- 품질 지표는 정답이 없는 운영 질의라서 정답 없는 지표만 쓸 수 있다([03-evals](../../03-evals/README.md)의 2×2 표).
- 거절 비율이 갑자기 늘면 검색 고장(인덱스 누락 등)일 가능성이 크다. 품질 지표보다 먼저 움직인다.

## 3. 샘플링

| 대상 | 비율 | 이유 |
| --- | --- | --- |
| 메타데이터 (지연, 토큰, 오류) | 100% | 저렴함, 모든 이상을 잡아야 함 |
| 품질 judge | 일부 (예: 1~5%) | judge 호출 비용 |
| 👎 피드백, 오류, 거절 | 100% judge + 사람 검토 후보 | 문제 사례는 빠짐없이 |

- 무작위 샘플만 보면 드문 질문 유형이 빠진다. 유형별로 나눠 뽑는 것도 함께 쓴다.

## 4. 알림 기준

| 조건 (예) | 의심 원인 |
| --- | --- |
| 오류율 > 평소의 2배 (10분 이상) | 모델 API 장애, 도구 장애 |
| p95 지연 > 기준 | 입력 길이 증가, 재시도 증가 |
| 결과 0건 비율 급증 | 인덱스 누락, 필터 오류 |
| 질의당 토큰 급증 | 프롬프트 변경, 에이전트 반복 |
| 샘플 Faithfulness 하락 (일 단위) | 모델·프롬프트 변경, 새 유형의 질문 |

- 기준값은 배포 전 회귀 테스트 기준([03-evals/05-regression-ci](../../03-evals/05-regression-ci/README.md))과 따로 둔다. 운영은 골든셋 밖 질의라 값의 수준이 다르다.
- 알림이 너무 많으면 무시된다. 처음엔 오류율과 지연만 걸고 늘려 간다.

## 5. 확인할 점

- 샘플 품질 지표는 judge 결과다. judge 버전이 바뀌면 값이 튈 수 있어 judge 버전도 함께 기록한다([03-evals/04-llm-judge](../../03-evals/04-llm-judge/README.md)).
- 대시보드 값이 나빠지면 해당 trace를 열어 보는 것이 다음 단계다. 지표만 보고 원인을 단정하지 않는다.
