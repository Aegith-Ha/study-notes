# 피드백 루프 (Feedback Loop)

운영에서 모은 사용자 피드백과 로그를 분류해 원인을 찾고, 골든셋에 반영하고, 개선 후 회귀 테스트로 확인하는 루프를 정리한다. 이 README에는 기본 선택과 이유를 두고, 수집과 루프 운영은 하위 노트에 둔다.

- 골든셋 갱신 절차는 [03-evals/03-golden-set/04-update-loop](../../03-evals/03-golden-set/04-update-loop.md) 참고
- 피드백과 실행 기록 연결은 [01-tracing](../01-tracing/README.md) 참고

## 하위 노트

- [01-feedback-collection](./01-feedback-collection.md): 명시적 피드백(👍/👎, 사유)과 암묵적 신호(재질문, 복사, 이탈), 신호별 신뢰도, 수집 설계
- [02-loop-operation](./02-loop-operation.md): 분류(triage) → 원인별 조치 → 골든셋 반영 → 회귀 테스트, 손계산 예시, 주기

## 기본 선택과 이유

| 항목 | 결정 | 이유 |
| --- | --- | --- |
| 명시적 피드백 | 👍/👎 + 👎일 때 사유 선택 (틀림, 근거 없음, 못 찾음, 기타) | 원인 분류의 첫 단서 |
| 암묵적 신호 | 같은 세션 재질문, 답변 복사를 보조 신호로 | 명시적 피드백은 적음 |
| 연결 | 피드백마다 trace ID 저장 | 검색 결과·버전까지 바로 확인 |
| 분류 | 4분면(검색 성공/실패 × 답변 맞음/틀림) + 범위 밖, 사용자 오류 | 조치가 원인마다 다름 |
| 골든셋 반영 | 사람이 정답·관련 문서를 확인한 사례만, 마스킹 후 | 골든셋 신뢰도 유지 |
| 주기 | 주 1회 분류, 월 1회 골든셋 버전 갱신 | 골든셋 버전이 너무 자주 바뀌면 비교가 어려움 |
| 효과 확인 | 개선 후 회귀 테스트 + 해당 유형 👎 비율 추이 | 고쳤는지, 다른 것을 깨지 않았는지 |
