# 비용 최적화 (Cost Optimization)

품질을 지키면서 질의당 비용과 지연을 줄이는 방법(프롬프트 캐싱, 시맨틱 캐시, 작은 모델 라우팅, 입력 줄이기)을 정리한다. 이 README에는 메인 결정과 결과를 두고, 방법별 원리와 계산은 하위 노트에 둔다.

- 질의당 비용 공식과 긴 컨텍스트 비교는 [04-advanced-rag/06-long-context-vs-rag/02-cost-latency](../../04-advanced-rag/06-long-context-vs-rag/02-cost-latency.md) 참고
- 비용 측정은 [01-tracing](../01-tracing/README.md)의 LLM span 기록을 쓴다.

## 하위 노트

- [01-caching](./01-caching.md): 프롬프트 캐싱과 시맨틱 캐시의 차이, 캐시가 맞는 조건, 잘못된 캐시 응답 위험, 손계산 예시
- [02-model-routing](./02-model-routing.md): 작은 모델 라우팅, 입력·출력 줄이기, 품질 손실 확인 방법, 손계산 예시

## 메인 결정 (초안)

| 항목 | 결정 | 이유 |
| --- | --- | --- |
| 먼저 할 것 | 프롬프트 캐싱 (고정 앞부분: 시스템 프롬프트, 도구 정의) | 품질 변화 없음, 설정만으로 효과 |
| 프롬프트 순서 | 고정 부분 → 자주 바뀌지 않는 부분 → 검색 결과 → 질문 | 캐시 적중 유지 |
| 시맨틱 캐시 | 보류. 도입하면 높은 유사도 기준 + 문서 버전 포함 키 + 법령 개정 시 무효화 | 비슷하지만 다른 질문에 틀린 답 위험 |
| 라우팅 | 쿼리 변환·분류·judge 샘플 같은 보조 단계부터 작은 모델로 | 답변 품질에 직접 영향이 작음 |
| 입력 줄이기 | top-k와 청크 길이를 결과 기준으로 조정 ([04-advanced-rag](../../04-advanced-rag/README.md)) | 비용 대부분이 입력 토큰 |
| 판단 기준 | 회귀 테스트 통과 + 질의당 비용 감소 | 품질 손실 없는 절감만 채택 |
