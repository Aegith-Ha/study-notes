# 모델 라우팅과 입력 줄이기 (Model Routing)

요청이나 단계에 따라 작은 모델과 큰 모델을 나눠 쓰는 라우팅, 그리고 입력·출력 토큰을 줄이는 방법과 품질 손실을 확인하는 방법을 정리한다.

- 폴더 요약과 기본 선택은 [README](./README.md) 참고
- 캐싱은 [01-caching](./01-caching.md) 참고

## 1. 무엇을 나누나

| 방식 | 예 | 위험 |
| --- | --- | --- |
| 단계별 | 쿼리 변환·분류·요약은 작은 모델, 최종 답변은 큰 모델 | 보조 단계 품질 저하가 검색에 번짐 |
| 질문별 | 쉬운 질문은 작은 모델, 어려운 질문은 큰 모델 | 쉬움/어려움 판정이 틀리면 품질 하락 |
| 단계적 (cascade) | 작은 모델이 먼저 답하고, 확신이 낮거나 검증 실패면 큰 모델로 | 두 번 호출하는 요청은 더 비쌈, 지연 증가 |

- 단계별 라우팅이 가장 안전하다. 각 단계의 품질을 따로 잴 수 있어서다(쿼리 변환은 검색 Recall로, 분류는 정확도로).
- 질문별 라우팅의 판정기는 그 자체가 분류기다. 판정 정확도를 따로 평가한다.

## 2. 손계산 예시: 질문별 라우팅

가정: 작은 모델 비용은 큰 모델의 1/10. 질문 1,000건

```text
전부 큰 모델:     1,000 × 1.0                      = 1,000
60%를 작은 모델:  400 × 1.0 + 600 × 0.1            = 460   → 46%
cascade (작은 모델 먼저, 30%가 큰 모델로 넘어감):
                  1,000 × 0.1 + 300 × 1.0           = 400   → 40%
```

| 설정 | 상대 비용 | Answer Correctness (가정) |
| --- | --- | --- |
| 전부 큰 모델 | 1.00 | 0.82 |
| 60% 작은 모델 | 0.46 | 0.78 |
| cascade | 0.40 | 0.81 |

읽는 법
- 평균 정확도가 0.01~0.04 떨어졌다. 이 차이가 의미 있는지는 같은 문항 대응 비교로 판단한다([03-evals/05-regression-ci](../../03-evals/05-regression-ci/01-gate-design.md)).
- 평균보다 **질문 유형별** 하락을 본다. 다중 근거·답 없음 질문에서만 크게 떨어지면 그 유형을 큰 모델로 보내면 된다.
- cascade의 비용은 넘어가는 비율에 따라 달라진다. 넘어가는 비율이 90%를 넘으면 전부 큰 모델(1.0)보다 비싸진다(0.1 + 0.9 = 1.0).

## 3. 입력·출력 줄이기

| 방법 | 효과 | 확인할 것 |
| --- | --- | --- |
| top-k 줄이기 | 입력 토큰 감소 | Recall@k, Answer Correctness 하락 여부 |
| 리랭커로 후보를 걸러 적게 넣기 | 입력 감소 + 순서 개선 | [04-advanced-rag/02-reranking](../../04-advanced-rag/02-reranking/README.md) |
| 청크 길이 조정 | 입력 감소 | 문맥 잘림 |
| 프롬프트 군더더기 제거 | 고정 입력 감소 | 거절·인용 지시가 빠지지 않았나 |
| 출력 길이 제한 | 출력 토큰 감소 | 답이 잘리지 않나 (종료 이유 확인) |
| 대화 기록 요약 | 다회차 입력 감소 | 앞의 조건을 잊지 않나 |

- 출력 단가는 보통 입력보다 비싸다. 답변이 길면 출력 쪽도 같이 본다.
- 에이전트는 호출 횟수가 비용을 좌우한다. 최대 단계와 토큰 예산을 둔다([05-agents/03-plan-execute-verify](../../05-agents/03-plan-execute-verify/README.md)).

## 4. 품질 손실 확인 순서

1. 골든셋 회귀 테스트로 기준 대비 하락이 허용 폭 안인지 본다.
2. 질문 유형별로 나눠 본다.
3. 배포 후 운영 샘플 지표와 👎 비율을 기준 기간과 비교한다([01-tracing](../01-tracing/02-tools-and-monitoring.md)).

## 5. 확인할 점

- 비용은 실험 날짜의 단가로 기록하고, 상대 비용도 함께 남긴다. 단가가 바뀌면 판단이 뒤집힐 수 있다.
- 작은 모델이 형식을 더 자주 어긴다. 스키마 위반율·파싱 실패율도 함께 본다.
