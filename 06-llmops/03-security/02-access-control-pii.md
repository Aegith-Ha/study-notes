# 문서 권한 제어와 개인정보 (Access Control, PII)

사용자마다 볼 수 있는 문서가 다를 때 RAG에서 권한을 지키는 방법과, 문서·로그 속 개인정보를 탐지하고 마스킹하는 방법을 정리한다.

- 폴더 요약과 메인 결정은 [README](./README.md) 참고
- 인젝션 대응은 [01-prompt-injection](./01-prompt-injection.md) 참고

## 1. 문서 권한: 어디서 거르나

| 위치 | 방식 | 문제 |
| --- | --- | --- |
| 생성 후 | 답변을 만든 뒤 권한 밖 내용을 걸러냄 | 이미 LLM이 읽음, 요약·바꿔 말한 내용은 못 거름 |
| 검색 후 | top-k 결과에서 권한 밖 문서를 뺌 | 결과가 k보다 적어짐, 권한 밖 문서가 상위를 차지하면 빈 결과 |
| **검색 중** | 메타데이터 필터(사용자 그룹, 문서 등급)로 검색 자체를 제한 | 권한 정보를 색인에 함께 넣어야 함 |

- 검색 중 필터가 기본이다. 권한 밖 문서는 LLM 입력에 **들어가지 않아야** 한다.
- 필터 방식은 [04-advanced-rag/03-query-transform/02-metadata-filter](../../04-advanced-rag/03-query-transform/02-metadata-filter.md)와 같은 구조를 쓴다. 다만 권한 필터는 LLM이 만들지 않고 **로그인 정보에서 앱이 넣는다**.

### 권한 정보 관리

| 항목 | 내용 |
| --- | --- |
| 색인 필드 | 문서(청크)마다 접근 그룹, 등급 |
| 동기화 | 원본 시스템 권한이 바뀌면 색인도 갱신. 갱신 지연 시간을 기록 |
| 청크 | 문서 권한을 모든 청크에 복사 (부모-자식 청크 포함) |
| 캐시 | 권한이 다른 사용자에게 캐시된 답을 주지 않음 ([02-cost-optimization](../02-cost-optimization/01-caching.md)) |
| 도구 | 사내 DB 도구는 사용자 권한을 그대로 전달 ([05-agents/02-tool-calling-mcp](../../05-agents/02-tool-calling-mcp/02-mcp.md)) |

### 권한 평가

| 테스트 | 방법 | 기대 |
| --- | --- | --- |
| 검색 누출 | 그룹별 테스트 사용자로 권한 밖 문서를 겨냥한 질문 | 권한 밖 문서 ID가 검색 결과에 0건 |
| 답변 누출 | 같은 질문의 답변에 권한 밖 문서의 고유 문구가 있는지 | 0건 |
| 권한 변경 | 권한 회수 후 같은 질문 | 동기화 시간 안에 차단 |
| 정상 접근 | 권한 안 문서 질문 | 정상 답변 (필터가 과하지 않음) |

- 위반은 비율이 아니라 **건수 0**을 기준으로 본다. 한 건이라도 나오면 배포를 막는다.
- 권한 밖 문서의 고유 문구(테스트용 표식)를 미리 심어 두면 답변 누출을 규칙으로 찾을 수 있다.

## 2. 개인정보 (PII)

### 어디서 나타나나

| 위치 | 예 | 처리 |
| --- | --- | --- |
| 색인할 문서 | 판결문 속 이름, 계약서 속 연락처 | 색인 전 마스킹 또는 권한 제한 |
| 사용자 질문 | 자기 주민번호, 사건 내용 | 로그 저장 전 마스킹 |
| 답변 | 문서에서 옮긴 개인정보 | 출력 검사 |
| 트레이스·평가 데이터 | 위 내용이 그대로 저장 | 마스킹 후 저장, 보관 기간 제한 |

- 골든셋을 운영 로그에서 만들 때도 마스킹을 거친다([03-evals/03-golden-set](../../03-evals/03-golden-set/README.md)의 출처 D).

### 탐지 방법

| 방법 | 잘 잡는 것 | 한계 |
| --- | --- | --- |
| 정규식 | 주민번호, 전화번호, 이메일, 계좌번호 | 형식이 없는 정보 |
| 개체명 인식 (NER) | 사람 이름, 주소 | 한국어 이름 오탐·누락 |
| LLM | 문맥상 개인을 특정할 수 있는 정보 | 비용, 일관성 |

- 정규식을 먼저 적용하고 이름·주소는 NER로 보완한다. 마스킹은 "[이름]", "[전화번호]"처럼 종류를 남겨 문장 뜻이 유지되게 한다.
- 탐지기도 평가한다: 표본 문서에 사람이 표시한 개인정보 대비 탐지 Recall. 놓친 것이 남는 위험이므로 Precision보다 Recall을 먼저 본다.

## 3. 확인할 점

- 권한 필터를 끈 채로 평가 수치를 내면 운영과 결과가 달라진다. 평가 실행에도 테스트 사용자 권한을 적용한다.
- 개인정보 처리 기준(보관 기간, 조회 권한)은 조직 규정을 따른다. 노트에는 기술적 처리만 정리한다.
