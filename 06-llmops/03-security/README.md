# 보안 (Security)

LLM 앱에 생기는 보안 위험 중 프롬프트 인젝션(문서·도구 결과를 통한 간접 인젝션 포함), 문서 권한 제어, 개인정보(PII) 처리를 정리한다. 이 README에는 메인 결정과 결과를 두고, 공격 유형과 대응은 하위 노트에 둔다.

- 도구·MCP 연결의 권한 원칙은 [05-agents/02-tool-calling-mcp/02-mcp](../../05-agents/02-tool-calling-mcp/02-mcp.md) 참고

## 하위 노트

- [01-prompt-injection](./01-prompt-injection.md): 직접·간접 인젝션, 피해 유형, 층별 대응, 공격 평가 세트와 손계산 예시
- [02-access-control-pii](./02-access-control-pii.md): 문서 권한 필터(검색 단계에서 거르기), 권한 평가, 개인정보 탐지·마스킹, 로그 보관

## 메인 결정 (초안)

| 항목 | 결정 | 이유 |
| --- | --- | --- |
| 기본 원칙 | LLM은 속을 수 있다고 가정하고, 피해 범위를 권한으로 제한 | 프롬프트만으로는 인젝션을 완전히 막을 수 없음 |
| 검색 문서·도구 결과 | 데이터로 표시해 넣고, 그 안의 지시는 따르지 않도록 지시 | 간접 인젝션 감소 |
| 도구 권한 | 읽기 전용 우선, 쓰기는 사람 확인 후 | 속아도 피해 제한 |
| 출력 | 링크·이미지 외부 URL 차단 또는 허용 목록 | 데이터 유출 경로 차단 |
| 문서 권한 | 검색 단계에서 사용자 권한으로 필터 (생성 후 거르지 않음) | 권한 밖 문서가 LLM에 들어가지 않게 |
| 개인정보 | 색인 전·로그 저장 전 탐지와 마스킹 | 검색 결과와 로그로 새는 것 방지 |
| 평가 | 공격 평가 세트(공격 성공률) + 정상 질문 오거절률 + 권한 위반 테스트 | 막는 것과 정상 동작을 함께 |
