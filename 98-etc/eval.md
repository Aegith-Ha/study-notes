# RAG 평가 데이터(Golden Set) 생성 방법

## 1. 개요

RAG(Retrieval-Augmented Generation) 시스템의 성능을 평가하려면 질문과 정답 문서, 정답 답변 등으로 구성된 **평가 데이터(Golden Set)**가 필요하다.

평가 데이터 생성 방법에는 Pooling, Synthetic Data Generation, Human Annotation 등 여러 방식이 있다.

### 평가 데이터 생성과 평가지표의 차이

| 구분 | 설명 | 예시 |
|---|---|---|
| 평가 데이터 생성 | 평가에 사용할 질문과 정답을 구축 | Pooling, Synthetic |
| 평가지표 계산 | 평가 데이터를 기준으로 성능 측정 | Recall@K, nDCG, MRR |
| 평가 결과 분석 | 검색 및 답변 시스템 성능 비교 | Dense vs BM25 vs Hybrid |

**핵심:** Pooling은 평가지표가 아니라 평가용 정답 데이터를 구축하는 방법이다.

---

## 2. RAG 평가 데이터 생성 방법

| 방법 | 핵심 원리 | 특징 |
|---|---|---|
| Pooling | 여러 검색 모델의 결과를 통합하여 정답 후보 수집 | 검색 모델 비교에 적합 |
| Human Annotation | 사람이 질문과 정답 문서를 직접 판정 | 높은 신뢰도, 높은 비용 |
| Synthetic Data Generation | LLM이 문서를 기반으로 질문과 정답 생성 | 대량 자동 생성 가능 |
| LLM-as-a-Judge | LLM이 문서 또는 답변의 관련성을 평가 | 자동 판정에 적합 |
| User Log 기반 | 실제 사용자 질문 및 피드백 활용 | 실서비스 환경 반영 |
| Known-Item | 정답 문서를 먼저 선택하고 질문 생성 | 문서 검색 성공 여부 평가 |
| Weak Supervision | 규칙 및 메타데이터를 기반으로 정답 추정 | 저비용 대량 생성 |
| Active Learning | 판정이 어렵거나 정보 가치가 높은 데이터 우선 검수 | 검수 비용 최적화 |

※ LLM-as-a-Judge와 Active Learning은 독립적인 데이터 생성 방법보다는 다른 방법과 결합하는 **관련성 판정 및 검수 전략**에 가깝다.

---

## 3. 주요 생성 방법 상세

### 3.1 Pooling

여러 검색 시스템의 상위 검색 결과를 통합하여 정답 문서 후보를 생성하는 방법이다.

**처리 과정**

```text
평가 질문
   ↓
Dense / BM25 / Hybrid 검색
   ↓
각 검색 결과 Top K 수집
   ↓
검색 결과 통합
   ↓
중복 문서 제거
   ↓
관련성 판정
   ↓
Golden Set 생성
```

**장점**
- 다양한 검색 방식의 정답 후보 확보
- 특정 검색 모델에 대한 편향 감소
- 검색 모델 간 성능 비교에 적합

**단점**
- 모든 검색 모델이 찾지 못한 정답 문서 누락 가능
- 검색 모델 구성에 따라 Pool 편향 발생 가능
- 관련성 판정 비용 발생

**적합한 목적:** Dense, BM25, Hybrid 등 검색 시스템 성능 비교

---

### 3.2 Synthetic Data Generation (합성 데이터 생성)

LLM이 기존 문서를 분석하여 평가 질문과 정답 데이터를 자동 생성하는 방법이다.

**처리 과정**

```text
기존 문서
   ↓
LLM 문서 분석
   ↓
평가 질문 생성
   ↓
정답 문서 연결
   ↓
정답 답변 생성
   ↓
질문 및 정답 검증
   ↓
Golden Set 생성
```

**예시**

원본 문서:

> 연차휴가는 사내 인사시스템에서 신청하며 부서장의 승인을 받아야 한다.

생성 결과:

| 항목 | 내용 |
|---|---|
| 질문 | 연차휴가는 어디에서 신청하나요? |
| 정답 문서 | DOC_001 |
| 정답 답변 | 사내 인사시스템에서 신청합니다. |

**장점**
- 대규모 평가 질문 자동 생성
- 정답 문서와 질문 연결이 쉬움
- 다양한 질문 유형 생성 가능
- 사람의 작성 비용 감소

**단점**
- 실제 사용자 질문과 분포가 다를 수 있음
- 비현실적이거나 지나치게 단순한 질문 생성 가능
- LLM의 잘못된 질문 또는 정답 생성 가능
- 다른 문서에도 정답이 존재할 수 있음

**적합한 목적:** 평가 질문 대량 생성 및 초기 Golden Set 구축

---

### 3.3 Human Annotation (사람이 직접 판정)

도메인 전문가 또는 담당자가 평가 질문에 관련된 문서를 직접 확인하여 정답 데이터를 생성하는 방법이다.

**처리 과정**

```text
평가 질문
   ↓
담당자 문서 검색
   ↓
관련 문서 검토
   ↓
관련성 점수 부여
   ↓
Golden Set 생성
```

**관련성 판정 예시**

| 점수 | 의미 |
|---|---|
| 0 | 관련 없음 |
| 1 | 부분적으로 관련 있음 |
| 2 | 매우 관련 있음 |

**장점**
- 도메인 지식을 반영한 높은 신뢰도
- 복잡한 질문 및 문서 관계 판정 가능
- 자동 생성 평가 데이터의 품질 검증 가능

**단점**
- 시간과 비용이 많이 소요됨
- 평가자 간 판단 차이 발생 가능
- 대규모 데이터 구축에 한계

**적합한 목적:** 고신뢰도 Golden Set 구축 및 자동 생성 데이터 검증

---

### 3.4 LLM-as-a-Judge

LLM을 평가자로 사용하여 질문과 문서의 관련성 또는 생성 답변의 품질을 판정하는 방법이다.

**처리 과정**

```text
평가 질문 + 후보 문서
          ↓
      LLM 평가
          ↓
      관련성 점수
          ↓
   판정 결과 검증
          ↓
      Golden Set
```

**장점**
- 관련성 판정 자동화
- 대규모 문서 판정 가능
- Human Annotation 비용 절감

**단점**
- LLM의 판단 오류 가능
- 프롬프트와 모델에 따른 결과 차이
- 도메인 전문 지식 부족 가능
- 모델 및 호출 비용 발생

**적합한 목적:** Pooling 및 Synthetic 데이터의 자동 관련성 판정

※ LLM 판정 결과를 그대로 확정하기보다 일부 표본을 사람이 검수하는 방식이 권장된다.

---

### 3.5 User Log 기반 생성

실제 서비스에서 발생한 사용자 질문, 검색 결과, 클릭 및 피드백을 활용하여 평가 데이터를 생성하는 방법이다.

**처리 과정**

```text
실제 사용자 질문 로그
          ↓
     질문 정제
          ↓
 검색 결과 및 피드백 수집
          ↓
     정답 후보 추출
          ↓
     관련성 판정
          ↓
      Golden Set
```

**장점**
- 실제 사용자 질문 분포 반영
- 실서비스 성능 평가에 적합
- 실제 검색 실패 사례 분석 가능

**단점**
- 서비스 운영 데이터 필요
- 클릭과 실제 정답이 일치하지 않을 수 있음
- 개인정보 보호 및 로그 정제 필요
- 사용자 행동에 따른 편향 발생 가능

**적합한 목적:** 운영 중인 RAG 시스템의 실사용 성능 평가

---

### 3.6 Known-Item 방식

특정 문서를 정답으로 먼저 선택한 다음, 해당 문서를 검색할 수 있는 질문을 생성하는 방법이다.

**처리 과정**

```text
정답 문서 선택
       ↓
문서 내용 분석
       ↓
해당 문서를 찾는 질문 생성
       ↓
질문과 정답 문서 연결
       ↓
Golden Set 생성
```

**장점**
- 질문과 목표 문서 연결이 명확함
- 자동 평가 데이터 구축이 쉬움
- 특정 문서 검색 가능 여부 검증에 유용

**단점**
- 실제 사용자 질문과 차이가 발생할 수 있음
- 다른 문서에도 정답이 존재할 수 있음
- 원본 문서만 정답으로 설정하면 Recall 왜곡 가능

**적합한 목적:** 특정 문서의 검색 성공 여부 평가

※ Synthetic Data Generation과 결합하여 구현할 수 있는 방식이다.

---

### 3.7 Weak Supervision (약지도 학습 기반)

문서의 메타데이터, 분류 정보, 업무 코드, 규칙 등을 활용하여 정답 후보를 자동 추정하는 방법이다.

**처리 과정**

```text
질문 + 문서 메타데이터
          ↓
       규칙 적용
          ↓
    정답 문서 자동 추정
          ↓
     Silver Set 생성
          ↓
    선택적 검수 및 확정
```

**예시**

- 질문의 업무 코드와 문서의 업무 코드가 일치
- FAQ 질문과 연결된 답변 문서 사용
- 문서 카테고리 및 키워드 일치
- 기존 업무 시스템의 질문-문서 연결 정보 활용

**장점**
- 대량 데이터 자동 생성
- LLM 없이도 구현 가능
- 기존 시스템의 메타데이터 활용 가능

**단점**
- 규칙의 정확도에 의존
- 정답 누락 및 오탐 가능
- 복잡한 의미 관계 판단에 한계

**적합한 목적:** 초기 Silver Set 구축 및 자동 평가 데이터 생성

---

### 3.8 Active Learning (능동 학습)

전체 평가 후보를 사람이 검수하는 대신, 판정하기 어렵거나 정보 가치가 높은 데이터만 우선적으로 선택하여 검수하는 방법이다.

**처리 과정**

```text
평가 후보 데이터
        ↓
LLM 또는 판정 모델 평가
        ↓
불확실한 데이터 선별
        ↓
사람이 우선 검수
        ↓
검수 결과 반영
        ↓
추가 검수 대상 선정
```

**장점**
- 사람의 검수 비용 감소
- 어려운 사례에 검수 집중
- 평가 데이터 품질을 효율적으로 개선

**단점**
- 불확실성 판단 기준 필요
- 초기 판정 모델의 품질에 영향받음
- 전체 데이터의 대표성이 부족해질 수 있음

**적합한 목적:** 대규모 Pooling 데이터의 검수 비용 최적화

---

## 4. 방법별 비교

| 방법 | 자동화 수준 | 사람 검수 비용 | 주요 특징 |
|---|---|---|---|
| Pooling | 높음(후보 수집) | 중~높음 | 다양한 검색 결과 통합 |
| Synthetic | 높음 | 낮음~중간 | 질문 대량 생성 |
| Human Annotation | 낮음 | 높음 | 고신뢰도 판정 |
| LLM-as-a-Judge | 높음 | 낮음~중간 | 관련성 자동 판정 |
| User Log | 중간 | 중간 | 실사용 데이터 반영 |
| Known-Item | 높음 | 낮음~중간 | 정답 문서 기반 질문 생성 |
| Weak Supervision | 높음 | 낮음~중간 | 규칙 기반 자동 정답 추정 |
| Active Learning | 중간~높음 | 최적화 가능 | 우선 검수 대상 선정 |

※ 자동화 수준과 비용은 일반적인 경향이며, 실제 문서 품질과 검증 기준에 따라 달라진다.

---

## 5. 평가 목적에 따른 생성 방법 선택

| 평가 목적 | 권장 방법 |
|---|---|
| Dense vs BM25 vs Hybrid 검색 비교 | Pooling + 관련성 판정 |
| 평가 질문 대량 생성 | Synthetic Data Generation |
| 특정 문서 검색 성공 여부 평가 | Known-Item |
| 실제 사용자 검색 품질 평가 | User Log + Human Annotation |
| 신뢰도 높은 정답 데이터 구축 | Human Annotation |
| 평가 구축 비용 절감 | LLM-as-a-Judge + 선택적 검수 |
| 메타데이터 기반 자동 생성 | Weak Supervision |
| 검수 대상 최적화 | Active Learning |
| 여러 문서를 조합하는 추론 평가 | Multi-hop Synthetic Generation |

## 6. RAG 평가 목적에 따른 데이터 구성

RAG 평가는 크게 검색 성능 평가와 답변 생성 성능 평가로 구분할 수 있다.

### 6.1 검색 성능 평가 (Retrieval Evaluation)

검색된 문서가 실제 정답 문서인지 평가한다.

**평가 데이터**

```csv
query_id,doc_id,relevance
Q1,DOC_001,2
Q1,DOC_002,1
Q1,DOC_003,0
```

**주요 평가지표**
- Precision@K
- Recall@K
- nDCG@K
- MRR@K
- Hit Rate@K

### 6.2 답변 생성 성능 평가 (Generation Evaluation)

검색된 문서를 바탕으로 생성한 답변의 정확성 및 근거 충실성을 평가한다.

**평가 데이터**

```json
{
  "query_id": "Q1",
  "question": "연차휴가는 어디에서 신청하나요?",
  "reference_answer": "사내 인사시스템에서 신청합니다.",
  "reference_contexts": ["DOC_001"]
}
```

**주요 평가지표**
- Answer Correctness
- Answer Relevancy
- Faithfulness
- Context Precision
- Context Recall

※ 일부 지표는 정답 답변 없이도 평가할 수 있으며, 필요한 데이터는 사용하는 평가 프레임워크와 지표 정의에 따라 달라진다.

## 7. 추천 평가 데이터 구축 파이프라인

Dense, BM25, Hybrid 검색 시스템을 비교하는 RAG 환경에서는 여러 방식을 결합하는 것이 효과적이다.

### 권장 구성

```text
           기존 문서 데이터
                 │
                 ▼
     Synthetic / Known-Item
        평가 질문 자동 생성
                 │
                 ▼
           평가 질문 목록
                 │
       ┌─────────┼─────────┐
       ▼         ▼         ▼
     Dense      BM25     Hybrid
     Top 20     Top 20    Top 20
       │         │         │
       └─────────┼─────────┘
                 ▼
              Pooling
                 │
                 ▼
            중복 제거
                 │
                 ▼
         LLM 관련성 판정
                 │
                 ▼
           사람 표본 검수
                 │
                 ▼
            Golden Set
                 │
                 ▼
       검색 성능 평가 및 비교
      Precision / Recall / nDCG
```

### 초기 권장 설정

| 항목 | 권장 구성 |
|---|---|
| 평가 질문 | 100개 이상으로 시작 |
| 질문 생성 | Synthetic + 실제 사용자 질문 |
| 검색 방식 | Dense + BM25 + Hybrid |
| Pooling 깊이 | Top 20부터 시작 |
| 중복 제거 | 문서 ID 또는 청크 ID |
| 관련성 점수 | 0 / 1 / 2 |
| 관련성 판정 | LLM + 사람 검수 |
| 평가 지표 | Precision@K, Recall@K, nDCG@K, MRR@K |

Pooling 깊이와 질문 개수는 초기 실험을 위한 예시이며, 정답 누락률과 판정 비용을 확인하면서 조정한다.

### 주의사항

1. 정답 후보 생성과 관련성 판정을 분리한다.
2. 검색 모델과 독립적인 Golden Set을 관리한다.
3. 문서 단위 평가와 청크 단위 평가를 구분한다.
4. 미판정 문서와 관련 없음(0)을 구분한다.
5. 부분적으로 관련 있는 문서(점수 1)를 정답으로 인정할지 미리 정의한다.
6. LLM이 생성한 정답은 검증 후 사용한다.
7. 검색 파라미터 최적화에 사용하는 개발셋과 최종 평가용 테스트셋을 분리한다.

## 8. 핵심 요약

| 구분 | 가장 적합한 방법 |
|---|---|
| 정답 후보 수집 | Pooling |
| 질문 자동 생성 | Synthetic Generation |
| 특정 문서 중심 질문 생성 | Known-Item |
| 정답 정확도 확보 | Human Annotation |
| 관련성 판정 자동화 | LLM-as-a-Judge |
| 실제 사용자 환경 반영 | User Log |
| 메타데이터 활용 | Weak Supervision |
| 사람 검수 비용 절감 | Active Learning |

**최종 권장 방식**

```text
Synthetic Generation
        ↓
   평가 질문 생성
        ↓
      Pooling
        ↓
  정답 문서 후보 확장
        ↓
  LLM 관련성 판정
        ↓
     사람 검수
        ↓
   Golden Set 확정
        ↓
    검색 성능 평가
```

**결론:** RAG 평가 데이터는 하나의 방법으로만 생성할 필요가 없다. Synthetic 방식으로 질문을 생성하고, Pooling으로 정답 후보를 확장한 다음, LLM과 사람의 검수를 통해 Golden Set을 구축하는 혼합 방식이 실용적이다.
