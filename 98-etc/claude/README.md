# AI 코딩 5단계 사용 예시 (Claude Code 기준)

> 프롬프트 → 컨텍스트 → 하네스 → 루프 → 그래프
> 차례로 갈아타는 단계가 아니라 **안쪽에서 바깥쪽으로 겹겹이 감싸는 층**입니다.
> 하네스(자동 검증) 없이 루프·그래프로 넘어가면 잘못된 코드를 더 빨리, 더 많이 만들게 됩니다.

---

## 한눈에 보기

| 단계 | 언제 쓰나 | 핵심 도구 |
|---|---|---|
| 프롬프트 | 한 번에 끝나는 작은 작업 | 명확한 지시 |
| 컨텍스트 | 같은 프로젝트를 여러 날 개발할 때 | `CLAUDE.md`, 새 세션 |
| 하네스 | 같은 실수를 두 번 이상 볼 때 | 훅, 테스트, 린트 |
| 루프 | 목표는 명확한데 시간이 오래 걸릴 때 | `claude -p` + 반복문 |
| 그래프 | 역할을 나누면 품질이 오르는 큰 작업 | 서브에이전트, git worktree |

**선택 기준 한 줄 요약**
- 반복 설명이 귀찮다 → **컨텍스트**
- 같은 실수가 반복된다 → **하네스**
- 기다리는 시간이 길다 → **루프**
- 작업이 커서 한 세션이 감당하기 어렵다 → **그래프**

---

## 1. 프롬프트: 한 번에 끝나는 작은 작업

**쓰기 좋은 경우**: 함수 하나 수정, 에러 메시지 해석, 간단한 리팩터링

**예시**
```
로그인 함수에서 이메일 대소문자 무시하게 고쳐줘. 기존 테스트는 깨지면 안 돼
```

**팁**: **무엇을 바꿀지**와 **무엇은 바꾸면 안 되는지**를 같이 말하세요.

---

## 2. 컨텍스트: 같은 프로젝트를 여러 날 개발할 때

**쓰기 좋은 경우**: 매번 "우리 프로젝트는 Next.js고…"를 반복 설명하고 있을 때

**예시** (프로젝트 루트의 `CLAUDE.md`)
```markdown
- 스택: Next.js 15, Prisma, Tailwind
- API는 app/api/ 아래에만 만든다
- DB 스키마 변경 시 반드시 마이그레이션 파일 생성
- 테스트: npm test
```

**팁**
- 기능 하나가 끝나면 새 세션을 여세요. 대화가 길어질수록 정확도가 떨어집니다.
- Claude가 틀려서 바로잡은 내용은 `CLAUDE.md`에 한 줄씩 추가해 쌓아가세요.

---

## 3. 하네스: 같은 실수를 두 번 이상 볼 때

**쓰기 좋은 경우**: "타입 에러 남겨두고 완료했다고 함", "린트 규칙 안 지킴"

**예시**: 파일을 수정할 때마다 자동으로 검사하는 훅 (`.claude/settings.json`)
```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          { "type": "command", "command": "npx tsc --noEmit && npm run lint" }
        ]
      }
    ]
  }
}
```

**효과**: 에러가 나면 Claude가 그 결과를 보고 스스로 고칩니다. 말로 시킬 필요가 없어집니다.

**구성 요소**
- **가이드 (행동 전)**: `CLAUDE.md`, 스킬, 참고 문서, 코딩 컨벤션
- **센서 (행동 후)**: 린터, 타입 체커, 테스트, AI 코드 리뷰

---

## 4. 루프: 목표는 명확한데 시간이 오래 걸릴 때

**쓰기 좋은 경우**: 실패하는 테스트 30개 고치기, JS → TS 대량 변환, 라이브러리 버전 업그레이드

**예시**
```bash
for i in $(seq 1 10); do
  npm test && break
  claude -p "npm test 실패 원인을 찾아서 하나씩 고쳐줘"
done
```

**조건**: **"다 됐다"를 기계가 판단할 수 있어야** 합니다 (테스트 통과, 빌드 성공 등).
"예쁘게 만들어줘" 같은 주관적인 작업에는 맞지 않습니다.

**주의**
- 반복 횟수 상한을 꼭 두세요 (위 예시는 10회).
- git 브랜치나 worktree에서 돌려서 결과가 이상하면 되돌릴 수 있게 하세요.

---

## 5. 그래프: 역할을 나누면 품질이 오르는 큰 작업

**쓰기 좋은 경우**: 새 기능 전체 개발, 독립적인 작업 여러 개를 동시에 처리

**예시 A: 역할 분리**
`.claude/agents/`에 서브에이전트를 만들고 순서대로 넘기기
- `planner`: 설계와 작업 분해
- `implementer`: 구현
- `reviewer`: 코드 리뷰

**예시 B: 병렬 처리**
git worktree 3개를 만들어서 이슈 3개를 에이전트 3개가 동시에 처리
```bash
git worktree add ../feature-a -b feature-a
git worktree add ../feature-b -b feature-b
git worktree add ../feature-c -b feature-c
```

**효과**: 구현한 에이전트가 자기 코드를 리뷰하지 않으니 놓치는 부분이 줄어듭니다.

---

## 추천 진행 순서

1. `CLAUDE.md`부터 작성 (컨텍스트)
2. 타입 체크·린트·테스트 훅 추가 (하네스) ← **가장 효과가 큰 단계**
3. 테스트가 갖춰진 작업부터 `claude -p` 반복문 적용 (루프)
4. 작업이 커지면 서브에이전트·worktree 도입 (그래프)
