# 역색인과 TF-IDF (Inverted Index, TF-IDF)

sparse 검색의 바탕인 역색인 구조와, 단어 빈도로 문서 점수를 매기는 가장 기본적인 방법인 TF-IDF를 정리한다.

- 폴더 요약과 메인 결정은 [README](./README.md) 참고
- TF-IDF의 한계를 고친 BM25는 [02-bm25](./02-bm25.md) 참고

## 1. sparse 검색이란

- 문서와 질의를 **단어(토큰) 단위 벡터**로 표현한다. 어휘 전체가 차원이라 대부분의 값이 0이다(sparse).
- 질의와 **같은 단어가 들어 있는 문서**를 찾는다. 단어가 겹치지 않으면 의미가 같아도 찾지 못한다.

| 잘하는 것 | 못하는 것 |
| --- | --- |
| 고유명사, 문서 제목, 섹션 번호, 제품·오류 코드, 숫자처럼 정확히 일치해야 하는 검색 | 동의어, 바꿔 말한 표현 ("비번" vs "비밀번호") |
| 학습 없이 바로 사용, 결과 이유를 설명하기 쉬움 | 문맥에 따른 의미 차이 |

## 2. 역색인 (Inverted Index)

문서마다 단어 목록을 저장하는 대신, **단어마다 그 단어가 나온 문서 목록**을 저장한다.

- **목적:** 질문의 단어가 들어 있는 문서만 바로 찾아 점수를 매기기 위해서다. 문서 전체를 하나씩 훑지 않아도 되므로 문서가 수백만 개여도 빠르게 검색할 수 있다.

예시 문서 (토큰화 후)

```text
d1: 재설정 링크 24시간 유효
d2: 비밀번호 재설정 방법 앱 재설정 메뉴
d3: 링크 만료 시 재요청
d4: 회원 링크
```

역색인

```text
재설정  → d1(1회), d2(2회)
링크    → d1(1회), d3(1회), d4(1회)
24시간  → d1(1회)
비밀번호 → d2(1회)
...
```

- 질의 "재설정 링크"가 오면 `재설정`, `링크`의 목록만 읽으면 된다. 전체 문서를 훑지 않는다.
- 목록에 단어 빈도(tf)와 문서 길이를 함께 저장해 두면 점수 계산에 바로 쓸 수 있다.

### 검색 순서

```text
1. 질의 토큰화              "재설정 링크" → [재설정, 링크]
2. 단어별 목록 꺼내기        재설정 → d1, d2
                            링크   → d1, d3, d4
3. 문서별 점수 더하기        d1 = 재설정 점수 + 링크 점수   (두 목록에 모두 있음)
                            d2 = 재설정 점수,  d3 = 링크 점수,  d4 = 링크 점수
4. 점수 순으로 정렬          상위 k개 반환
```

- **목록에 없는 문서는 계산하지 않고 0점이다.** 질의 단어가 하나도 없는 문서는 처음부터 후보가 아니다. 의미가 같아도 단어가 다르면 못 찾는 이유가 이것이다.
- 질의 단어가 여러 개면 **하나라도 들어 있는 문서**가 후보가 된다. 여러 단어가 함께 있는 문서가 보통 더 높을 뿐이다.
- 3번의 점수 계산 방식만 TF-IDF(3장), BM25([02-bm25](./02-bm25.md)), 학습된 sparse([03-learned-sparse](./03-learned-sparse.md))마다 다르다. 꺼내서 더하는 순서는 같다.
- 빠른 이유: 질의 단어가 나온 문서만 본다. 문서가 100만 개여도 그 단어가 나온 문서가 1,000개면 1,000개만 계산한다.
- 실제 엔진은 여기에 최적화를 더한다. 단어마다 낼 수 있는 최대 점수를 알아 두고, 현재 상위 k개를 넘을 수 없는 문서는 계산하지 않고 건너뛴다(WAND, MaxScore). 목록은 문서 ID 순으로 정렬·압축해 저장한다.

### sparse 벡터와 역색인은 같은 데이터다

```text
[문서 기준으로 보면 = sparse 벡터]       d2: {비밀번호: 1, 재설정: 2, 방법: 1, 앱: 1, 메뉴: 1}
[단어 기준으로 뒤집으면 = 역색인]         재설정 → d1(1회), d2(2회)
```

- 문서마다 `{단어: tf}`를 적으면 어휘 수만큼 칸이 있고 대부분 0인 벡터, 즉 sparse 벡터다. 이것을 단어 기준으로 뒤집은 것이 역색인이다.
- 그래서 "키워드 검색"과 "sparse 벡터 검색"은 같은 데이터를 다르게 부르는 것이다. 의미를 압축한 임베딩(dense) 벡터와는 다르다. 벡터 DB가 BM25를 sparse 벡터 필드에 담는 것도 이 때문이다([03-vector-index/02-vector-db](../03-vector-index/02-vector-db.md) 4.2).
- dense 검색은 역색인 대신 ANN 인덱스로 가까운 벡터를 찾는다. 단어가 겹치지 않아도 모든 문서가 거리로 비교된다([03-vector-index/01-ann-algorithms](../03-vector-index/01-ann-algorithms.md)).

## 3. TF-IDF

```text
tf(t, d)  = 문서 d에 단어 t가 나온 횟수
idf(t)    = log(N / df(t))           N: 전체 문서 수, df(t): t가 나온 문서 수
score(q, d) = Σ_{t ∈ q} tf(t, d) × idf(t)
```

- **tf**: 문서 안에서 많이 나올수록 그 문서의 주제일 가능성이 높다.
- **idf**: 여러 문서에 흔하게 나오는 단어는 구별력이 낮으니 가중치를 낮춘다.

### 손계산 예시

질의: `재설정 링크`, N = 4

```text
df(재설정) = 2 → idf = ln(4/2) = 0.693
df(링크)   = 3 → idf = ln(4/3) = 0.288
```

| 문서 | 재설정 tf | 링크 tf | 계산 | TF-IDF 점수 | 순위 |
| --- | --- | --- | --- | --- | --- |
| d1 | 1 | 1 | 1 × 0.693 + 1 × 0.288 | 0.981 | 2 |
| d2 | 2 | 0 | 2 × 0.693 | **1.386** | **1** |
| d3 | 0 | 1 | 1 × 0.288 | 0.288 | 3 (동점) |
| d4 | 0 | 1 | 1 × 0.288 | 0.288 | 3 (동점) |

읽는 법
- 질의 두 단어를 모두 가진 d1보다, `재설정`만 두 번 나온 d2가 1위다. **tf가 끝없이 커지는** 문제다.
- d3(4단어)과 d4(2단어)는 같은 점수다. 짧은 문서에서 한 번 나온 단어가 더 중요할 수 있는데 **문서 길이를 반영하지 않는다.**
- 이 두 문제를 고친 것이 BM25다. 같은 예시를 [02-bm25](./02-bm25.md)에서 다시 계산한다.

## 4. 텍스트 분석 (정규화, 토큰화, 동의어)

sparse 검색 품질은 토큰화에 크게 좌우된다. 질의와 문서를 **같은 방식으로** 토큰화해야 단어가 겹친다.

분석 순서 (색인과 검색에 똑같이 적용)

```text
1. 정규화      표기를 하나로 맞춤
2. 토큰화      단어로 자름 (아래 표)
3. 필터        기능어 제거, 동의어 치환
```

### 정규화

토큰화 전에 표기를 맞추지 않으면 같은 단어가 다른 단어로 색인된다.

| 대상 | 예 | 처리 |
| --- | --- | --- |
| 유니코드 | 전각 `ＡＢＣ１２３` / 반각 `ABC123`, 조합형·완성형 한글 | NFKC 정규화 |
| 영문 대소문자 | `Wi-Fi`, `wifi`, `WIFI` | 소문자로 통일, 하이픈 처리 규칙 정함 |
| 숫자·단위 | `7일`, `7 일`, `칠일`, `1,000원`, `1000원` | 숫자 표기 통일, 숫자와 단위 분리 여부 정함 |
| 한영 혼용 | `와이파이` / `Wi-Fi`, `앱` / `App` | 동의어 사전으로 묶음 (아래) |

- 정규화를 너무 세게 하면 구분해야 할 것이 합쳐진다(예: 제품 코드 `E-4012`와 `E4012`가 다른 제품일 때). 코드·식별자는 따로 규칙을 둔다.

### 토큰화

| 방식 | 예: "재설정링크는" | 장점 | 단점 |
| --- | --- | --- | --- |
| 공백 기준 | `재설정링크는` | 단순 | 조사·붙여쓰기 때문에 거의 안 겹침 |
| 형태소 분석 (Kiwi, Mecab 등) | `재설정`, `링크`, `는` | 한국어 조사·어미 분리 | 사전에 없는 신조어, 도메인 전문 용어 오분석 |
| 글자 n-gram (예: 2-gram) | `재설`, `설정`, `정링`, `링크`, `크는` | 사전 불필요, 붙여쓰기에 강함 | 색인이 커지고 잡음이 많음 |

- 한국어는 공백 기준이 거의 쓸모없다. 형태소 분석을 기본으로 하고, 조사·어미 같은 기능어는 제거한다.
- 문서 제목, 제품 코드(`E-4012`)처럼 쪼개지면 안 되는 표현은 사용자 사전에 등록한다.
- 토크나이저를 바꾸면 색인을 다시 만들어야 한다. 토크나이저 이름과 버전, 사용자 사전 버전을 평가 결과와 함께 남긴다.

### 동의어 사전

사용자 사전은 **단어가 쪼개지지 않게** 하고, 동의어 사전은 **다른 단어를 같은 단어로 묶는다.** 역할이 다르다.

```text
동의어 사전:  비번, 패스워드 → 비밀번호
질의 "비번 재설정"  →  [비밀번호, 재설정]   → "비밀번호"로 색인된 문서와 겹침
```

| 적용 시점 | 방식 | 장단점 |
| --- | --- | --- |
| 검색할 때 (질의만) | 질의 단어에 동의어를 덧붙이거나 바꿈 | 사전을 고쳐도 재색인 불필요. 보통 이쪽을 먼저 쓴다 |
| 색인할 때 (문서) | 문서 단어에 동의어를 함께 색인 | 검색이 빠름. 사전을 고치면 재색인, 색인이 커짐 |

- dense나 확장형 sparse 없이 BM25만으로 어휘 불일치를 줄이는 가장 싼 방법이다. 다만 **사전에 적은 것만** 되고 문맥을 구분하지 못한다("사과 = 애플"을 항상 적용). 학습된 sparse와 비교는 [03-learned-sparse](./03-learned-sparse.md) 4장 "도메인 전문 용어에 대응하는 방법" 참고
- 동의어를 넣으면 idf와 tf가 바뀐다. 넣기 전후를 골든셋 dev 세트로 비교하고, 사전 버전을 결과와 함께 남긴다.
- 사전 후보는 검색 실패 질의 로그와 골든셋의 `user` 말투 질문에서 찾는다.

## 5. 확인할 점

- 불용어 제거는 질의와 문서에 똑같이 적용한다. 한쪽만 적용하면 겹침이 깨진다.
- idf는 색인한 문서 집합에서 계산된다. 문서를 추가하면 같은 질의의 점수가 바뀔 수 있다. 기준선을 비교할 때 문서 집합 버전을 함께 기록한다.
