# 학습된 sparse 검색 (Learned Sparse Retrieval)

BM25처럼 "단어 → 가중치" 형태의 sparse 벡터를 쓰되, 가중치를 공식이 아니라 언어 모델이 매기는 검색을 정리한다. 가중치만 학습하는 방식과 문서에 없는 단어까지 덧붙이는 확장형(SPLADE)으로 나눠 보고, 대표 모델인 SPLADE를 따로 설명한다.

- 폴더 요약과 메인 결정은 [README](./README.md) 참고
- 공식 기반 sparse 검색은 [02-bm25](./02-bm25.md), 역색인은 [01-inverted-index-tfidf](./01-inverted-index-tfidf.md) 참고
- 의미 기반 검색은 [02-dense-retrieval](../02-dense-retrieval/README.md) 참고

## 1. 학습된 sparse란

BM25는 tf·idf 공식으로 단어 가중치를 계산한다. 학습된 sparse는 **언어 모델이 문맥을 보고 단어 가중치를 매긴다.** 결과는 여전히 sparse 벡터라서 BM25와 같은 역색인에 그대로 넣을 수 있고, 어떤 단어 때문에 찾았는지도 보인다. dense처럼 의미를 벡터 하나로 압축하지 않는다.

```text
sparse 검색
├─ 공식 기반: BM25, TF-IDF
└─ 학습된 sparse (모델이 단어 가중치를 매김)
   ├─ 가중치만 학습: DeepImpact, uniCOIL, bge-m3 sparse 등
   └─ 확장형:        SPLADE (대표), SPLADE++ 등
```

## 2. 두 종류: 가중치만 학습 / 확장형

문서에 없는 단어까지 덧붙이는지(확장)에 따라 나뉜다.

| | BM25 | 가중치만 학습 | 확장형 |
| --- | --- | --- | --- |
| 단어 가중치 | tf, idf, 문서 길이로 계산 | 모델이 문맥을 보고 예측 | 모델이 문맥을 보고 예측 |
| 가중치를 받는 단어 | 입력에 나온 단어 | **입력에 나온 토큰만** | 입력 토큰 + **어휘 전체 중 관련 단어** |
| 문서에 없는 단어 | 점수 0 | 점수 0 | 관련 단어로 확장해 점수를 줌 ("환불" 문서에 "취소") |
| 주로 고치는 것 | - | 의미 없는 단어가 자주 나와 점수가 오르는 문제 (단어 중요도) | 위 문제 + 동의어·다른 표현 (어휘 불일치) |
| 토큰 단위 | 형태소 분석기 + 사용자 사전 (직접 정함) | 모델의 서브워드 토크나이저 (고정) | 모델의 서브워드 토크나이저 (고정) |
| 학습·인코딩 | 불필요, CPU로 빠름 | 문서 전체를 모델로 인코딩 | 문서 전체를 모델로 인코딩, 색인이 더 큼 |
| 설명 가능성 | 높음 | 높음 (겹친 단어가 그대로 보임) | 중간 (확장된 단어는 보이지만 왜 확장됐는지는 모름) |
| 대표 예 | `rank_bm25`, Elasticsearch | **bge-m3의 sparse 출력** | **SPLADE** |

## 3. 학습 방식

- 사전처럼 사람이 등록하는 것이 아니라, 질문과 정답 문서 쌍(+ 비슷하지만 정답이 아닌 문서)으로 학습한다. 정답 문서와의 점수는 높이고 오답 문서와의 점수는 낮추는 대조 학습이다.
- 확장형은 BERT가 빈칸 단어를 맞히는 부분을 써서 어휘 전체에 점수를 낸 뒤, 0이 아닌 단어 수에 벌점을 줘(희소성 규제) 수십~수백 개만 남긴다.
- 그래서 같은 단어라도 문장에 따라 가중치와 확장이 달라진다. 반대로 학습 데이터에 없던 도메인 용어는 약하다.

## 4. 손계산 예시

점수는 두 종류 모두 질의와 문서에 함께 있는 단어의 가중치 곱을 더한다.

```text
score(q, d) = Σ (단어 t가 q와 d 모두에 있을 때) w_q(t) × w_d(t)
```

예: 질의 "환불 지연"

```text
문서 A "결제 취소 후 환불은 3~5일 이내 처리"
문서 B "배송 지연 시 보상 기준"

[가중치만 학습]
질의:  환불 1.5, 지연 1.0
A:     환불 1.2, 취소 1.0, 결제 0.8, 처리 0.6
B:     지연 1.4, 배송 1.3, 보상 0.9
score(A) = 1.5 × 1.2 (환불)                    = 1.8
score(B) = 1.0 × 1.4 (지연)                    = 1.4

[확장형]
질의:  환불 1.5, 지연 1.0, 취소 0.5(확장)
A, B:  위와 같음 (문서 쪽 확장은 생략)
score(A) = 1.5 × 1.2 (환불) + 0.5 × 1.0 (취소) = 2.3
score(B) = 1.0 × 1.4 (지연)                    = 1.4
```

- BM25였다면 A는 "환불", B는 "지연" 한 단어씩만 겹쳐 비슷한 점수가 나온다.
- 가중치만 학습해도 모델이 "환불"을 더 중요한 단어로 보면 A가 앞선다(1.8 대 1.4). 다만 겹치는 단어 자체는 BM25와 같다.
- 확장형은 질의를 "취소"로 넓혀서 A를 더 확실히 올린다(2.3 대 1.4). 대신 확장이 틀리면(관련 없는 단어로 확장) BM25에 없던 오답이 들어온다.
- "결제했는데 돈이 안 돌아와요"처럼 겹치는 단어가 하나도 없는 질문은 가중치만 학습하는 방식으로는 못 찾는다. 이 경우는 확장형이나 dense가 맡는다.

## 5. SPLADE: 확장형의 대표 모델

"학습된 sparse"는 방식의 이름이고, SPLADE는 그 방식 중 확장형에 속하는 모델의 이름이다.

| 질문 | 답 |
| --- | --- |
| 학습된 sparse = SPLADE인가? | 아니다. SPLADE는 학습된 sparse 중 하나다 |
| 학습된 sparse는 모두 확장을 하나? | 아니다. 확장은 SPLADE 계열의 특징이다. bge-m3 sparse는 확장하지 않는다 |
| lawlens가 쓰는 것은? | bge-m3 sparse. 학습된 sparse이지만 SPLADE 계열은 아니다 |

대표로 꼽히는 이유
- 확장과 가중치 학습을 **한 모델 안에서 같이** 한다. 이전에는 둘을 따로 했다(doc2query로 문서에 질문을 생성해 덧붙이는 확장, 별도 모델로 가중치).
- 희소성 규제로 0이 아닌 단어 수를 줄여, 역색인으로 실제 검색할 수 있는 효율을 맞췄다.
- 이후 버전(SPLADE v2, SPLADE++)에서 하드 네거티브와 cross-encoder 증류를 더해 성능을 올렸다. 학습된 sparse의 기준 모델처럼 쓰인다.

변형
| 변형 | 내용 | 장단점 |
| --- | --- | --- |
| 질의·문서 모두 확장 | 질의도 모델로 인코딩해 확장 | 정확도가 높지만 질문마다 모델 호출 |
| 문서만 확장 | 문서는 색인할 때 확장, 질의는 토큰 그대로 | 검색할 때 모델 호출이 없어 빠름. 질의 쪽 확장 효과는 없음 |

- 공개된 SPLADE 모델은 주로 영어로 학습되어 있다. 한국어 문서에 쓰려면 다국어 모델이나 한국어로 추가 학습한 모델이 있는지 먼저 확인한다.

## 6. 비교할 때 주의

- **BM25와 별도의 기준선이다.** "sparse 검색"이라고 묶어서 하나만 재지 않는다. 어느 종류인지(가중치만 / 확장형)도 결과에 적는다.
- 같은 모델의 dense와 학습된 sparse는 같은 학습 데이터에서 나와서 실패하는 질문이 겹치기 쉽다. 하이브리드나 골든셋 pool에서 서로 다른 검색기로 세지 않는다([03-golden-set/02-pooling](../../03-evals/03-golden-set/02-pooling.md) 6장).
- 토크나이저가 고정이라 사용자 사전을 넣을 수 없다. 코드·고유명사가 잘게 쪼개지면 BM25보다 정확 일치가 약할 수 있다.
- 동의어 대응을 기대한다면 확장형인지 먼저 확인한다. bge-m3 sparse는 확장하지 않으므로 동의어는 dense 쪽이 맡는다.

## 7. 확인할 점

- 모델 이름과 함께 종류(가중치만 / 확장형)와 확장 방식(질의·문서 / 문서만)을 결과에 기록한다.
- 확장형은 확장된 단어 수만큼 색인이 커진다. 문서당 0이 아닌 단어 수의 평균을 기록하고, 색인 크기와 검색 지연을 BM25와 비교한다.
- 학습 데이터에 없던 도메인 용어가 어떻게 토큰화되고 가중치를 받는지 몇 개 직접 확인한다([07-ml/01-pytorch-hf/02-huggingface](../../07-ml/01-pytorch-hf/02-huggingface.md)).
