# BM25와 변형 (BM25, BM25+, BM25L, BM25F)

TF-IDF의 두 문제(tf가 끝없이 커짐, 문서 길이 무시)를 고친 BM25와 그 변형을 정리한다. BM25는 sparse 검색의 사실상 표준이고, 이 저장소의 모든 검색 비교에서 첫 번째 기준선이다.

- 폴더 요약과 기본 선택은 [README](./README.md) 참고
- 역색인과 TF-IDF는 [01-inverted-index-tfidf](./01-inverted-index-tfidf.md) 참고

## 1. 공식

```text
score(q, d) = Σ_{t ∈ q} idf(t) × tf(t, d) × (k1 + 1) / ( tf(t, d) + k1 × (1 − b + b × |d| / avgdl) )

idf(t) = ln( 1 + (N − df(t) + 0.5) / (df(t) + 0.5) )      (Lucene 방식, 항상 양수)
```

| 기호 | 의미 | 기본값 |
| --- | --- | --- |
| k1 | tf 포화 정도. 클수록 tf를 더 오래 반영 | 1.2 (보통 1.2~2.0) |
| b | 문서 길이 정규화 강도. 0이면 길이 무시, 1이면 완전 정규화 | 0.75 |
| \|d\| | 문서 길이 (토큰 수) | - |
| avgdl | 전체 문서 평균 길이 | - |

두 가지 개선
- **tf 포화**: tf가 커져도 점수가 `(k1 + 1)`에 가까워질 뿐 끝없이 커지지 않는다.
- **길이 정규화**: 평균보다 긴 문서는 tf의 효과를 줄이고, 짧은 문서는 키운다.

## 2. 손계산 예시

[01-inverted-index-tfidf](./01-inverted-index-tfidf.md)와 같은 문서, 같은 질의 `재설정 링크`

```text
N = 4, 문서 길이: d1 = 4, d2 = 6, d3 = 4, d4 = 2 → avgdl = 4
k1 = 1.2, b = 0.75

idf(재설정) = ln(1 + (4 − 2 + 0.5) / (2 + 0.5)) = ln(2.0)   = 0.693
idf(링크)   = ln(1 + (4 − 3 + 0.5) / (3 + 0.5)) = ln(1.429) = 0.357
```

길이 정규화 항 `k1 × (1 − b + b × |d| / avgdl)`

| 문서 | \|d\| | 정규화 항 |
| --- | --- | --- |
| d1, d3 | 4 | 1.2 × (0.25 + 0.75 × 1.0) = 1.20 |
| d2 | 6 | 1.2 × (0.25 + 0.75 × 1.5) = 1.65 |
| d4 | 2 | 1.2 × (0.25 + 0.75 × 0.5) = 0.75 |

| 문서 | 재설정 tf 항 | 링크 tf 항 | BM25 점수 | BM25 순위 | TF-IDF 순위 |
| --- | --- | --- | --- | --- | --- |
| d1 | 1 × 2.2 / (1 + 1.20) = 1.000 | 1.000 | 0.693 + 0.357 = **1.050** | **1** | 2 |
| d2 | 2 × 2.2 / (2 + 1.65) = 1.205 | - | 0.693 × 1.205 = 0.836 | 2 | 1 |
| d4 | - | 1 × 2.2 / (1 + 0.75) = 1.257 | 0.357 × 1.257 = 0.448 | 3 | 3 (동점) |
| d3 | - | 1.000 | 0.357 | 4 | 3 (동점) |

읽는 법
- **tf 포화**: d2의 `재설정` tf는 2지만 tf 항은 1.205다. 두 배가 되지 않는다. 그래서 질의 두 단어를 모두 가진 d1이 1위로 올라온다.
- **길이 정규화**: d3과 d4는 `링크`를 한 번씩 가졌지만, 짧은 d4(2단어)의 tf 항이 1.257로 더 크다. TF-IDF에서는 동점이었다.

### 단어 하나만 검색할 때: 횟수가 많다고 1위가 아니다

질의 "사과", 평균 문서 길이 100토큰, k1 = 1.2, b = 0.75

| 문서 | 사과 tf | 문서 길이 | tf 항 | 순위 |
| --- | --- | --- | --- | --- |
| A | 2 | 50 | 2 × 2.2 / (2 + 1.2 × 0.625) = 2 × 2.2 / (2 + 0.75) = **1.60** | **1** |
| B | 5 | 400 | 5 × 2.2 / (5 + 1.2 × 3.25) = 5 × 2.2 / (5 + 3.90) = **1.24** | 2 |

- 후보는 "사과"가 나온 문서뿐이다(목록에 없는 문서는 0점). 그 안의 순위는 tf 포화와 길이 정규화가 정한다.
- 단어가 하나뿐이면 idf는 모든 후보에 같은 값으로 곱해져 순위에 영향이 없다.
- 횟수는 B가 많지만, 짧은 문서에 2번 나온 A를 "사과에 관한 문서"일 가능성이 더 높다고 본다. 단순 횟수나 TF-IDF였다면 B가 1위다.

## 3. 파라미터 조정

| 상황 | 조정 방향 |
| --- | --- |
| 같은 단어 반복이 실제로 중요함 (긴 설명 문서) | k1을 올린다 |
| 문서 길이가 고르게 비슷함 (섹션 단위 청크) | b의 영향이 작다. 기본값 유지 |
| 긴 문서가 부당하게 밀림 | b를 낮춘다 |
| 짧은 제목·FAQ가 지나치게 위로 옴 | b를 올리거나 필드별로 나눈다 (BM25F) |

- 파라미터는 골든셋 **dev 세트**에서만 조정한다. test 세트로 조정하면 기준선이 부풀려진다([04-update-loop](../../03-evals/03-golden-set/04-update-loop.md) 5장).
- 조정 전후를 같은 표에 남긴다. 기본값(k1 = 1.2, b = 0.75)도 하나의 기준선이다.

## 4. 변형

| 변형 | 고친 문제 | 핵심 아이디어 | 쓰면 좋은 곳 |
| --- | --- | --- | --- |
| BM25+ | 아주 긴 문서에서 질의 단어가 나와도 tf 항이 0에 가까워짐 | tf 항에 작은 하한 δ를 더함 | 문서 길이 차이가 매우 큰 경우 |
| BM25L | 긴 문서가 지나치게 불리함 | 길이로 나눈 tf에 상수를 더해 긴 문서 보정 | 긴 문서가 정답인 경우가 많을 때 |
| BM25F | 제목, 본문 등 필드 구분 없음 | 필드마다 가중치와 길이 정규화를 따로 적용 | 문서 제목·섹션 제목·본문처럼 필드가 있는 문서 |

- 정책·매뉴얼 문서처럼 문서 제목, 섹션 제목, 본문이 나뉘어 있으면 BM25F를 시도해 볼 만하다. 다만 먼저 기본 BM25 기준선을 잡은 뒤 비교한다.

## 5. 공식 밖에서 보완하는 방법

BM25 공식은 단어 하나하나를 따로 센다. 단어 순서와 어휘 불일치는 공식 밖에서 보완한다.

| 방법 | 고치는 것 | 방식 |
| --- | --- | --- |
| 동의어 사전 | 정해 둔 다른 표현 | 분석 단계에서 같은 단어로 바꿈 ([01-inverted-index-tfidf](./01-inverted-index-tfidf.md) 4장) |
| 질의 확장 (pseudo-relevance feedback, RM3) | 질의에 없는 관련 단어 | 1차 검색 상위 문서에서 자주 나온 단어를 뽑아 질의에 덧붙이고 다시 검색 |
| 구문 검색 (phrase) | 단어 순서 | 단어가 그 순서로 붙어 나오는 문서만 찾거나 가산점 |
| 근접 검색 (proximity) | 단어 간 거리 | 질의 단어들이 가까이 나올수록 가산점 |

질의 확장 (RM3) 흐름

```text
1. 질의 "환불 지연"으로 BM25 검색
2. 상위 10개 문서를 정답이라고 가정 (실제로 판정하지 않음 → pseudo)
3. 그 문서들에 자주 나온 단어 중 질의에 없는 것: 취소, 처리기간, 결제
4. 원래 질의 + 확장 단어(낮은 가중치)로 다시 검색
```

- 1차 상위 문서가 맞으면 Recall이 오르지만, 틀리면 엉뚱한 단어가 덧붙어 더 나빠진다(질의 표류). 정답 문서가 드문 질문에서 오히려 떨어질 수 있다.
- 검색을 두 번 하므로 지연이 늘어난다. 학습이 필요 없어 확장형 sparse의 가장 싼 대안으로 비교해 볼 만하다.
- 구문·근접 검색은 Elasticsearch / OpenSearch의 `match_phrase`, `slop` 같은 기능으로 지원된다. 위치 정보(position)를 역색인에 함께 저장해야 해서 색인이 커진다. `rank_bm25` 같은 단순 라이브러리에는 없다.

## 6. 학습된 sparse와의 관계

BM25는 단어 가중치를 **공식**으로 계산한다. 같은 역색인 구조를 쓰면서 가중치를 **언어 모델**이 매기는 것이 학습된 sparse다.

```text
sparse 검색
├─ 공식 기반: BM25, TF-IDF                (이 노트)
└─ 학습된 sparse (모델이 단어 가중치를 매김)
   ├─ 가중치만 학습: bge-m3 sparse 등      입력에 나온 토큰에만 가중치
   └─ 확장형:        SPLADE 등             문서에 없는 관련 단어까지 덧붙임
```

- "학습된 sparse"는 방식의 이름이고, SPLADE는 그중 확장형의 대표 모델이다. 학습된 sparse가 모두 확장을 하는 것은 아니다.
- BM25의 약점 중 단어 중요도는 두 종류 모두 보완하고, 동의어·다른 표현은 확장형만 일부 보완한다. 학습 없이 보완하려면 동의어 사전이나 질의 확장(5장)을 쓴다.
- BM25와는 별도의 기준선으로 비교한다. 자세한 비교, 손계산, 학습 방식은 [03-learned-sparse](./03-learned-sparse.md) 참고

## 7. 확인할 점

- **BM25 점수는 질의끼리 비교할 수 없다.** 점수 크기가 질의 단어 수, idf, 문서 집합에 따라 달라서 "8점 이상이면 관련 문서" 같은 고정 임계값을 정할 수 없다. 같은 질의 안의 순위만 의미가 있다. 그래서 dense 점수와 합칠 때는 순위 기반 결합(RRF)이나 질의별 정규화를 쓴다([04-advanced-rag/01-hybrid-search/01-fusion-methods](../../04-advanced-rag/01-hybrid-search/01-fusion-methods.md)).
- 라이브러리마다 idf 공식과 기본값이 조금씩 다르다(예: idf에 `1 +`를 더하는지). 라이브러리 이름과 버전을 평가 결과와 함께 남긴다.
- 직접 구현했다면 이 노트의 손계산 예시를 단위 테스트로 쓴다([05-regression-ci](../../03-evals/05-regression-ci/01-gate-design.md) L0).
