# 임베딩 검색 기초 (Embedding Basics)

질의와 문서를 의미 벡터로 바꿔 가까운 문서를 찾는 dense 검색의 원리, 유사도 척도, 인코딩할 때 주의할 점을 정리한다.

- 폴더 요약과 메인 결정은 [README](./README.md) 참고
- 토큰마다 벡터를 남기는 멀티 벡터는 [02-multi-vector](./02-multi-vector.md), 임베딩 모델을 고르는 방법은 [03-model-selection](./03-model-selection.md) 참고

## 1. dense 검색이란

```text
문서 ──▶ [임베딩 모델] ──▶ 벡터 (예: 1024차원)  ──▶ 벡터 인덱스에 저장
질의 ──▶ [임베딩 모델] ──▶ 벡터                 ──▶ 가까운 문서 벡터 top-k 검색
```

- 모든 차원에 값이 있는 짧은 벡터다(dense). 단어가 겹치지 않아도 의미가 비슷하면 가깝다.
- 질의와 문서를 **각각 따로** 인코딩한다(bi-encoder). 문서 벡터는 미리 계산해 두므로 검색이 빠르다.
- 질의와 문서를 **함께** 넣어 점수를 내는 cross-encoder는 더 정확하지만 느려서 리랭커로 쓴다([04-advanced-rag/02-reranking](../../04-advanced-rag/02-reranking/README.md)).

| sparse (BM25) | dense |
| --- | --- |
| "비번 재설정"으로 "비밀번호 재설정" 문서를 못 찾음 | 찾음 |
| "E-4012"를 정확히 찾음 | 비슷한 번호의 다른 코드와 헷갈릴 수 있음 |
| 학습 불필요 | 임베딩 모델 필요, 도메인이 다르면 성능 하락 |

두 방식은 서로 다른 질문에 강하다. 그래서 둘을 섞는 하이브리드가 다음 단계다.

### 벡터 하나로 합치는 방식 (풀링)

모델은 토큰마다 벡터를 낸다. 이를 청크 벡터 하나로 합치는 방식을 **풀링**이라 하고, 모델마다 학습할 때 쓴 방식이 정해져 있다.

```text
"환불은 7일 이내" → 토큰마다 출력 h_CLS, h1 … h5
[CLS] 풀링:     h_CLS 하나를 그대로 씀                 예: bge 계열(bge-m3)
평균 풀링:      h1 … h5의 평균                        예: e5 계열(multilingual-e5)
마지막 토큰:    마지막 토큰 위치의 출력                예: 일부 LLM 기반 모델(Qwen3-Embedding 등)
```

- 학습 때와 다른 풀링을 쓰면 **오류 없이 성능만 떨어진다.** 결과가 그럴듯해 보여서 알아채기 어렵다.
- `sentence-transformers`로 불러오면 모델에 저장된 풀링 설정을 따른다. `transformers`로 직접 불러와 출력을 쓸 때는 풀링과 정규화를 모델 설명서대로 직접 맞춘다([07-ml/01-pytorch-hf/02-huggingface](../../07-ml/01-pytorch-hf/02-huggingface.md)).
- 평균 풀링은 패딩 토큰을 빼고 평균한다(attention mask 사용). 패딩까지 평균하면 배치 크기에 따라 벡터가 달라진다.
- 합치지 않고 토큰 벡터를 모두 남기는 것이 멀티 벡터다([02-multi-vector](./02-multi-vector.md)).

### 의미가 가까워지는 원리

모델이 단어 뜻을 알아서 가까워지는 것이 아니다. **질문과 그 정답 문서가 가까워지도록 학습했기 때문이다.**

```text
학습 데이터:  (질문, 정답 문서) 쌍 수백만~수억 개
학습 목표:    질문 벡터와 정답 문서 벡터는 가깝게,
              같은 배치의 다른 문서(오답) 벡터와는 멀게      ← 대조 학습
결과:         "비번 재설정"과 "비밀번호 재설정 방법"이 자주 같은 쌍으로 나왔다면 두 벡터가 가까워짐
```

- 그래서 dense가 말하는 "의미가 비슷하다"는 **학습 데이터에서 같은 질문의 정답이 되곤 했다**는 뜻이다. 사람이 보는 의미와 다를 수 있다.
- 학습 데이터에 드문 구분(부정, 숫자 차이, 도메인 용어)은 벡터에 잘 반영되지 않는다(4장).
- 학습 데이터에 없던 도메인은 질문-문서 쌍으로 추가 학습해 고친다. 손실 함수와 데이터 만드는 법은 [07-ml/02-embedding-finetuning](../../07-ml/02-embedding-finetuning/README.md) 참고

## 2. 유사도 척도

| 척도 | 정의 | 특징 |
| --- | --- | --- |
| 코사인 유사도 | `q·d / (‖q‖ ‖d‖)` | 방향만 봄. 길이 무시 |
| 내적 (dot product) | `q·d` | 방향과 길이를 함께 봄 |
| L2 거리 | `‖q − d‖` | 작을수록 가까움 |

- 벡터를 길이 1로 정규화하면 세 척도의 **순위가 같아진다.** 코사인 = 내적이고, L2 거리² = 2 − 2 × 코사인이다.
- 모델마다 학습할 때 쓴 척도가 있다. 모델 설명서의 권장 척도를 따르고, 정규화 여부를 기록한다.

### 손계산 예시: 정규화하지 않으면 순위가 바뀐다

```text
질의 q  = (1, 1, 0)
문서 a  = (2, 2, 1)     ← 길이가 긴 벡터
문서 b  = (1, 1, 0)     ← q와 방향이 완전히 같음
```

| 문서 | 내적 | 코사인 |
| --- | --- | --- |
| a | 1×2 + 1×2 + 0×1 = **4** | 4 / (√2 × 3) = 0.943 |
| b | 1×1 + 1×1 + 0 = 2 | 2 / (√2 × √2) = **1.000** |

- 내적으로는 a가 1위, 코사인으로는 b가 1위다.
- 모델이 코사인으로 학습됐는데 정규화 없이 내적으로 검색하면 벡터 길이가 긴 문서가 부당하게 위로 온다.

### 점수의 절대값은 믿기 어렵다

코사인은 −1~1 범위지만, 실제 점수가 그 범위에 고르게 퍼지지 않는다.

```text
같은 질문, 같은 문서 집합 (예시)
모델 A:  정답 0.86, 관련 없는 문서 0.78     ← 전체가 0.7~0.9에 몰림
모델 B:  정답 0.62, 관련 없는 문서 0.21
```

- 모델마다 점수 분포가 다르다. 학습 방식(온도 값 등) 때문에 관련 없는 문서도 0.7 이상이 나오는 모델이 흔하다. "0.8 이상이면 관련 문서" 같은 고정 임계값은 모델을 바꾸면 그대로 쓸 수 없다.
- 같은 모델 안에서도 질문 길이와 주제에 따라 분포가 달라진다. 점수보다 **같은 질문 안의 순위**가 더 믿을 만하다. BM25 점수를 질의끼리 비교할 수 없는 것과 같은 문제다([01-sparse-retrieval/02-bm25](../01-sparse-retrieval/02-bm25.md) 7장).
- 임계값이 필요하면(답 없음 판정, 낮은 점수 문서 버리기) 골든셋 dev 세트로 정한다. 답 있는 질문과 답 없는 질문([03-golden-set/01-query-sources](../../03-evals/03-golden-set/01-query-sources.md) "답 없음 질의 만들기")의 top-1 점수 분포를 그려 보고, 놓치는 정답과 걸러지는 오답의 비율로 고른다. 모델을 바꾸면 다시 정한다.
- 단독 임계값보다 리랭커 점수가 구분력이 좋은 경우가 많다([04-advanced-rag/02-reranking](../../04-advanced-rag/02-reranking/README.md)).

## 3. 인코딩할 때 주의할 점

| 항목 | 내용 |
| --- | --- |
| 최대 길이 | 모델의 최대 입력 토큰을 넘는 부분은 **잘려서 무시된다.** 긴 섹션은 뒷부분 내용이 벡터에 반영되지 않는다. 청크 크기를 최대 길이 안으로 맞춘다 |
| 질의·문서 접두어 | 일부 모델은 질의 앞에 `query: `, 문서 앞에 `passage: ` 같은 접두어를 붙이도록 학습됐다. 빠뜨리면 성능이 떨어진다 |
| 같은 모델 | 질의와 문서를 반드시 같은 모델·같은 버전으로 인코딩한다. 모델을 바꾸면 문서 전체를 다시 인코딩한다 |
| 무엇을 넣나 | 본문만 넣을지, 문서 제목·섹션 제목을 앞에 붙일지에 따라 결과가 달라진다. 제목을 붙이면 맥락이 생긴다 |
| 배치·속도 | 문서 인코딩은 한 번이지만 질의 인코딩은 매 검색마다 한다. 질의 인코딩 지연을 따로 잰다 |
| 풀링 | 모델이 학습한 풀링 방식([CLS] / 평균 / 마지막 토큰)을 그대로 쓴다 (1장) |

### 접두어와 지시문 (instruction)

질문과 문서는 모양이 다르다. 짧은 질문으로 긴 문서를 찾는 것을 **비대칭 검색**, 비슷한 길이의 문장끼리 비교하는 것을 **대칭 검색**이라 한다. 모델은 입력 앞에 붙는 글로 어느 쪽인지 구분한다.

| 방식 | 질의 입력 예 | 문서 입력 예 | 예시 모델 |
| --- | --- | --- | --- |
| 없음 | `환불 기한` | `환불은 7일 이내…` | bge-m3 |
| 접두어 | `query: 환불 기한` | `passage: 환불은 7일 이내…` | multilingual-e5 |
| 지시문 | `Instruct: 질문에 답하는 문서를 찾아라\nQuery: 환불 기한` | 문서는 그대로 | e5-instruct, Qwen3-Embedding 등 LLM 기반 모델 |

- 지시문은 **질의에만** 붙이고 문서에는 붙이지 않는 모델이 많다. 문서 쪽에 붙이면 성능이 떨어질 수 있다. 모델 설명서를 따른다.
- 지시문 내용으로 작업을 바꿀 수 있다(검색, 중복 찾기, 분류). 검색용 문장을 하나 정해 고정하고, 바꾸면 기준선을 다시 잰다. 도메인을 적은 지시문("고객 문의에 답하는 정책 문서를 찾아라")이 나은지는 dev 세트로 비교한다.
- 대칭 작업(비슷한 질문 찾기, 중복 문서 찾기)에 비대칭용 설정을 그대로 쓰면 결과가 나빠진다. 작업마다 설정을 따로 기록한다.

## 4. dense가 잘 틀리는 경우

벡터 하나로 의미를 압축하면서 잃는 정보가 있다. 아래 유형은 골든셋에서 따로 나눠 본다.

| 유형 | 예 | 왜 틀리나 | 보완 |
| --- | --- | --- | --- |
| 부정 | "환불 가능한 경우" ↔ "환불이 불가한 경우" 문서가 매우 가까움 | 단어 대부분이 같고, 부정어 하나의 영향이 작음 | 리랭커(cross-encoder), 생성 단계에서 확인 |
| 숫자·날짜·버전 | "7일 이내" ↔ "30일 이내", "2024년 개정" ↔ "2023년" | 숫자 차이가 학습에서 드물게 구분됨 | BM25(정확 일치), 메타데이터 필터([04-advanced-rag/03-query-transform/02-metadata-filter](../../04-advanced-rag/03-query-transform/02-metadata-filter.md)) |
| 식별자·코드 | `E-4012` ↔ `E-4021` | 서브워드로 쪼개져 비슷한 벡터 | BM25, 정확 조회 라우팅 (위 metadata-filter 노트 5장) |
| 처음 보는 용어·약어 | 사내 약어, 도메인 전문 용어 | 학습 데이터에 없어 뜻을 모름 | BM25 + 사용자 사전, 파인튜닝 ([01-sparse-retrieval/03-learned-sparse](../01-sparse-retrieval/03-learned-sparse.md) 4장 "도메인 전문 용어에 대응하는 방법") |
| 긴 청크 | 여러 주제가 섞인 긴 섹션의 한 문장을 묻는 질문 | 벡터 하나에 평균되어 세부가 묻힘 | 청크 줄이기, 멀티 벡터([02-multi-vector](./02-multi-vector.md)), 부모-자식 청킹([04-advanced-rag/04-chunking](../../04-advanced-rag/04-chunking/README.md)) |
| 주제만 같은 문서 | "환불 절차" 질문에 "환불 정책 개요" 문서 | 주제가 비슷하면 답이 없어도 가까움 | 리랭커 |
| 한영 혼용·교차 언어 | 한국어 질문으로 영어 문서 찾기, "와이파이" 질문과 "Wi-Fi" 문서 | 다국어 모델은 언어가 달라도 가깝게 학습되지만, 한국어로만 추가 학습한 모델은 이 능력이 약해질 수 있음 | 다국어 모델 유지, 질의 번역, BM25 쪽 동의어 사전 |

- dense는 "관련 있어 보이는" 문서를 항상 top-k로 돌려준다. 답이 없는 질문에도 결과가 나오므로, 결과가 있다는 것만으로 답이 있다고 보지 않는다(2장 "점수의 절대값은 믿기 어렵다").
- 이 유형들은 BM25가 강한 곳과 많이 겹친다. 하이브리드가 효과를 보는 이유다.
- 문서에 영어 원문, 영어 용어가 섞여 있으면 골든셋에 한영 혼용 질문을 따로 넣고, 한국어 특화 모델과 다국어 모델을 이 유형에서 따로 비교한다([03-model-selection](./03-model-selection.md) 5장).

## 5. 확인할 점

- 벡터를 저장할 때 모델 이름·버전, 정규화 여부, 접두어 규칙, 입력 구성(제목 포함 여부)을 함께 기록한다. 하나라도 다르면 새 질의 벡터와 저장된 문서 벡터가 맞지 않는다.
- 잘림 비율(최대 길이를 넘은 문서 비율)을 한 번 재 둔다. 비율이 높으면 청크를 나눠야 한다.
- 풀링 방식과 정규화 여부를 직접 구현했다면, `sentence-transformers` 결과와 같은 벡터가 나오는지 문장 몇 개로 비교한다.
