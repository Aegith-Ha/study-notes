# vLLM 기초 (vLLM Basics)

LLM 서빙의 병목인 KV 캐시 메모리와, vLLM이 이를 다루는 방법(PagedAttention, 연속 배칭, 접두어 캐시), 양자화와 API 형식을 정리한다.

- 폴더 요약과 기본 선택은 [README](./README.md) 참고
- 측정 방법은 [02-serving-benchmark](./02-serving-benchmark.md) 참고

## 1. 생성 과정과 KV 캐시

```text
[prefill]  입력 전체를 한 번에 처리 → 첫 토큰       (입력 길이에 비례, 계산이 병목)
[decode]   토큰 하나씩 생성, 앞 토큰들의 K, V 재사용  (메모리 읽기가 병목)
```

- 앞 토큰들의 어텐션 K, V를 저장해 둔 것이 KV 캐시다. 다시 계산하지 않으려고 저장하지만 메모리를 많이 쓴다.
- 동시에 처리할 수 있는 요청 수는 대개 **KV 캐시 메모리**로 정해진다.

## 2. 손계산 예시: KV 캐시 메모리

8B급 모델 가정: 32층, KV 헤드 8개(GQA), 헤드 차원 128, bf16

```text
토큰당 KV = 2 (K, V) × 32 층 × 8 헤드 × 128 차원 × 2 바이트 = 131,072 바이트 = 128 KiB
4,096 토큰 시퀀스 1개 = 4,096 × 128 KiB = 512 MiB
```

24 GB GPU에서

| 가중치 | 가중치 메모리 | KV 캐시에 남는 메모리 (가정) | 4k 시퀀스 동시 수 |
| --- | --- | --- | --- |
| bf16 | 약 16 GB | 약 5 GiB | 5 × 1024 / 512 = 10 |
| 4-bit | 약 4 GB | 약 16 GiB | 16 × 1024 / 512 = 32 |

- 양자화는 가중치를 줄여 KV 캐시 자리를 늘린다. 동시 처리 수가 3배가 되는 것이 속도보다 큰 효과일 수 있다.
- RAG 입력은 검색 문서 때문에 길다. top-k를 늘리면 비용뿐 아니라 동시 처리 수도 줄어든다([04-advanced-rag/06-long-context-vs-rag](../../04-advanced-rag/06-long-context-vs-rag/README.md)).
- KV 헤드 수, 층 수는 모델 설정 파일에서 확인한다. 모델마다 다르다.

## 3. vLLM의 방법

| 방법 | 문제 | 해결 |
| --- | --- | --- |
| PagedAttention | 요청마다 최대 길이만큼 연속 메모리를 미리 잡으면 대부분 낭비 | KV 캐시를 작은 블록으로 나눠 필요한 만큼만 할당 |
| 연속 배칭 (continuous batching) | 배치 전체가 끝나야 다음 요청을 받으면 짧은 요청이 기다림 | 토큰 단계마다 끝난 요청을 빼고 새 요청을 넣음 |
| 접두어 캐시 (prefix caching) | 같은 시스템 프롬프트를 매번 다시 prefill | 같은 앞부분의 KV 블록을 공유 |
| 텐서 병렬 | 모델이 GPU 한 장에 안 들어감 | 여러 GPU에 층을 나눠 계산 |

- 접두어 캐시는 API의 프롬프트 캐싱과 같은 원리다. 고정 부분을 앞에 두는 프롬프트 순서 원칙이 똑같이 적용된다.

## 4. 양자화

| 방식 | 내용 | 확인할 것 |
| --- | --- | --- |
| AWQ, GPTQ | 미리 양자화한 4-bit 가중치 | 품질 저하 (골든셋으로 확인) |
| FP8 | 8-bit 부동소수 (지원 GPU 필요) | GPU 지원 여부 |
| KV 캐시 양자화 | KV 캐시를 8-bit로 | 긴 입력에서 품질 |

- QLoRA 학습의 4-bit(NF4)와 서빙용 4-bit는 목적과 형식이 다르다. 학습한 어댑터를 서빙할 때 어떤 기반 가중치에 붙일지 확인한다([03-lora-qlora](../03-lora-qlora/README.md)).

## 5. API 형식

- vLLM은 OpenAI 호환 API 서버를 제공한다. 앱은 엔드포인트 주소와 모델 이름만 바꿔 API 모델과 자체 서빙 모델을 오갈 수 있다.
- 도구 호출, 구조화 출력 지원 범위는 모델과 버전에 따라 다르다. 에이전트에 쓸 때는 도구 호출 평가 세트로 확인한다([05-agents/02-tool-calling-mcp](../../05-agents/02-tool-calling-mcp/README.md)).
- LoRA 어댑터를 여러 개 올려 요청마다 고르는 기능도 있다(기반 모델 1개 공유).

## 6. 확인할 점

- 최대 길이를 모델 한계보다 작게 잡으면 동시 처리 수가 늘어난다. 실제 입력 길이 분포를 보고 정한다.
- 서빙 엔진과 버전이 바뀌면 같은 모델·같은 설정이어도 출력이 조금 달라질 수 있다. 버전을 기록한다.
