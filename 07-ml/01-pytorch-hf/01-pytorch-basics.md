# PyTorch 기초 (PyTorch Basics)

모델 학습에 필요한 PyTorch의 핵심 개념(텐서, 자동 미분, 학습 루프, device와 dtype)과 GPU 메모리를 미리 계산하는 방법을 정리한다.

- 폴더 요약과 기본 선택은 [README](./README.md) 참고
- Hugging Face 도구는 [02-huggingface](./02-huggingface.md) 참고

## 1. 핵심 개념

| 개념 | 설명 | 자주 하는 실수 |
| --- | --- | --- |
| 텐서 | 다차원 배열. 모양(shape), dtype, device를 가짐 | 모양이 맞지 않는 연산, 다른 device끼리 연산 |
| 자동 미분 | 연산을 기록해 두고 `backward`로 기울기 계산 | 평가 때 기울기 기록을 끄지 않아 메모리 낭비 |
| 모듈 | 파라미터를 가진 층의 묶음 | 학습/평가 모드 전환을 잊음 (드롭아웃 동작이 다름) |
| 옵티마이저 | 기울기로 파라미터를 갱신 | 매 단계 기울기를 0으로 초기화하지 않음 |
| 데이터 로더 | 데이터를 배치로 묶어 공급 | 길이가 다른 문장을 패딩하지 않음 |

## 2. 학습 루프

```text
for epoch:
    for batch in train_loader:
        출력 = 모델(입력)              # 순전파
        손실 = 손실함수(출력, 정답)
        기울기 초기화 → 손실.backward() # 역전파
        옵티마이저.step()              # 파라미터 갱신
    dev 세트로 평가 (학습 모드 끔, 기울기 기록 끔)
    가장 좋은 체크포인트 저장
```

- 평가는 학습에 쓰지 않은 데이터로 한다. 검색 모델이라면 골든셋 dev로 Recall@k를 잰다([03-evals/01-retrieval-metrics](../../03-evals/01-retrieval-metrics/README.md)).
- 손실이 줄어드는 것과 평가 지표가 오르는 것은 다르다. 둘 다 기록한다.

## 3. device와 dtype

| dtype | 바이트 / 값 | 쓰임 |
| --- | --- | --- |
| fp32 | 4 | 기본, 옵티마이저 상태 |
| bf16 | 2 | 학습·추론 (값 범위가 fp32와 같아 안정적) |
| fp16 | 2 | 학습·추론 (범위가 좁아 손실 스케일링 필요) |
| int8 | 1 | 추론 양자화 |
| 4-bit | 0.5 | 추론, QLoRA ([03-lora-qlora](../03-lora-qlora/README.md)) |

- 혼합 정밀도: 계산은 bf16/fp16으로 빠르게, 갱신용 원본 가중치와 옵티마이저 상태는 fp32로 유지한다.

## 4. 손계산 예시: GPU 메모리

### 추론

```text
7B 모델, bf16:  7 × 10⁹ × 2 바이트 = 14 GB  (+ KV 캐시, 활성값)
7B 모델, 4-bit: 7 × 10⁹ × 0.5 바이트 = 3.5 GB
```

### 전체 파인튜닝 (Adam, 혼합 정밀도)

| 항목 | 바이트 / 파라미터 |
| --- | --- |
| bf16 가중치 | 2 |
| bf16 기울기 | 2 |
| fp32 원본 가중치 | 4 |
| Adam 상태 2개 (fp32) | 8 |
| 합계 | 16 |

```text
7B × 16 바이트 = 112 GB  (+ 활성값)
→ 24 GB GPU 한 장으로는 불가. LoRA / QLoRA를 쓰는 이유 (03-lora-qlora)

임베딩 모델 560M (예: bge-m3 규모) × 16 = 약 9 GB  (+ 활성값)
→ 한 장으로 가능. 임베딩 파인튜닝은 전체 학습도 현실적 (02-embedding-finetuning)
```

- 활성값 메모리는 배치 크기와 문장 길이에 비례한다. OOM이 나면 배치를 줄이고 기울기 누적(gradient accumulation)으로 실질 배치 크기를 유지한다.
- 단, 대조 학습은 배치 안의 다른 예를 오답으로 쓰므로 기울기 누적으로 효과가 같아지지 않는다([02-embedding-finetuning/02-loss-and-evaluation](../02-embedding-finetuning/02-loss-and-evaluation.md)).

## 5. 확인할 점

- 계산값과 실측(최대 할당 메모리)을 함께 비교한다. 차이는 대개 활성값과 프레임워크 여유분이다.
- 시드를 고정해도 GPU 연산은 완전히 같은 결과를 내지 않을 수 있다. 비교는 여러 시드의 평균과 편차로 한다.
