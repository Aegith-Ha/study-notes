# 손실과 평가 (Loss and Evaluation)

임베딩 모델의 대조 손실(배치 내 네거티브)이 무엇을 학습하는지, 리랭커 학습은 무엇이 다른지, 파인튜닝 결과를 어떻게 평가하는지 정리한다.

- 폴더 요약, 메인 결정, 결과는 [README](./README.md) 참고
- 학습 데이터는 [01-training-data](./01-training-data.md) 참고

## 1. 배치 내 네거티브 대조 손실

배치에 (질의, 관련 문서) 쌍이 B개 있으면, 각 질의에 대해 자기 문서는 정답, 나머지 B−1개 문서는 오답으로 본다.

```text
점수 = 스케일 × cos(질의, 문서)
손실 = −log( exp(정답 점수) / Σ exp(배치 안 모든 문서 점수) )
```

- 정답 점수가 다른 문서보다 충분히 높으면 손실이 0에 가깝다. 비슷하면 손실이 커지고 둘을 떼어 놓도록 학습한다.
- 배치가 클수록 오답이 많아 학습 신호가 강하다. 그래서 대조 학습은 큰 배치가 유리하다.
- 기울기 누적은 배치 안 오답 수를 늘리지 않는다. 메모리가 부족하면 캐시 방식 손실(예: CachedMultipleNegativesRankingLoss)을 검토한다.

### 손계산 예시

배치 4, 스케일 20, 한 질의의 코사인 유사도

```text
쉬운 경우: 정답 0.80, 오답 0.60 / 0.50 / 0.30
  점수 16, 12, 10, 6
  손실 = log(1 + e^−4 + e^−6 + e^−10) ≈ 0.021

어려운 경우 (하드 네거티브): 정답 0.80, 오답 0.78 / 0.50 / 0.30
  점수 16, 15.6, 10, 6
  손실 = log(1 + e^−0.4 + e^−6 + e^−10) ≈ 0.515
```

읽는 법
- 쉬운 오답만 있으면 손실이 거의 0이라 배울 것이 없다. 하드 네거티브 하나가 손실 대부분을 만든다.
- 그래서 하드 네거티브가 효과적이고, 그만큼 거짓 네거티브가 해롭다([01-training-data](./01-training-data.md) 4장).

## 2. 리랭커 학습

| 항목 | 임베딩 (bi-encoder) | 리랭커 (cross-encoder) |
| --- | --- | --- |
| 입력 | 질의, 문서 따로 | 질의 + 문서 함께 |
| 출력 | 벡터 (유사도는 나중에) | 관련도 점수 |
| 학습 데이터 | 쌍 + 배치 내 네거티브 | 질의당 정답 1 + 하드 네거티브 여러 개 (또는 점수) |
| 바뀌면 | 전체 재색인 | 재색인 없음 |

- 리랭커는 교체 비용이 작아 먼저 파인튜닝해 볼 만하다. 다만 후보 안에 정답이 없으면 리랭커로는 고칠 수 없다([04-advanced-rag/02-reranking/02-candidate-depth](../../04-advanced-rag/02-reranking/02-candidate-depth.md)).

## 3. 평가

| 단계 | 데이터 | 용도 |
| --- | --- | --- |
| 학습 중 | 골든셋 dev | 체크포인트 선택, 하이퍼파라미터 조정 |
| 최종 | 골든셋 test | 한 번만, 결과 표에 기록 |
| 일반 성능 | 일반 한국어 검색 세트 | 도메인 밖 질문에서 나빠지지 않았는지 (망각) |
| 유형별 | user / expert 표현, 학습에서 뺀 조문 | 표현 차이 해소, 일반화 |

- 지표는 기성 모델 기준선과 같은 조건(Flat 인덱스, 같은 k)으로 잰다([02-retrieval-basics/02-dense-retrieval](../../02-retrieval-basics/02-dense-retrieval/README.md)).
- 개선 폭이 작으면 같은 문항 대응 비교로 우연인지 확인한다([03-evals/05-regression-ci/01-gate-design](../../03-evals/05-regression-ci/01-gate-design.md)).
- dense 단독 개선이 하이브리드·리랭커를 거친 최종 결과에서도 남는지 확인한다. 단독으로는 올라도 파이프라인 전체에서는 차이가 사라질 수 있다.

## 4. 확인할 점

- dev로 여러 번 골랐다면 dev 점수는 낙관적이다. 비교는 test 결과로 한다.
- 모델을 바꾸면 질의 인코딩과 문서 인코딩 모두 새 모델로 해야 한다. 섞으면 검색이 무너진다.
