# 학습 데이터 만들기 (Training Data)

임베딩·리랭커 파인튜닝에 쓰는 (질의, 관련 문서) 쌍과 네거티브를 만드는 방법, 그리고 평가 데이터가 섞이지 않게 하는 방법을 정리한다.

- 폴더 요약과 메인 결정은 [README](./README.md) 참고
- 손실과 평가는 [02-loss-and-evaluation](./02-loss-and-evaluation.md) 참고

## 1. 데이터 형태

| 형태 | 구성 | 쓰는 손실 |
| --- | --- | --- |
| 쌍 | (질의, 관련 문서) | 배치 내 네거티브 대조 손실 |
| 삼중쌍 | (질의, 관련 문서, 무관 문서) | 대조 손실, triplet |
| 점수 | (질의, 문서, 관련도 0~1) | 회귀형, 리랭커 |

- 쌍만 있으면 시작할 수 있다. 무관 문서는 배치 안의 다른 문서가 대신한다.

## 2. 쌍을 어디서 얻나

| 출처 | 방법 | 장점 | 위험 |
| --- | --- | --- | --- |
| 합성 질문 | 문서를 LLM에 주고 그 문서로 답할 수 있는 질문 생성 | 대량, 모든 문서 포함 | 문서 표현을 그대로 베낀 질문 (실제 사용자와 다름) |
| FAQ·상담 기록 | 기존 질의와 근거 문서 | 실제 질문 표현 | 양이 적음, 골든셋 출처와 겹칠 수 있음 |
| 운영 로그 | 👍 받은 질의와 인용 문서 | 실제 분포 | 틀린 쌍 섞임, 개인정보 |
| 제목·본문 | 섹션 제목 → 본문 | 자동 | 너무 쉬움 |

- 합성 질문은 사용자 말투로 쓰게 하고(문서 단어를 그대로 쓰지 말라고 지시), 사람이 표본을 검토한다. 질문 생성 방식은 골든셋 생성 방법과 같은 문제를 가진다([03-evals/03-golden-set/00-generation-methods](../../03-evals/03-golden-set/00-generation-methods.md)).

## 3. 골든셋과 분리

| 확인 | 방법 |
| --- | --- |
| 같은 질문 | 골든셋 질문과 정확히 같거나 거의 같은(임베딩 유사도 높은) 학습 질문 제거 |
| 같은 출처 | 골든셋을 만든 질의응답·로그 항목은 학습에 쓰지 않음 |
| 문서 단위 | 일부 문서를 학습에서 빼고 그 문서만 묻는 평가로 일반화 확인 |

- 섞이면 점수가 오르지만 실제 성능은 그대로다. 학습 데이터 버전에 제거 내역을 기록한다.

## 4. 하드 네거티브

배치 내 네거티브는 대부분 너무 쉽다(전혀 다른 주제의 문서). 헷갈리는 오답을 넣으면 모델이 미세한 차이를 배운다.

| 채굴 방법 | 예 |
| --- | --- |
| BM25 상위 결과 중 정답 아닌 것 | 같은 단어를 쓰는 다른 문서 |
| 기성 임베딩 상위 결과 중 정답 아닌 것 | 뜻이 비슷한 다른 문서 |
| 구조상 이웃 | 같은 문서의 인접 섹션, 하위 지침의 대응 섹션 |

### 거짓 네거티브

```text
질의: "해외 배송 상품도 무료 반품이 되나요?"
정답 표시: 반품 정책 3.1
채굴된 네거티브: 해외 배송 안내 2.4 (해외 반품 비용 기준) ← 실제로는 관련 있음
```

- 채굴된 "오답"이 실제로는 관련 문서인 경우가 많다. 정책-세부 지침-FAQ처럼 같은 내용을 여러 문서가 나눠 담는 경우가 많다.
- 대책: 최상위 몇 개는 제외하고 그 아래에서 뽑는다, 리랭커 점수가 높은 것은 제외한다, 표본을 사람이 확인한다.
- 거짓 네거티브로 학습하면 관련 문서를 밀어내도록 배운다. 하드 네거티브를 넣었는데 성능이 떨어지면 먼저 의심한다.

## 5. 확인할 점

- 쌍 수보다 질의 다양성이 중요하다. 같은 문서에서 비슷한 질문 수십 개를 만들면 그 문서에 치우친다.
- 학습 데이터의 질문 유형 분포(단순, 다중 근거, 답 없음)를 기록한다. 답 없음 질문은 임베딩 학습 쌍이 되지 않는다.
