# LoRA (Low-Rank Adaptation)

기존 가중치는 고정하고 작은 행렬 두 개만 학습해 모델을 조정하는 LoRA의 원리, 학습 파라미터 수, 하이퍼파라미터를 정리한다.

- 폴더 요약과 메인 결정은 [README](./README.md) 참고
- 양자화와 적용 판단은 [02-qlora-and-when](./02-qlora-and-when.md) 참고

## 1. 원리

```text
원래:   y = W x                  W: d × d  (고정)
LoRA:   y = W x + (alpha / r) · B A x
                                 A: r × d,  B: d × r  (학습)
                                 r ≪ d  (예: d = 4096, r = 16)
```

- 파인튜닝으로 생기는 가중치 변화는 낮은 랭크로 근사할 수 있다는 가정이다.
- B를 0으로 초기화해 학습 시작 시점에는 원래 모델과 똑같이 동작한다.
- 기존 가중치 W는 기울기·옵티마이저 상태가 필요 없다. 메모리 대부분이 여기서 줄어든다.

## 2. 손계산 예시: 학습 파라미터 수

d = 4096, r = 16인 투영 행렬 하나

```text
전체 W:  4096 × 4096        = 16,777,216
LoRA:    2 × 4096 × 16      =    131,072   → 0.78%
```

7B 모델, 32층, 층마다 4096 × 4096 투영 4개(q, k, v, o)에 적용했다고 단순화하면

```text
LoRA 파라미터 = 4 × 32 × 131,072 = 16,777,216 (약 16.8M) → 7B의 약 0.24%
학습 상태 메모리 = 16.8M × 16 바이트 ≈ 268 MB
(전체 파인튜닝의 112 GB와 비교: 01-pytorch-hf/01-pytorch-basics)
```

- 실제 모델은 k, v 투영이 더 작고(GQA) MLP 층이 더 커서 숫자가 다르다. 실제 값은 학습 도구가 출력하는 학습 파라미터 수로 확인한다.
- 기반 모델 가중치(bf16 14 GB)는 여전히 메모리에 올라간다. 이것까지 줄이는 것이 QLoRA다.

## 3. 하이퍼파라미터

| 항목 | 의미 | 시작값 | 조정 |
| --- | --- | --- | --- |
| r | 랭크, 표현력 | 8~16 | 형식·행동 학습은 작아도 충분, 새 작업이면 키움 |
| alpha | 출력 배율 (alpha / r) | r의 2배 | r을 바꿀 때 비율 유지 |
| 대상 층 | 어디에 붙이나 | 어텐션 + MLP 투영 전체 | 어텐션만이면 파라미터는 적지만 효과도 작을 수 있음 |
| dropout | LoRA 입력 드롭아웃 | 0.05 | 데이터가 적으면 올림 |
| 학습률 | | 전체 파인튜닝보다 큼 (예: 1e-4~2e-4) | 손실이 튀면 낮춤 |

- 하이퍼파라미터 하나씩 바꾸고 dev 결과로 고른다. 여러 개를 동시에 바꾸면 무엇이 효과인지 모른다.

## 4. 병합과 어댑터 교체

| 방식 | 내용 | 장단점 |
| --- | --- | --- |
| 병합 | W' = W + (alpha / r) B A 로 합쳐 하나의 모델로 저장 | 추론 속도 원래와 같음, 어댑터 교체 불가 |
| 어댑터 분리 | 기반 모델 1개 + 작업별 어댑터 여러 개 | 작은 파일로 여러 작업 전환, 서빙 시 지원 필요 ([04-vllm-serving](../04-vllm-serving/README.md)) |

- 어댑터는 학습한 기반 모델 리비전에서만 맞는다. 기반 모델 버전을 함께 기록한다.

## 5. 확인할 점

- 학습 손실이 계속 내려가도 dev 지표는 어느 순간 나빠진다(과적합). 데이터가 적으면 에폭을 짧게 잡는다.
- 대화 템플릿과 정답 부분만 손실에 넣는지(질문·문서 부분 제외) 확인한다. 설정에 따라 결과가 크게 다르다.
