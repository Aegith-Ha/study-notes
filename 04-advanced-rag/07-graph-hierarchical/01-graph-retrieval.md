# 그래프 기반 검색 (Graph Retrieval)

문서나 개체 사이의 연결을 그래프로 만들고, 검색할 때 그 연결을 따라가 관련 문서를 더 가져오는 방법을 정리한다. 가장 가벼운 참조 링크 확장부터 LLM으로 개체·관계를 뽑는 GraphRAG까지 다룬다.

- 폴더 요약과 메인 결정은 [README](./README.md) 참고
- 요약을 여러 단계로 쌓는 방법은 [02-hierarchical-summary](./02-hierarchical-summary.md) 참고

## 1. 왜 그래프인가

일반 검색은 질문과 비슷한 청크를 **하나씩** 찾는다. 답에 필요한 두 번째 문서가 질문과 단어도 뜻도 멀면 상위에 오지 못한다.

```text
질문: "해외 배송 상품을 반품하면 배송비는 누가 내나?"

검색 1위: 반품 정책 3.1 "단순 변심 반품은 고객이 왕복 배송비를 부담한다"   ← 질문과 가까움
놓침:     해외 배송 안내 2.4 "해외 반품 배송비는 실비로 청구한다"            ← "해외"만 겹침

그래프:   반품 정책 3.1 ──(예외 참조)──▶ 해외 배송 안내 2.4
          → 1위를 찾으면 연결된 2.4를 함께 가져온다
```

## 2. 방법 비교

| 방법 | 그래프의 노드와 연결 | 만드는 법 | 색인 비용 | 잘 맞는 질문 |
| --- | --- | --- | --- | --- |
| **참조 링크 확장** | 섹션 → 섹션 (문서 안의 명시적 참조) | 규칙(정규식): "3.1에도 불구하고", "2.4 참조", 하이퍼링크 | 거의 없음 | 참조를 따라가야 하는 질문 |
| 메타데이터 그래프 | 문서 → 문서 (같은 주제, 상위·하위 문서) | 기존 분류·목차 | 낮음 | 정책과 세부 지침처럼 계층이 있는 문서 |
| **GraphRAG (개체·관계 그래프)** | 개체(제품, 절차, 기관) → 개체, 관계마다 근거 청크 | LLM이 청크마다 개체와 관계를 추출 | 높음 (청크마다 LLM 호출) | multi-hop, 전체 요약형 |

- 참조 링크 확장부터 시작한다. 규칙 문서·매뉴얼은 명시적 참조가 많아서 LLM 없이도 효과를 볼 수 있다.

## 3. 참조 링크 확장

```text
1. 색인할 때: 섹션마다 본문 속 참조를 추출해 (출발 섹션 → 참조된 섹션) 목록을 저장
2. 검색할 때: 일반 검색 top-k를 얻는다
3. top-k의 각 섹션이 참조하는 섹션을 1단계까지 덧붙인다 (중복 제거)
4. 덧붙인 섹션은 원래 결과 뒤에 둔다 (또는 리랭커로 다시 정렬)
```

- **확장은 1단계까지만** 한다. 2단계 이상 따라가면 컨텍스트가 빠르게 불어난다.
- 참조된 섹션 수만큼 컨텍스트 토큰이 늘어난다. 같은 토큰 예산으로 비교한다([03-evals/01-retrieval-metrics](../../03-evals/01-retrieval-metrics/01-reference-based.md) 3.7).
- 양방향을 다 볼지 정한다. "A가 B를 참조"일 때 B를 찾았으면 A도 가져올지(역참조)는 문서 성격에 따라 다르다. 예외 조항은 역참조가 유용하다.

## 4. GraphRAG

### 4.1 색인

```text
청크 ──▶ [LLM: 개체·관계 추출] ──▶ 개체 그래프 (관계마다 출처 청크 기록)
                                        │
                                        ▼
                         [커뮤니티 탐지: 촘촘히 연결된 개체 묶음]
                                        │
                                        ▼
                         [LLM: 커뮤니티마다 요약 작성]
```

- 같은 개체가 다른 이름으로 나오면 합쳐야 한다("환불 정책" = "환불규정"). 이 정리가 그래프 품질을 크게 좌우한다.

### 4.2 검색 방식

| 방식 | 하는 일 | 맞는 질문 |
| --- | --- | --- |
| local | 질문 속 개체를 찾고, 그 개체와 이웃 개체의 관계·출처 청크를 모음 | 특정 대상에 대한 multi-hop 질문 |
| global | 모든 커뮤니티 요약에 질문을 던져 부분 답을 만들고 합침(map-reduce) | "주요 쟁점을 정리해 줘" 같은 전체 요약형 |

- global 검색은 커뮤니티 수만큼 LLM을 호출하므로 질의당 비용이 크다. 전체 요약형 질문이 드물면 쓰지 않는다.

### 4.3 비용 손계산

문서 청크 2,000개, 청크당 추출 호출 1회(입력 600토큰, 출력 300토큰), 커뮤니티 150개 요약(입력 2,000토큰, 출력 400토큰)

```text
추출:    2,000 × (600 + 300) = 1,800,000 토큰
요약:      150 × (2,000 + 400) =   360,000 토큰
합계:                            2,160,000 토큰 (색인 1회)
```

- 일반 임베딩 색인은 LLM 호출이 없다. 문서가 바뀔 때마다 추출과 요약을 다시 해야 하므로, 자주 바뀌는 문서에서는 갱신 비용이 더 문제다.

## 5. 평가

| 질문 유형 | 지표 | 이유 |
| --- | --- | --- |
| multi-hop | Set Recall@k (필요한 문서 조합이 다 들어왔나) | 문서별 Recall은 한쪽만 가져와도 점수가 나옴 |
| 단일 근거 | 기존 Recall@5, MRR | 확장한 문서가 원래 정답을 밀어내지 않았는지 확인 |
| 전체 요약형 | pairwise judge (포괄성, 다양성), Faithfulness | 정답 답변을 만들기 어려움 |
| 공통 | 질의당 컨텍스트 토큰, 색인 비용 | 같은 비용으로 비교 |

- 질의 분해([03-query-transform](../03-query-transform/README.md))와 반드시 비교한다. 질의 분해는 색인을 바꾸지 않고 multi-hop 질문을 일부 해결한다.
- 골든셋의 다중 근거 질문에 `evidence_sets`가 있어야 Set Recall을 잴 수 있다([03-golden-set](../../03-evals/03-golden-set/README.md) 데이터 형식).

## 6. 확인할 점

- 그래프는 문서가 바뀌면 함께 바뀌어야 한다. 참조 목록과 개체 그래프에도 문서 버전(`doc_version`)을 붙인다.
- 개체·관계 추출도 LLM 판정이다. 표본을 사람이 보고 빠진 관계와 잘못된 관계 비율을 잰다([04-llm-judge](../../03-evals/04-llm-judge/README.md)와 같은 방식).
- 답변의 인용은 그래프 노드나 커뮤니티 요약이 아니라 원문 청크로 단다.
