# 비용과 지연 계산 (Cost and Latency)

긴 컨텍스트와 RAG의 비용·지연을 질의 단위로 계산하는 방법을 정리한다. 실제 단가는 모델과 시점마다 다르므로 토큰 수와 상대 비용으로 정리하고, 실제 금액은 그때의 단가로 따로 계산한다.

- 폴더 요약과 메인 결정은 [README](./README.md) 참고
- 실험 설계는 [01-experiment-design](./01-experiment-design.md) 참고

## 1. 질의당 비용

```text
질의당 비용 = 입력 토큰 × 입력 단가 + 출력 토큰 × 출력 단가
            (+ RAG: 검색·임베딩·리랭크 비용, 보통 LLM 비용보다 훨씬 작음)
```

- 출력 토큰(답변 길이)은 설정이 달라도 비슷하다. 차이는 거의 **입력 토큰**에서 난다.

## 2. 손계산 예시

가정: 섹션 1개 평균 400토큰, 프롬프트·질문 300토큰, 문서 하나 120개 섹션

| 설정 | 입력 토큰 계산 | 입력 토큰 | RAG 대비 |
| --- | --- | --- | --- |
| R. RAG top-5 | 5 × 400 + 300 | 2,300 | 1.0배 |
| RL. RAG top-50 | 50 × 400 + 300 | 20,300 | 8.8배 |
| L. 문서 통째 | 120 × 400 + 300 | 48,300 | 21.0배 |

### 프롬프트 캐싱을 쓰면

같은 문서를 여러 질문이 반복해서 쓰면, 문서 부분을 캐시해서 싸게 다시 읽을 수 있다.

```text
가정: 캐시에서 읽는 입력은 일반 입력 단가의 10%
L + 캐시: 48,000 × 0.1 + 300 = 5,100 (일반 입력 환산) → RAG 대비 약 2.2배
```

- 캐시는 같은 앞부분(문서 본문)을 **그대로** 재사용할 때만 맞는다. 질문을 앞에 두면 캐시가 깨진다. 문서 본문을 앞에, 질문을 뒤에 둔다.
- 처음 캐시에 쓰는 요청은 일반 단가보다 비쌀 수 있다. 같은 문서를 쓰는 질문이 적으면 효과가 작다.
- 캐싱 자체는 [06-llmops/02-cost-optimization](../../06-llmops/02-cost-optimization/01-caching.md)에서 다룬다.

## 3. 지연

| 구간 | 영향 요인 | 긴 컨텍스트에서 |
| --- | --- | --- |
| 검색 | 검색기, 리랭커 | 없음 (문서 선택만) |
| 첫 토큰까지 시간 | **입력 토큰 수** (입력 처리) | 크게 늘어남 |
| 생성 | 출력 토큰 수 | 비슷함 |

- RAG는 검색 단계가 추가되지만 입력이 짧아 첫 토큰이 빨리 나온다. 긴 컨텍스트는 검색이 없지만 입력 처리에 시간이 든다.
- 캐시를 쓰면 첫 토큰까지 시간도 줄어든다.
- p50과 p95를 함께 본다. 긴 문서에서 p95가 크게 늘어날 수 있다.

## 4. 판단 기준

| 지표 | 계산 |
| --- | --- |
| 질의당 비용 | 위 공식 |
| 정확도당 비용 | 질의당 비용 / Answer Correctness |
| 추가 정확도의 비용 | (L 비용 − R 비용) / (L 정확도 − R 정확도) → 정확도 1%p를 올리는 데 드는 추가 비용 |

- 예: RAG 대비 비용이 21배인데 정확도가 2%p만 오르면, 같은 비용으로 RAG 쪽 개선(하이브리드, 리랭커)을 하는 편이 낫다.
- 반대로 다중 근거 질문처럼 RAG가 구조적으로 약한 유형에서만 긴 컨텍스트로 보내는 **라우팅**도 선택지다. 질문 유형별 결과를 따로 본다.

## 5. 확인할 점

- 토큰 수는 모델의 토크나이저로 센다. 같은 글이라도 모델마다 토큰 수가 다르다.
- 실제 단가는 실험 날짜와 함께 남긴다. 노트의 상대 비용은 단가가 바뀌어도 유지된다.
