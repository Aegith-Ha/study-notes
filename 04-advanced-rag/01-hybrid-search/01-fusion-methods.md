# 결과 합치기 방법 (Fusion Methods)

BM25와 dense 검색 결과를 하나의 순위로 합치는 방법을 정리한다. 두 검색기는 점수의 범위와 의미가 달라서 그냥 더할 수 없다.

- 폴더 요약과 메인 결정은 [README](./README.md) 참고
- 가중치 조정과 결과 분석은 [02-tuning-and-analysis](./02-tuning-and-analysis.md) 참고

## 1. 왜 그냥 더하면 안 되나

| 검색기 | 점수 범위 | 의미 |
| --- | --- | --- |
| BM25 | 0 ~ 수십 (상한 없음, 질의마다 다름) | 단어 겹침의 양 |
| dense (코사인) | 대략 0.2 ~ 0.9 | 의미 벡터의 방향 유사도 |

BM25 12점과 코사인 0.8을 더하면 BM25가 결과를 거의 다 정한다. 그래서 **점수를 맞추거나(정규화), 점수 대신 순위를 쓴다(RRF).**

## 2. 방법

| 방법 | 계산 | 장점 | 단점 |
| --- | --- | --- | --- |
| 가중합 (정규화 후) | `α × norm(BM25) + (1 − α) × norm(dense)` | 점수 차이의 크기를 반영 | 정규화 방식과 α에 민감 |
| RRF (Reciprocal Rank Fusion) | `Σ 1 / (k + rank)`, 보통 k = 60 | 정규화 불필요, 튜닝할 것이 거의 없음 | 점수 차이의 크기를 버림 |

정규화 방식

| 방식 | 계산 | 주의 |
| --- | --- | --- |
| min-max | `(s − min) / (max − min)` (질의별, 검색기별) | 각 목록의 꼴찌가 0이 됨 |
| z-score | `(s − 평균) / 표준편차` | 결과 수가 적으면 불안정 |

## 3. 손계산 예시

각 검색기의 top-3 결과

| 순위 | BM25 (점수) | dense (코사인) |
| --- | --- | --- |
| 1 | d1 (12.0) | d4 (0.82) |
| 2 | d2 (9.0) | d3 (0.80) |
| 3 | d3 (3.0) | d1 (0.60) |

### 3.1 min-max 정규화 + 가중합

```text
BM25 정규화:  d1 = (12 − 3) / 9 = 1.000, d2 = (9 − 3) / 9 = 0.667, d3 = 0.000
dense 정규화: d4 = 1.000, d3 = (0.80 − 0.60) / 0.22 = 0.909, d1 = 0.000
목록에 없는 문서는 0
```

| 문서 | α = 0.5 | α = 0.3 (dense 쪽 가중) |
| --- | --- | --- |
| d1 | 0.5 × 1.000 + 0.5 × 0.000 = **0.500** | 0.300 |
| d2 | 0.5 × 0.667 = 0.333 | 0.200 |
| d3 | 0.5 × 0.000 + 0.5 × 0.909 = 0.455 | 0.636 |
| d4 | 0.5 × 1.000 = **0.500** | **0.700** |
| 순위 | d1 = d4, d3, d2 | d4, d3, d1, d2 |

### 3.2 RRF (k = 60)

| 문서 | 계산 | 점수 | 순위 |
| --- | --- | --- | --- |
| d1 | 1/(60+1) + 1/(60+3) | 0.03227 | 1 |
| d3 | 1/(60+3) + 1/(60+2) | 0.03200 | 2 |
| d4 | 1/(60+1) | 0.01639 | 3 |
| d2 | 1/(60+2) | 0.01613 | 4 |

읽는 법
- **min-max의 함정**: d1은 BM25 1위이고 dense에서도 3위로 나왔는데, dense 목록의 꼴찌라 dense 점수가 0이 됐다. d3도 BM25 꼴찌라 BM25 점수가 0이다. 정규화가 "목록에 들어왔다"는 정보를 지운다.
- **α에 민감**: α를 0.5에서 0.3으로 바꾸니 1위가 d1에서 d4로 바뀌었다.
- **RRF**: 두 목록에 모두 나온 d1, d3이 위로 온다. "두 검색기가 모두 찾은 문서"를 우대하는 효과가 있다.
- 그래서 튜닝 데이터가 적을 때는 RRF로 시작하는 것이 안전하다.

## 4. 합치기 전 후보 수

- 각 검색기에서 몇 개를 가져와 합칠지(N)도 정해야 한다. 최종 top-5를 만들더라도 각 검색기에서 top-20~50을 가져와 합친다.
- N이 너무 작으면 한쪽 검색기의 6위 문서가 다른 쪽 1위여도 합쳐지지 않는다.
- N을 골든셋 Pooling 깊이(20)보다 크게 잡으면 판정 안 된 문서가 섞일 수 있다. 최종 평가 k(5)가 Pooling 깊이 안이면 평가에는 문제가 없다([02-pooling](../../03-evals/03-golden-set/02-pooling.md) 4장).

## 5. 확인할 점

- 정규화는 질의별로 한다. 전체 질의의 점수를 한꺼번에 정규화하면 질의마다 다른 BM25 점수 범위가 섞인다.
- 같은 문서의 여러 청크가 각 목록에 있으면, 합치기 전에 문서 단위로 중복을 정리할지 정한다(평가의 청크 → 문서 매핑 규칙과 맞춘다).
