# cross-encoder 리랭커 (Cross-encoder Reranker)

1차 검색이 가져온 후보를 더 정확한 모델로 다시 정렬하는 리랭커의 원리와 종류, 비용을 정리한다. 기본 RAG 실패 유형 중 F3(정답이 top-20 안에는 있는데 top-5 밖)을 고친다.

- 폴더 요약, 메인 결정, 결과는 [README](./README.md) 참고
- 1차 후보 수 정하기는 [02-candidate-depth](./02-candidate-depth.md) 참고

## 1. bi-encoder와 cross-encoder

```text
bi-encoder (1차 검색)
  질문 ──▶ [인코더] ──▶ 벡터 q
  문서 ──▶ [인코더] ──▶ 벡터 d      (미리 계산)      점수 = q · d

cross-encoder (리랭커)
  [질문 + 문서] ──▶ [인코더] ──▶ 관련성 점수        (질문마다 문서마다 새로 계산)
```

| 항목 | bi-encoder | cross-encoder |
| --- | --- | --- |
| 질문과 문서를 보는 방식 | 따로 | **함께** (단어끼리 서로 참조) |
| 정확도 | 중간 | 높음 |
| 문서 미리 계산 | 가능 | 불가능 |
| 속도 | 수백만 문서에서도 빠름 | 후보 수에 비례해 느림 |
| 쓰는 곳 | 1차 검색 (수백만 → 수십) | 2차 정렬 (수십 → 5) |

- 그래서 **2단계 검색**을 쓴다. 1차 검색기가 넓게 가져오고, 리랭커가 그중 위쪽을 정한다.

## 2. 리랭커 종류

| 종류 | 방식 | 장점 | 단점 |
| --- | --- | --- | --- |
| cross-encoder 모델 | 질문·문서 쌍마다 점수 | 빠르고 로컬 실행 가능 | 한국어·도메인 성능 확인 필요 |
| LLM 리랭커 (pointwise) | LLM이 쌍마다 관련성 점수 | 지시문으로 기준을 줄 수 있음 | 비용·지연 큼 |
| LLM 리랭커 (listwise) | LLM에 후보 목록을 주고 순서를 정하게 함 | 문서끼리 비교 가능 | 긴 입력, 앞쪽 후보 쏠림 |

- 기본은 다국어 cross-encoder 모델(예: `bge-reranker-v2-m3` 계열)로 시작하고, LLM 리랭커는 비용을 감당할 수 있을 때 비교한다.
- LLM 리랭커는 사실상 LLM judge의 청크 관련성 판정과 같은 일을 한다. 판정 기준 문장을 골든셋 기준과 맞추면 결과를 해석하기 쉽다([판정 기준](../../03-evals/03-golden-set/README.md)).

## 3. 비용과 지연

```text
리랭크 지연 ≈ 후보 수 N × 쌍당 처리 시간 (배치로 줄일 수 있음)
```

예시 가정: 쌍당 4ms

| 후보 수 N | 리랭크 지연 |
| --- | --- |
| 20 | 80ms |
| 50 | 200ms |
| 100 | 400ms |

- 실제 값은 모델 크기, 문서 길이, 하드웨어, 배치 크기에 따라 크게 다르다. 직접 재서 결과 표에 기록한다.
- 지연은 회귀 테스트의 품질 외 기준(p95 지연)에 걸린다([05-regression-ci](../../03-evals/05-regression-ci/01-gate-design.md) 6장).

## 4. 입력 구성

| 항목 | 주의 |
| --- | --- |
| 최대 길이 | 문서가 길면 잘린다. 조문 뒷부분 단서 조항이 잘리지 않는지 확인 |
| 문서 앞 정보 | 법령명·조문 제목을 본문 앞에 붙이면 맥락이 생긴다 |
| 점수 의미 | 리랭커 점수는 순위용이다. "0.7 이상이면 관련" 같은 절대 기준으로 바로 쓰지 않는다 |

- 리랭커 점수로 "관련 없는 문서를 잘라내기"를 하려면 골든셋으로 임계값을 따로 정해야 한다. 기본은 점수와 무관하게 top-5를 넘긴다.

## 5. 확인할 점

- 리랭커는 1차 후보에 없는 문서를 살릴 수 없다. 리랭커 효과를 볼 때는 1차 Recall@N을 함께 기록한다.
- 리랭커가 바뀌어도 1차 검색 결과는 같아야 한다. 1차 검색 결과를 캐시해 두면 리랭커 비교가 빠르다.
