# 1차 후보 수 정하기 (Candidate Depth)

리랭커 앞단에서 몇 개(N)를 가져올지 정하는 방법과, 리랭커 효과를 평가하는 방법을 정리한다. N은 정확도의 상한과 지연을 동시에 정한다.

- 폴더 요약과 기본 선택은 [README](./README.md) 참고
- 리랭커 원리와 비용은 [01-cross-encoder](./01-cross-encoder.md) 참고

## 1. N이 정하는 것

```text
1차 검색 top-N ──▶ 리랭커 ──▶ top-5 ──▶ LLM

최종 Recall@5 ≤ 1차 Recall@N       (1차에서 놓친 정답은 리랭커가 살릴 수 없다)
```

| N | 1차 Recall@N (상한) | 리랭크 지연 | 리랭커가 헷갈릴 후보 |
| --- | --- | --- | --- |
| 작음 (20) | 낮음 | 짧음 | 적음 |
| 큼 (100) | 높음 | 김 | 많음 |

- N을 늘리면 상한은 오르지만, 비슷해 보이는 오답 후보도 늘어 리랭커가 실수할 기회도 늘어난다. 그래서 N을 키운다고 최종 점수가 계속 오르지는 않는다.

## 2. 손계산 예시: 상한과 실제

dev 세트 50건, 정답 1개씩인 질의라고 가정

| 설정 | 1차 Recall@N | 최종 Recall@5 | 리랭커가 살린 비율 |
| --- | --- | --- | --- |
| 리랭커 없음 (1차 top-5) | - | 0.70 (35건) | - |
| N = 20 + 리랭커 | 0.88 (44건) | 0.82 (41건) | (41 − 35) / (44 − 35) = 6 / 9 = 0.67 |
| N = 50 + 리랭커 | 0.94 (47건) | 0.84 (42건) | (42 − 35) / (47 − 35) = 7 / 12 = 0.58 |

읽는 법
- "리랭커가 살린 비율"은 1차 top-5 밖이지만 top-N 안에 있던 정답 중 리랭커가 top-5로 올린 비율이다.
- N을 20에서 50으로 늘리면 상한은 0.88 → 0.94로 오르지만 최종 점수는 0.82 → 0.84로 조금만 오른다. 늘어난 지연(예: 80ms → 200ms)과 비교해서 정한다.
- 위 수치는 설명용 가정이다. 실제 값은 직접 재서 확인한다.

## 3. Pooling 깊이와의 관계

- 골든셋 Pooling 깊이는 20이다([03-golden-set](../../03-evals/03-golden-set/README.md) 사양).
- 1차 Recall@50은 21~50위 정답이 미판정이라 **낮게 나온다.** 참고용으로 보고 Judged@50을 함께 기록한다.
- 최종 Recall@5는 리랭커가 21~50위의 **미판정 문서**를 top-5로 올리면 낮게 나올 수 있다. 리랭커 결과 top-5의 Judged@5를 확인하고, 떨어지면 해당 문서를 추가 판정한다([04-update-loop](../../03-evals/03-golden-set/04-update-loop.md)).

## 4. 리랭커 효과 평가

| 지표 | 보는 것 |
| --- | --- |
| 최종 Recall@5 | LLM에 정답이 들어가는 비율 (가장 중요) |
| MRR, nDCG@5 | 정답이 얼마나 위로 왔나 |
| 리랭커가 살린 비율 | 리랭커 자체의 능력 (1차 검색과 분리) |
| 리랭커가 밀어낸 질의 | 1차 top-5 안에 있던 정답이 리랭커 후 밖으로 밀린 질의 수 |
| Judged@5 | 미판정 문서가 위로 올라왔는지 |
| p95 지연 | 비용 |

- "밀어낸 질의"가 0이 아니면 리랭커가 특정 유형(예: 제품 코드 질문)에서 약한지 본다. 이런 질의는 BM25가 1위로 찾던 경우가 많다.

### 4.1 리랭커가 정답을 밀어낼 때

| 방법 | 방식 | 맞는 경우 |
| --- | --- | --- |
| 1차 순위와 섞기 | 리랭커 순위와 1차 순위를 RRF 등으로 다시 합침 (예: 리랭커 0.7, 1차 0.3) | 리랭커가 대체로 낫지만 가끔 1차의 확실한 정답을 밀어낼 때 |
| 상위 보호 | 식별자가 정확히 일치하는 1차 1위 문서는 리랭크와 상관없이 top-5에 남김 | 제품 코드, 문서 번호 질문 |
| 정확 조회 라우팅 | 식별자 질문은 리랭커 앞단에서 DB 조회로 따로 처리 ([03-query-transform/02-metadata-filter](../03-query-transform/02-metadata-filter.md) 5장) | 식별자를 규칙으로 뽑을 수 있을 때 |
| 리랭커 교체·추가 학습 | 약한 유형의 질문-문서 쌍으로 학습 | 같은 유형에서 계속 밀어낼 때 |

- 섞는 비율도 레버다. dev 세트에서 "살린 질의"와 "밀어낸 질의"를 같이 세어 고른다. 밀어낸 질의를 0으로 만들려다 살린 질의까지 줄면 의미가 없다.
- 섞기 결과는 하이브리드와 같은 방식으로 계산한다([01-hybrid-search/01-fusion-methods](../01-hybrid-search/01-fusion-methods.md) 3.3 가중 RRF).

## 5. 다양성을 고려한 재정렬 (MMR)

리랭커는 질문과의 관련성만 보므로, 내용이 거의 같은 청크 여러 개(같은 섹션의 앞뒤 청크, 중복 문서)를 모두 위로 올릴 수 있다. 그러면 답에 필요한 다른 근거가 top-5에 들어갈 자리가 없다(실패 유형 F11, [02-failure-modes](../../02-retrieval-basics/04-naive-rag/02-failure-modes.md)).

MMR(Maximal Marginal Relevance)은 이미 고른 것과 비슷한 후보에 벌점을 준다.

```text
다음에 고를 후보 = argmax [ λ × 관련성(후보) − (1 − λ) × max 유사도(후보, 이미 고른 것) ]
λ = 1이면 관련성만 (리랭커 순서 그대로), λ가 작을수록 다양성 중시
```

손계산 (λ = 0.7, top-3 고르기)

| 후보 | 리랭커 관련성 | A와 유사도 | 메모 |
| --- | --- | --- | --- |
| A | 0.95 | - | 환불 기한 섹션 |
| B | 0.93 | 0.95 | A와 같은 섹션의 다음 청크 |
| C | 0.80 | 0.30 | 배송비 부담 섹션 |
| D | 0.70 | 0.20 | 환불 예외 섹션 |

```text
1번째: A (관련성 최고)
2번째: B = 0.7 × 0.93 − 0.3 × 0.95 = 0.366
       C = 0.7 × 0.80 − 0.3 × 0.30 = 0.470   ← 선택
       D = 0.7 × 0.70 − 0.3 × 0.20 = 0.430
3번째: B = 0.366 (A와 유사도 0.95가 그대로 벌점)
       D = 0.7 × 0.70 − 0.3 × max(0.20, C와 0.25) = 0.415   ← 선택
결과:  리랭커만 → A, B, C   /   MMR → A, C, D
```

- "환불 기한과 배송비 부담 주체는?" 같은 다중 근거 질문에서 MMR 쪽이 두 근거를 모두 담는다. 단일 근거 질문에서는 B가 A의 뒷부분이라 오히려 B가 필요했을 수도 있다.
- 그래서 λ는 dev 세트에서 질문 유형별로 본다. 다중 근거 질문의 조합 충족률(Set Recall)과 단일 근거 질문의 Recall@5를 함께 본다([03-evals/01-retrieval-metrics/01-reference-based](../../03-evals/01-retrieval-metrics/01-reference-based.md) 3.6).
- 유사도는 임베딩 코사인을 주로 쓴다. 같은 문서의 청크끼리만 벌점을 주는 단순 규칙(문서당 최대 2개)으로 시작해도 된다.

## 6. 확인할 점

- 리랭커 비교 때 1차 검색 설정(하이브리드 여부, N)을 고정한다. 둘을 함께 바꾸면 어느 쪽 효과인지 알 수 없다.
- 생성 쪽 효과도 본다. 정답이 1위로 오면 LLM이 더 잘 쓰는 경향이 있어 Recall@5가 같아도 Answer Correctness가 오를 수 있다.
