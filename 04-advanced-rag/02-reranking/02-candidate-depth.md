# 1차 후보 수 정하기 (Candidate Depth)

리랭커 앞단에서 몇 개(N)를 가져올지 정하는 방법과, 리랭커 효과를 평가하는 방법을 정리한다. N은 정확도의 상한과 지연을 동시에 정한다.

- 폴더 요약과 메인 결정은 [README](./README.md) 참고
- 리랭커 원리와 비용은 [01-cross-encoder](./01-cross-encoder.md) 참고

## 1. N이 정하는 것

```text
1차 검색 top-N ──▶ 리랭커 ──▶ top-5 ──▶ LLM

최종 Recall@5 ≤ 1차 Recall@N       (1차에서 놓친 정답은 리랭커가 살릴 수 없다)
```

| N | 1차 Recall@N (상한) | 리랭크 지연 | 리랭커가 헷갈릴 후보 |
| --- | --- | --- | --- |
| 작음 (20) | 낮음 | 짧음 | 적음 |
| 큼 (100) | 높음 | 김 | 많음 |

- N을 늘리면 상한은 오르지만, 비슷해 보이는 오답 후보도 늘어 리랭커가 실수할 기회도 늘어난다. 그래서 N을 키운다고 최종 점수가 계속 오르지는 않는다.

## 2. 손계산 예시: 상한과 실제

dev 세트 50건, 정답 1개씩인 질의라고 가정

| 설정 | 1차 Recall@N | 최종 Recall@5 | 리랭커가 살린 비율 |
| --- | --- | --- | --- |
| 리랭커 없음 (1차 top-5) | - | 0.70 (35건) | - |
| N = 20 + 리랭커 | 0.88 (44건) | 0.82 (41건) | (41 − 35) / (44 − 35) = 6 / 9 = 0.67 |
| N = 50 + 리랭커 | 0.94 (47건) | 0.84 (42건) | (42 − 35) / (47 − 35) = 7 / 12 = 0.58 |

읽는 법
- "리랭커가 살린 비율"은 1차 top-5 밖이지만 top-N 안에 있던 정답 중 리랭커가 top-5로 올린 비율이다.
- N을 20에서 50으로 늘리면 상한은 0.88 → 0.94로 오르지만 최종 점수는 0.82 → 0.84로 조금만 오른다. 늘어난 지연(예: 80ms → 200ms)과 비교해서 정한다.
- 위 수치는 설명용 가정이다. 실제 값은 직접 재서 확인한다.

## 3. Pooling 깊이와의 관계

- 골든셋 Pooling 깊이는 20이다([03-golden-set](../../03-evals/03-golden-set/README.md) 사양).
- 1차 Recall@50은 21~50위 정답이 미판정이라 **낮게 나온다.** 참고용으로 보고 Judged@50을 함께 기록한다.
- 최종 Recall@5는 리랭커가 21~50위의 **미판정 문서**를 top-5로 올리면 낮게 나올 수 있다. 리랭커 결과 top-5의 Judged@5를 확인하고, 떨어지면 해당 문서를 추가 판정한다([03-update-loop](../../03-evals/03-golden-set/03-update-loop.md)).

## 4. 리랭커 효과 평가

| 지표 | 보는 것 |
| --- | --- |
| 최종 Recall@5 | LLM에 정답이 들어가는 비율 (가장 중요) |
| MRR, nDCG@5 | 정답이 얼마나 위로 왔나 |
| 리랭커가 살린 비율 | 리랭커 자체의 능력 (1차 검색과 분리) |
| 리랭커가 밀어낸 질의 | 1차 top-5 안에 있던 정답이 리랭커 후 밖으로 밀린 질의 수 |
| Judged@5 | 미판정 문서가 위로 올라왔는지 |
| p95 지연 | 비용 |

- "밀어낸 질의"가 0이 아니면 리랭커가 특정 유형(예: 제품 코드 질문)에서 약한지 본다. 이런 질의는 BM25가 1위로 찾던 경우가 많다.

## 5. 확인할 점

- 리랭커 비교 때 1차 검색 설정(하이브리드 여부, N)을 고정한다. 둘을 함께 바꾸면 어느 쪽 효과인지 알 수 없다.
- 생성 쪽 효과도 본다. 정답이 1위로 오면 LLM이 더 잘 쓰는 경향이 있어 Recall@5가 같아도 Answer Correctness가 오를 수 있다.
