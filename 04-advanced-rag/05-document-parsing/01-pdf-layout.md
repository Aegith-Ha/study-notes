# PDF와 레이아웃 파싱 (PDF Layout Parsing)

PDF·스캔 문서에서 텍스트를 뽑을 때 생기는 문제(읽기 순서, 머리말·꼬리말, 줄바꿈, 스캔 이미지)와 대응을 정리한다. 기본 RAG 실패 유형 중 F7(파싱 손실)을 고친다.

- 폴더 요약과 메인 결정은 [README](./README.md) 참고
- 표와 이미지 처리는 [02-tables-images](./02-tables-images.md) 참고

## 1. 왜 파싱이 검색 품질을 정하나

```text
원본 PDF ──▶ [파싱] ──▶ 텍스트 ──▶ 청킹 ──▶ 색인 ──▶ 검색 ──▶ 생성
                 ↑
          여기서 깨진 내용은 뒤의 어떤 기법으로도 되살릴 수 없다
```

- 검색·생성 지표가 특정 문서 유형(PDF 첨부, 스캔본)에서만 낮으면 파싱을 먼저 의심한다.

## 2. 자주 생기는 문제

| 문제 | 예 | 결과 | 대응 |
| --- | --- | --- | --- |
| 읽기 순서 | 2단 편집 문서가 왼쪽·오른쪽 줄이 섞여 나옴 | 문장이 뒤섞여 의미 손실 | 레이아웃 분석 기반 추출기 |
| 머리말·꼬리말 | 매 쪽마다 "OO공단 내부 규정 - 3 -" 반복 | 모든 청크에 같은 잡음, BM25 점수 왜곡 | 반복 줄 제거 |
| 줄바꿈 | 한 문장이 쪽 끝에서 끊겨 다른 청크로 | 문장 분리 | 쪽 경계 이어 붙이기 |
| 하이픈·공백 | "재설-\n정", "재 설 정" | 단어가 안 겹침 | 정규화 |
| 스캔 이미지 | 글자가 이미지로만 있음 | 텍스트 0 | OCR |
| 각주·주석 | 본문 중간에 각주 텍스트 끼어듦 | 문장 오염 | 각주 영역 분리 |

## 3. 도구 유형

| 유형 | 방식 | 맞는 문서 |
| --- | --- | --- |
| 텍스트 레이어 추출 | PDF 안의 텍스트를 그대로 꺼냄 | 디지털로 만든 단순 문서 |
| 레이아웃 분석 | 쪽 이미지에서 제목·문단·표·그림 영역을 먼저 찾고 순서대로 추출 | 다단 편집, 표가 많은 문서 |
| OCR | 이미지에서 글자 인식 | 스캔본 |
| 멀티모달 LLM | 쪽 이미지를 보고 구조화된 텍스트로 변환 | 복잡한 레이아웃, 비용 감당 가능 시 |

- 법령 본문은 공식 API나 구조화된 원문(XML 등)이 있으면 PDF 파싱보다 그쪽이 정확하다. PDF 파싱은 별표, 서식, 첨부 문서처럼 원문 구조가 없는 경우에 쓴다.

## 4. 파싱 품질 재기

| 방법 | 내용 |
| --- | --- |
| 표본 육안 검수 | 문서 유형별 몇 쪽을 원본과 나란히 비교 |
| 글자 오류율 (CER) | 사람이 옮겨 적은 정답 텍스트와 비교 (스캔본, OCR) |
| 검색 지표 나눠 보기 | 근거가 PDF·스캔본에 있는 질문만 모아 Recall@5 비교 |
| 빈 결과 비율 | 텍스트가 거의 안 나온 쪽 비율 (OCR 누락 탐지) |

- 최종 판단은 검색 지표 나눠 보기로 한다. 육안 검수는 원인 찾기용이다.
- 골든셋 질문에 근거 문서의 형식(본문 / 별표 / 첨부 PDF / 스캔)을 태그해 두면 나눠 보기가 쉽다.

## 5. 확인할 점

- 파서나 설정을 바꾸면 그 문서들의 청크, 색인, 벡터를 모두 다시 만든다. 파서 이름과 버전을 문서 집합 버전에 포함한다.
- 파싱 결과의 `doc_id`가 원본 문서와 1:1로 이어지는지 확인한다. 골든셋 qrels가 이 ID를 쓴다.
