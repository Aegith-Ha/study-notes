# 표와 이미지 처리 (Tables and Images)

표와 이미지 안의 정보(금액, 기한, 기준표, 서식, 도식)를 검색과 생성이 쓸 수 있는 텍스트로 바꾸는 방법을 정리한다.

- 폴더 요약과 기본 선택은 [README](./README.md) 참고
- PDF 레이아웃 문제는 [01-pdf-layout](./01-pdf-layout.md) 참고

## 1. 표가 어려운 이유

```text
원본 표
| 위반 횟수 | 과태료 |
| 1회       | 50만 원 |
| 2회       | 100만 원 |

단순 추출 결과
"위반 횟수 과태료 1회 50만 원 2회 100만 원"
```

- 행과 열의 관계가 사라진다. "2회 위반 시 과태료"를 물으면 검색은 될 수 있어도 LLM이 어느 숫자인지 헷갈린다.
- 표가 쪽을 넘어가면 머리행이 첫 쪽에만 있어 뒤쪽 행의 의미가 사라진다.

## 2. 표를 텍스트로 바꾸는 방법

| 방법 | 결과 예 | 장점 | 단점 |
| --- | --- | --- | --- |
| 마크다운 표 | `\| 2회 \| 100만 원 \|` | 구조 보존, LLM이 잘 읽음 | 큰 표는 길어짐, 임베딩에 불리할 수 있음 |
| 행 단위 문장 | "위반 횟수 2회: 과태료 100만 원" | 행마다 의미가 완결, 검색에 유리 | 행 수만큼 길어짐 |
| 표 요약 | "위반 횟수(1~3회)에 따른 과태료 기준표" | 짧아서 검색 진입점으로 좋음 | 세부 값 손실 |

- 검색용과 생성용을 나누는 조합이 실용적이다. **표 요약 + 행 단위 문장으로 검색하고, 찾으면 원본 마크다운 표를 LLM에 넘긴다.** 부모-자식 청크([02-parent-child-contextual](../04-chunking/02-parent-child-contextual.md))와 같은 구조다.
- 행 단위 문장에는 표 제목과 머리행을 매번 붙인다. 행만 떼어 놓으면 무슨 표인지 모른다.

## 3. 이미지

| 이미지 종류 | 처리 |
| --- | --- |
| 글자가 든 이미지 (스캔 서식) | OCR |
| 도식·흐름도 (절차도) | 멀티모달 LLM으로 단계 설명 텍스트 생성 |
| 사진·장식 | 대부분 무시, 캡션만 보존 |

- 멀티모달 LLM이 만든 설명은 틀릴 수 있다. 생성된 설명은 원본 이미지와 연결해 두고 표본을 확인한다.
- 설명 텍스트를 만들었다면 그 청크에 "이미지 설명"이라는 표시를 남긴다. 답변이 이 청크를 인용하면 원본 확인을 권하는 식으로 쓸 수 있다.

## 4. 평가

| 확인 | 방법 |
| --- | --- |
| 표 질문 검색 | 근거가 표에 있는 질문만 모아 Recall@5 비교 (변환 방식별) |
| 표 질문 정답 | 같은 질문의 Answer Correctness (숫자·기한을 정확히 답했나, 단답형 EM) |
| 변환 정확도 | 표본 표에서 변환 결과의 셀 값이 원본과 같은 비율 |

- 표 질문은 정답이 숫자·기한인 단답형이 많아 EM으로 채점하기 쉽다([01-reference-based](../../03-evals/02-generation-metrics/01-reference-based.md) 3.1).
- 골든셋에 표·이미지 근거 질문이 적으면 이 유형만 모은 평가 질문을 따로 만든다.

## 5. 확인할 점

- 병합 셀, 다단 머리행이 있는 표는 변환이 자주 틀린다. 이런 표는 따로 목록을 만들어 확인한다.
- 표 변환 방식을 바꾸면 청크 수와 질의당 토큰이 크게 달라질 수 있다. 함께 기록한다.
