# 메타데이터 필터 추출 (Metadata Filter)

질문 속 조건("2024년 개정 후", "환불 정책에서", "매뉴얼 기준")을 LLM으로 뽑아 검색 조건으로 거는 방법을 정리한다. 기본 RAG 실패 유형 중 F5(조건 누락으로 구버전·다른 문서를 가져옴)를 고친다.

- 폴더 요약과 기본 선택은 [README](./README.md) 참고
- 벡터 DB의 필터 동작은 [02-vector-db](../../02-retrieval-basics/03-vector-index/02-vector-db.md) 3장 참고

## 1. 구조

```text
질문 ──▶ [LLM: 조건 추출] ──▶ { "doc_title": "환불 정책", "doc_type": null, "effective_after": "2024-01-01" }
                                      │
질문 ──▶ 검색 (조건을 필터로 적용) ◀────┘
```

| 필드 | 예 | 문서 쪽 메타데이터 |
| --- | --- | --- |
| `doc_title` | 환불 정책 | 문서 제목 |
| `doc_type` | 정책 / 지침 / 매뉴얼 | 문서 종류 |
| `effective_after` | 2024-01-01 | 시행일 |
| `section` | 3.2 | 섹션 번호 |

- 질문에 조건이 없으면 모든 필드를 비워 둔다(`null`). **조건이 없는데 만들어 내는 것**이 가장 흔한 실패다.
- 추출 결과는 정해진 형식(JSON)으로 받는다. 형식이 깨지면 필터 없이 검색한다.

## 2. 평가: 정답이 명확한 단계

조건 추출은 정답이 분명해서 judge 없이 채점할 수 있다.

| 지표 | 계산 |
| --- | --- |
| 필드별 정확 일치 (EM) | 필드마다 추출값 = 정답값 비율 |
| 과잉 추출률 | 정답이 `null`인데 값을 만든 비율 |
| 누락률 | 정답에 값이 있는데 `null`로 둔 비율 |
| 질문 단위 완전 일치 | 모든 필드가 맞은 질문 비율 |

- 골든셋에 조건이 들어간 질문이 많지 않으면, 조건 추출 전용 평가 질문(예: 50건)을 따로 만든다.
- 문서 제목은 정식 명칭으로 정규화한 뒤 비교한다(약칭 "환불규정" → "환불 정책").

## 3. 실패 처리

| 상황 | 문제 | 대응 |
| --- | --- | --- |
| 과잉 추출 | 없는 조건으로 정답 문서가 걸러짐 | 확신도가 낮으면 필터 대신 가산점(부스트)으로 |
| 필터 후 결과 0건 | 조건이 너무 좁거나 잘못 뽑힘 | 필터를 풀고 다시 검색 (fallback) |
| 문서 제목 오추출 | 비슷한 다른 문서로 필터 | 문서 제목 사전으로 검증, 사전에 없으면 필터 생략 |

- 필터는 틀리면 정답을 **완전히** 지운다. 그래서 재작성보다 보수적으로 쓴다.

## 4. 검색 지표와 함께 보기

| 비교 | 보는 것 |
| --- | --- |
| 필터 전후 Recall@5 | 최종 효과 |
| 필터 전후 구버전 문서 반환율 | F5가 실제로 줄었나 ([05-regression-ci](../../03-evals/05-regression-ci/01-gate-design.md) L1 규칙 검사) |
| 추출 오류 질의의 Recall@5 | 추출이 틀렸을 때 얼마나 손해인가 |

- Recall이 떨어졌을 때 "검색기 문제인가, 필터를 잘못 뽑았나"를 이 표로 바로 구분한다.

## 5. 정확 조회 라우팅

질문에 문서 번호, 섹션 번호, 제품 코드처럼 **문서를 바로 가리키는 식별자**가 있으면 검색할 필요가 없다. 식별자로 DB를 직접 조회하는 쪽으로 보낸다.

```text
질문 ──▶ [식별자 탐지: 정규식·사전] ──┬─ 있음 ──▶ DB 직접 조회 ──┐
                                      │                          ├─▶ 조회 결과를 맨 앞에, 검색 결과를 뒤에
                                      └──────▶ 일반 검색 ────────┘
                                         (없음이면 일반 검색만)
```

| | 메타데이터 필터 (1~4장) | 정확 조회 라우팅 |
| --- | --- | --- |
| 하는 일 | 검색 범위를 좁힘 | 검색을 건너뛰고 해당 문서를 바로 가져옴 |
| 탐지 방법 | LLM으로 조건 추출 | 정규식, 식별자 사전 (LLM 없이도 가능) |
| 틀렸을 때 | 정답이 걸러짐 | 엉뚱한 문서가 맨 앞에 옴 |

- **조회 결과만 쓰지 않고 일반 검색 결과를 함께 붙인다.** "3.2항 말고 다른 예외도 있나요?"처럼 식별자가 있어도 다른 문서가 필요한 질문이 있다.
- 오탐에 주의한다. "3일 이내"의 "3"을 섹션 번호로 잡으면 엉뚱한 문서가 1위가 된다. 식별자 형식을 좁게 정하고, 조회 결과가 없으면 일반 검색만 쓴다.
- 평가: 식별자 탐지의 정밀도·재현율, 식별자 질문에서의 MRR(기대값 1)을 따로 잰다. 일반 질문에서 오탐으로 Recall이 떨어지지 않았는지도 본다.
- 집계형 질문("2024년에 개정된 정책은 몇 개인가?")은 문서를 찾는 문제가 아니라 DB를 세는 문제다. text-to-SQL 같은 도구 호출로 푼다([05-agents/02-tool-calling-mcp](../../05-agents/02-tool-calling-mcp/README.md)).

## 6. 확인할 점

- 문서 쪽 메타데이터(시행일, 문서 종류)가 정확해야 필터가 의미 있다. 색인할 때 메타데이터 누락 비율을 먼저 확인한다.
- 추출 프롬프트에 오늘 날짜를 넣어야 "최근 개정", "올해" 같은 표현을 날짜로 바꿀 수 있다. 회귀 테스트에서는 날짜를 고정한다.
