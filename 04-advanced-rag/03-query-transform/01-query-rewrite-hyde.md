# 질의 재작성과 HyDE (Query Rewrite, HyDE)

사용자 질문을 그대로 검색하지 않고, LLM으로 검색에 유리한 형태로 바꾼 뒤 검색하는 방법을 정리한다. 기본 RAG 실패 유형 중 F4(모호하거나 짧은 질문)와 F1(표현 불일치) 일부를 고친다.

- 폴더 요약과 메인 결정은 [README](./README.md) 참고
- 질문에서 검색 조건을 뽑는 방법은 [02-metadata-filter](./02-metadata-filter.md) 참고

## 1. 방법

| 방법 | 하는 일 | 예 (원래 질문: "집주인이 보증금을 안 줘요") |
| --- | --- | --- |
| 재작성 (rewrite) | 일상어를 문서의 용어로 바꿔 하나의 검색어로 | "임대차 종료 후 임대인의 보증금 반환 의무" |
| 다중 질의 (multi-query) | 여러 표현으로 바꿔 각각 검색 후 합침 | "보증금 반환 청구", "임차권등기명령", "임대차 종료 시 보증금" |
| HyDE | 그럴듯한 **답변 문서**를 먼저 쓰게 하고 그 글로 검색 | "임대차가 종료된 경우 임대인은 보증금을 반환하여야 하며 …" (가상의 조문 문체 글) |
| 분해 (decomposition) | 여러 조건이 섞인 질문을 하위 질문으로 쪼개 각각 검색 | "보증금 반환 요건" + "반환 지연 시 구제 절차" |

- 다중 질의와 분해의 결과는 [하이브리드의 합치기 방법](../01-hybrid-search/01-fusion-methods.md)(RRF)으로 합친다.

## 2. HyDE가 동작하는 이유

```text
질문 (짧은 일상어)  ↔  조문 (긴 법률 문체)        : 표현이 멀다
가상 답변 (조문 문체) ↔  조문 (긴 법률 문체)        : 표현이 가깝다
```

- 질문과 문서의 **문체 차이**를 LLM이 메워 준다. 주로 dense 검색에서 효과가 있다.
- 가상 답변의 **내용이 틀려도** 검색에는 도움이 될 수 있다. 문체와 용어가 비슷하면 가까운 조문을 찾는다. 다만 가상 답변은 검색에만 쓰고 사용자에게 보여 주지 않는다.

## 3. 위험

| 위험 | 예 | 대응 |
| --- | --- | --- |
| 의도 이탈 (drift) | "전세 사기 신고"를 "전세 계약 해지 절차"로 바꿈 | 원래 질문 검색 결과와 함께 합침 (원래 질문을 버리지 않음) |
| 없는 용어 생성 | 존재하지 않는 법령명·조문 번호를 넣음 | BM25에는 재작성 결과를 넣지 않거나, 법령명 사전으로 검증 |
| 정보 손실 | 질문의 조건("2024년 이후")을 빠뜨림 | 조건은 메타데이터 필터로 따로 뽑음 |
| 지연·비용 | 검색 전에 LLM 호출 1회 추가 | 짧은 출력, 작은 모델, 캐시 |

- 가장 안전한 기본값은 **원래 질문 + 변환 질의를 각각 검색해서 RRF로 합치는 것**이다. 변환이 틀려도 원래 질문의 결과가 남는다.

## 4. 평가

| 확인 | 방법 |
| --- | --- |
| 최종 효과 | 변환 전후 Recall@5, MRR (검색 지표) |
| 질의별 변화 | 변환으로 실패 → 성공, 성공 → 실패가 된 질의 |
| 변환 품질 | 의도 이탈 비율: 변환 질의를 표본으로 사람 또는 judge가 확인 |
| 나눠 보기 | `user` 말투에서 효과가 크고 `expert`에서는 작거나 손해일 수 있음 |
| 비용 | 질의당 추가 LLM 호출, p95 지연 |

- 변환 LLM은 중간 단계라 생성 지표가 아니라 **검색 지표**로 평가한다([03-evals README](../../03-evals/README.md) 시스템 유형별 지표).

## 5. 확인할 점

- 변환 프롬프트와 모델 버전을 기록한다. 변환 결과가 바뀌면 검색 결과도 바뀐다.
- 같은 질문의 변환 결과를 캐시해 두면 회귀 테스트가 결정적이 된다.
