# 실패 복구 설계 (Failure Recovery)

에이전트 실행 중 생기는 실패(도구 오류, 빈 결과, 틀린 결과, 반복, 시간 초과)를 나누고, 유형별 복구 방법과 복구 능력을 평가하는 방법을 정리한다.

- 폴더 요약과 메인 결정은 [README](./README.md) 참고
- 루프 구조는 [01-loop-design](./01-loop-design.md) 참고

## 1. 실패 유형과 복구

| 유형 | 예 | 일시적인가 | 복구 방법 |
| --- | --- | --- | --- |
| 일시적 도구 오류 | 시간 초과, 연결 끊김, 호출 한도 | 예 | 간격을 늘려 재시도 (최대 N회) |
| 잘못된 인자 | 스키마 위반, 없는 문서 제목 | 아니오 | 오류 메시지를 LLM에 주고 인자 수정 후 재호출 |
| 빈 결과 | 검색 결과 0건 | 아니오 | 검색어 바꾸기, 필터 풀기, 다른 도구 |
| 틀린 결과 | 검증 단계에서 완료 기준 불충족 | 아니오 | 재계획 |
| 반복 | 같은 호출·같은 실패가 계속 | 아니오 | 중단 후 부분 결과 반환 |
| 권한 거부 | 사용자 권한 밖 데이터 | 아니오 | 재시도하지 않음. 사용자에게 알림 |
| 예산 초과 | 토큰·단계 상한 도달 | 아니오 | 중단 후 부분 결과 반환 |

- **일시적 오류만 재시도한다.** 인자 오류나 권한 거부를 같은 인자로 재시도하면 같은 실패만 반복한다.
- 재시도해도 안전하려면 읽기 도구는 같은 호출에 같은 결과를 내야 하고, 쓰기 도구는 중복 실행돼도 결과가 한 번과 같아야 한다(중복 실행 방지 키 등).

## 2. 끝내는 방식

| 상황 | 응답 |
| --- | --- |
| 전부 성공 | 결과 + 근거 |
| 일부 성공 | 성공한 부분 + 실패한 단계와 이유 ("규정 B 조회 실패로 대조하지 못함") |
| 전부 실패 | 실패 이유와 사용자가 할 수 있는 다음 행동 |
| 사람 확인 필요 | 확인 요청과 근거 |

- 실패를 숨기고 그럴듯한 답을 만드는 것이 가장 나쁜 결과다. 부분 결과임을 분명히 밝힌다.

## 3. 복구 능력 평가: 실패 주입

실제 실패는 드물어서 평가 세트에서 잘 나오지 않는다. 일부러 실패를 넣어 복구를 시험한다.

| 주입 방법 | 예 |
| --- | --- |
| 도구 오류 | 도구 호출의 20%에 시간 초과 반환 |
| 빈 결과 | 특정 검색어에 0건 반환 |
| 잘못된 결과 | 다른 섹션 내용을 반환 |
| 느린 응답 | 응답 지연 추가 |

### 손계산 예시

작업 50건, 도구 호출의 일부에 시간 초과를 주입

```text
주입 없음:  성공 45 / 50 = 0.90
주입 후 실패를 한 번 이상 만난 작업: 20건, 만나지 않은 작업: 30건 (이 중 27건 성공)

복구 없음:  실패를 만난 20건 모두 실패 → 성공 27 / 50 = 0.54
복구 있음:  실패를 만난 20건 중 15건 복구 후 성공 → 성공 (27 + 15) / 50 = 0.84
복구 성공률 = 15 / 20 = 0.75
```

읽는 법
- 복구 없이는 실패 주입만으로 성공률이 0.90 → 0.54로 떨어진다. 복구가 0.84까지 되돌렸다.
- 복구하지 못한 5건을 열어 보고 유형(재시도 대상이 아닌데 재시도, 부분 결과를 숨김 등)을 기록한다.
- 복구 있음의 비용(추가 호출 수, 지연)도 함께 기록한다.

## 4. 확인할 점

- 실패 주입은 테스트 환경에서만 한다. 쓰기 도구는 실제 데이터에 닿지 않게 가짜 도구로 바꿔 시험한다.
- 실패 주입 결과도 회귀 테스트에 넣을 수 있다. 복구 성공률이 떨어지는 변경을 막는다([05-regression-ci](../../03-evals/05-regression-ci/README.md)).
