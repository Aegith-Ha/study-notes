# 에이전트형 검색 (Agentic Retrieval)

검색을 한 번 하고 끝내는 기본 RAG와 달리, LLM이 검색할지, 무엇으로 검색할지, 더 검색할지를 스스로 정하는 구조를 정리한다.

- 폴더 요약, 메인 결정, 결과는 [README](./README.md) 참고
- 이 구조를 평가하는 방법은 [02-trajectory-evaluation](./02-trajectory-evaluation.md) 참고

## 1. 기본 RAG와의 차이

```text
기본 RAG:     질문 ──▶ 검색 1회 ──▶ 생성

Agentic RAG:  질문 ──▶ [LLM 판단] ──┬─▶ 검색 불필요 ──▶ 바로 답변
                          ▲         └─▶ 검색어 작성 ──▶ 검색 ──▶ 결과 확인
                          │                                      │
                          └──────── 부족하면 다시 ◀────────────────┘
                                    충분하면 ──▶ 생성
```

| 결정 | 기본 RAG | Agentic RAG |
| --- | --- | --- |
| 검색 여부 | 항상 검색 | LLM이 판단 (인사, 일반 질문은 생략) |
| 검색어 | 질문 그대로 | LLM이 작성, 단계마다 바꿈 |
| 검색 횟수 | 1회 | 여러 번 (상한 있음) |
| 멈추는 시점 | 고정 | 근거가 충분하다고 판단할 때 |

## 2. 패턴

| 패턴 | 동작 | 맞는 질문 |
| --- | --- | --- |
| 라우터 | 검색할지, 어느 색인(법령 / 해석례 / FAQ)을 쓸지만 정함 | 질문 종류가 뚜렷이 나뉠 때 |
| 반복 검색 | 결과를 보고 부족하면 검색어를 바꿔 다시 검색 | 첫 검색이 빗나가기 쉬운 질문 |
| 분해 후 검색 | 질문을 하위 질문으로 나누고 각각 검색 | 다중 근거 질문 ("요건은? 위반하면?") |
| 교정형 (corrective) | 검색 결과의 충분성을 판정해 부족하면 재검색, 그래도 없으면 거절 | 답 없음 질문이 섞인 경우 |

- 교정형의 "충분성 판정"은 [Context Sufficiency](../../03-evals/01-retrieval-metrics/02-reference-free.md)와 같은 판정이다. 평가용 judge 기준을 그대로 에이전트의 판단 기준으로 쓸 수 있다.
- 분해 후 검색은 [질의 변환의 분해](../../04-advanced-rag/03-query-transform/01-query-rewrite-hyde.md)를 LLM이 동적으로 하는 것이다.

## 3. 기본 RAG로 충분한 경우

- 대부분의 질문이 조문 하나로 답해진다면 에이전트 구조는 비용과 지연만 늘린다.
- [실패 유형](../../02-retrieval-basics/04-naive-rag/02-failure-modes.md) 분포에서 다중 근거(F6 일부), 모호한 질문(F4)이 많을 때 효과가 크다.
- 먼저 [04-advanced-rag](../../04-advanced-rag/README.md)의 고정 파이프라인을 최대한 개선한 뒤, 남은 실패에 에이전트 구조를 적용한다.

## 4. 자주 생기는 문제

| 문제 | 예 | 대응 |
| --- | --- | --- |
| 과잉 검색 | 이미 근거가 있는데 계속 검색 | 최대 검색 횟수, 충분성 판정 |
| 검색 생략 오류 | 검색해야 할 법령 질문을 사전 지식으로 답함 | 법령 질문은 검색 필수 규칙 |
| 같은 검색 반복 | 비슷한 검색어로 같은 결과를 반복 | 이전 검색어 목록을 보여 주고 중복 금지 |
| 검색어 이탈 | 단계가 지날수록 원래 질문에서 멀어짐 | 매 단계 원래 질문을 다시 제시 |
| 무한 반복 | 멈추는 조건을 만족하지 못함 | 최대 단계, 예산 상한 |

## 5. 확인할 점

- 에이전트의 각 단계(판단, 검색어, 검색 결과)를 모두 기록한다. 기록이 없으면 왜 틀렸는지 알 수 없다.
- 같은 질문에 실행할 때마다 경로가 달라질 수 있다. temperature 0, 모델 버전 고정, 최대 단계 고정으로 변동을 줄인다.
