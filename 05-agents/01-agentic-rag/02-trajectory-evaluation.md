# 에이전트 경로 평가 (Trajectory Evaluation)

에이전트는 최종 답변만이 아니라 **어떤 경로로 답에 도달했는지**도 평가해야 한다. 최종 결과를 기존 지표로 재는 방법과, 경로를 재는 과정 지표를 정리한다.

- 폴더 요약과 기본 선택은 [README](./README.md) 참고
- 에이전트 구조는 [01-agentic-retrieval](./01-agentic-retrieval.md) 참고

## 1. 무엇을 재나

| 대상 | 지표 | 출처 |
| --- | --- | --- |
| 최종 답변 | Answer Correctness, Faithfulness, 거절 정확도 | [02-generation-metrics](../../03-evals/02-generation-metrics/README.md) |
| 모은 근거 | 모든 단계 검색 결과의 합집합으로 Recall | [01-retrieval-metrics](../../03-evals/01-retrieval-metrics/README.md) |
| 경로 (과정) | 검색 횟수, 중복 검색률, 검색 판단 정확도, 최대 단계 도달률 | 이 노트 |
| 비용 | 질의당 LLM 호출 수, 토큰, 지연 | [05-regression-ci](../../03-evals/05-regression-ci/01-gate-design.md) 6장 |

- 에이전트의 "검색 결과"는 한 번의 top-5가 아니다. 단계마다 가져온 문서를 합친 것이 LLM이 본 근거다.
- 다만 합집합이 클수록 Recall은 쉽게 오른다. 그래서 **합집합 크기(본 문서 수)**를 함께 기록한다.

## 2. 과정 지표

| 지표 | 계산 | 좋은 방향 |
| --- | --- | --- |
| 평균 검색 횟수 | 질의당 검색 호출 수 | 정확도가 같다면 적을수록 |
| 중복 검색률 | 새 문서를 하나도 가져오지 못한 검색 / 전체 검색 | 낮을수록 |
| 검색 판단 정확도 | 검색 여부 판단이 맞은 비율 (검색이 필요한 질문인지 골든셋에 표시) | 높을수록 |
| 최대 단계 도달률 | 상한에 걸려 강제로 멈춘 질의 비율 | 낮을수록 (높으면 멈추는 조건 문제) |
| 첫 검색 Recall vs 최종 Recall | 첫 단계 결과와 합집합의 Recall 차이 | 차이가 반복 검색의 효과 |

## 3. 손계산 예시

다중 근거 질문 Q, 정답 문서 2개 (d2, d7)

```text
단계 1  검색어 q1 → top-5: d2, d4, d9, d1, d5        새 문서 5개, 정답 d2
단계 2  검색어 q2 → top-5: d7, d2, d8, d3, d6        새 문서 4개 (d2 중복), 정답 d7
단계 3  검색어 q3 → top-5: d2, d4, d9, d1, d5        새 문서 0개 (단계 1과 같음)
단계 4  충분하다고 판단 → 답변 생성
```

| 지표 | 계산 | 값 |
| --- | --- | --- |
| 검색 횟수 | 3 | 3 |
| 중복 검색률 | 새 문서 0개인 검색 1 / 3 | 0.33 |
| 첫 검색 Recall | d2 / {d2, d7} | 0.5 |
| 최종 Recall (합집합) | {d2, d7} / {d2, d7} | 1.0 |
| 본 문서 수 | 5 + 4 + 0 | 9 |

읽는 법
- 반복 검색이 Recall을 0.5 → 1.0으로 올렸다. 다중 근거 질문에서 에이전트 구조의 효과다.
- 단계 3은 낭비다. 단계 1과 같은 검색을 다시 했다. 이전 검색어를 보여 주는 규칙으로 줄일 수 있다.
- 본 문서가 9개라 기본 RAG(5개)보다 컨텍스트가 크다. Faithfulness와 토큰 비용을 함께 본다.

## 4. 기본 RAG와 비교하는 법

| 비교 | 보는 것 |
| --- | --- |
| 전체 평균 | Answer Correctness, 질의당 비용·지연 |
| 답변 유형별 | 다중 근거 질문에서 이득, 단답 질문에서 손해(불필요한 비용)가 없는지 |
| 질의별 변화 | 기본 RAG에서 맞고 에이전트에서 틀린 질의 → 경로를 열어 원인 확인 |

- 에이전트는 평균보다 **질문 유형별**로 봐야 한다. 이득이 특정 유형에 몰려 있으면, 그 유형만 에이전트로 보내는 라우팅이 비용 면에서 낫다.

## 5. 확인할 점

- 경로가 실행마다 달라질 수 있어, 같은 질문을 여러 번 돌려 정답률이 흔들리는 폭을 잰다. 회귀 테스트의 δ는 이 폭보다 크게 잡는다.
- 경로 기록(trace)은 운영에서도 그대로 쓴다. 요청 단위 트레이싱은 [06-llmops/01-tracing](../../06-llmops/01-tracing/README.md)에서 다룬다.
